# DeepWiki Q&A with Code Context for Repository: zeroclaw-labs/zeroclaw
## Q1
zeroclaw onboardをターミナルではなくプログラムから完了させる方法を探しています。設定情報をファイルで一気に与えることで設定を完了させたり、全てプログラムからコマンドを実行していくことで設定を完了させたりしたいのです。また、設定変更も全てプログラムから行えなければなりません。以下のようなヘルプを見て方法を探していますが、何か良い方法はありますか？

```
Usage: zeroclaw onboard [OPTIONS]

Options:
      --config-dir <CONFIG_DIR>
      --force                    Overwrite existing config without confirmation
      --reinit                   Reinitialize from scratch (backup and reset all configuration)
      --channels-only            Reconfigure channels only (fast repair flow)
      --api-key <API_KEY>        API key for provider configuration
      --provider <PROVIDER>      Provider name (used in quick mode, default: openrouter)
      --model <MODEL>            Model ID override (used in quick mode)
      --memory <MEMORY>          Memory backend (sqlite, lucid, markdown, none) - used in quick mode, default: sqlite
      --quick                    Skip interactive prompts and use quick setup with defaults
      --tui                      Use the ratatui-based TUI onboarding wizard
  -h, --help                     Print help
```
### Answer
## プログラムからの zeroclaw onboard 完了方法

zeroclaw onboard をプログラムから完了させるには、以下の方法があります。

### 1. クイックセットアップモードの使用

`--quick` フラグと必要なオプションを組み合わせることで、非対話的に設定を完了できます zeroclaw:196-202 ：

```bash
zeroclaw onboard --quick --api-key "sk-..." --provider openrouter --model "anthropic/claude-sonnet-4" --memory sqlite
```

### 2. プロバイダーフラグによる自動クイックセットアップ

`--quick` フラグがなくても、プロバイダー関連のフラグが指定されている場合は自動的にクイックセットアップが実行されます zeroclaw:965-977 ：

```bash
zeroclaw onboard --api-key "sk-..." --provider openrouter
```

### 3. 設定ファイルの直接作成

プログラムで直接 `config.toml` を作成することも可能です。`install.sh` ではこの方法が使用されています zeroclaw:653-666 ：

```toml
# ~/.zeroclaw/config.toml
default_provider = "openrouter"
workspace_dir = "/path/to/workspace"
api_key = "sk-..."
default_model = "anthropic/claude-sonnet-4"
```

### 4. 環境変数を使用した設定

環境変数を使用して設定を渡すこともできます zeroclaw:934-936 ：

```bash
ZEROCLAW_API_KEY="sk-..." ZEROCLAW_PROVIDER="openrouter" zeroclaw onboard --quick
```

### 5. 設定変更のプログラムからの実行

既存の設定を変更するには `--force` フラグを使用します zeroclaw:170-172 ：

```bash
zeroclaw onboard --force --api-key "new-key" --provider anthropic
```

### 実装例

`run_quick_setup` 関数はプログラムからの設定呼び出しを処理します zeroclaw:453-473 。この関数は：
- APIキー、プロバイダー、モデル、メモリバックエンドを受け取る
- 設定ディレクトリとワークスペースを作成する
- デフォルト値を適用する
- `config.toml` を生成する

## Notes

- `--channels-only` オプションはチャネル設定のみを再構成する場合に使用します zeroclaw:178-180 
- `--reinit` オプションは設定を完全にリセットする場合に使用します zeroclaw:174-176

## Q2
~/.zeroclawというのがzeroclawのホームディレクトリに固定されているのですか？zeroclawのホームディレクトリを任意のパスのディレクトリに変更できませんか？
### Answer
## zeroclawのホームディレクトリについて

いいえ、`~/.zeroclaw` は固定されていません。任意のパスに変更できます。

### 変更方法

#### 1. `--config-dir` オプションを使用
CLIコマンドで直接指定： zeroclaw:159-160 

```bash
zeroclaw --config-dir /path/to/custom/dir agent
```

#### 2. 環境変数 `ZEROCLAW_CONFIG_DIR` を設定
プログラム内で設定： zeroclaw:840-846 

```bash
export ZEROCLAW_CONFIG_DIR=/path/to/custom/dir
zeroclaw agent
```

#### 3. 環境変数 `ZEROCLAW_WORKSPACE` を設定
ワークスペースディレクトリを指定： zeroclaw:484-492 

```bash
export ZEROCLAW_WORKSPACE=/path/to/workspace
```

### ディレクトリ解決の優先順位

`resolve_quick_setup_dirs_with_home` 関数による解決順序： zeroclaw:475-506 

1. `ZEROCLAW_CONFIG_DIR` 環境変数
2. `ZEROCLAW_WORKSPACE` 環境変数
3. Homebrewインストール時の var ディレクトリ
4. デフォルト: `~/.zeroclaw`

### 設定ファイルの解決順序

設定の読み込み順序： zeroclaw:63-67 

1. `ZEROCLAW_WORKSPACE` 環境変数
2. `~/.zeroclaw/active_workspace.toml` マーカーファイル
3. デフォルト: `~/.zeroclaw/config.toml`

## Q3
では、config dirを ~/.mycute/zeroclaw にした上で、~/.mycute/zeroclaw/config.toml を作成すれば、onboardを完了させることができますか？
### Answer
## はい、その方法で onboard を完了させることができます

`~/.mycute/zeroclaw` を設定ディレクトリとして指定し、そこに `config.toml` を作成することで onboard プロセスを完了させることが可能です zeroclaw:475-506 。

### 実装方法

#### 1. 設定ディレクトリを指定して onboard を実行

```bash
# --config-dir を使用
zeroclaw onboard --config-dir ~/.mycute/zeroclaw --quick --api-key "sk-..." --provider openrouter

# または環境変数を使用
ZEROCLAW_CONFIG_DIR=~/.mycute/zeroclaw zeroclaw onboard --quick --api-key "sk-..." --provider openrouter
```

#### 2. 手動で config.toml を作成

プログラムで直接設定ファイルを作成する場合 zeroclaw:653-666 ：

```bash
# ディレクトリを作成
mkdir -p ~/.mycute/zeroclaw/workspace

# config.toml を作成
cat > ~/.mycute/zeroclaw/config.toml <<TOML
default_provider = "openrouter"
workspace_dir = "$HOME/.mycute/zeroclaw/workspace"
api_key = "sk-..."
default_model = "anthropic/claude-sonnet-4"
TOML

# 権限を設定
chmod 600 ~/.mycute/zeroclaw/config.toml
```

### 注意点

1. **ワークスペースの作成**: `config.toml` だけでなく、ワークスペースディレクトリも作成する必要があります zeroclaw:475-506 

2. **追加のスキャフォールディング**: onboard プロセスは通常、ワークスペースに初期ファイル（IDENTITY.md、USER.md、MEMORY.md など）も作成します zeroclaw:672-719 

3. **設定の検証**: 作成後、`zeroclaw status` や `zeroclaw doctor` で設定が正しく読み込まれることを確認してください

### 完全な自動化例

```bash
#!/bin/bash
CONFIG_DIR="$HOME/.mycute/zeroclaw"
WORKSPACE_DIR="$CONFIG_DIR/workspace"

# ディレクトリ構造を作成
mkdir -p "$WORKSPACE_DIR"/{sessions,memory,state,cron,skills}

# 基本的な config.toml を作成
cat > "$CONFIG_DIR/config.toml" <<TOML
default_provider = "openrouter"
workspace_dir = "$WORKSPACE_DIR"
api_key = "$ZEROCLAW_API_KEY"
default_model = "anthropic/claude-sonnet-4"
TOML

chmod 600 "$CONFIG_DIR/config.toml"

# 動作確認
ZEROCLAW_CONFIG_DIR="$CONFIG_DIR" zeroclaw status
```

## Environment Provider Overrides

Provider selection can also be controlled by environment variables. Precedence is:

1. `ZEROCLAW_PROVIDER` (explicit override, always wins when non-empty)
2. `PROVIDER` (legacy fallback, only applied when config provider is unset or still `openrouter`)
3. `default_provider` in `config.toml`

Operational note for container users:

- If your `config.toml` sets an explicit custom provider like `custom:https://.../v1`, a default `PROVIDER=openrouter` from Docker/container env will no longer replace it.
- Use `ZEROCLAW_PROVIDER` when you intentionally want runtime env to override a non-default configured provider.

## Q5
以下の質問に答えてください。 1. config.tomlを書き換えた後は再起動しなければ設定反映しませんか？再起動を要する場合、再起動を要しない別の設定方法もあれば教えてください。 2. model_providersの各種設定と、api_key, default_provider という独立した設定はどのように区別して取り扱えば良いのですか？
### Answer
## 設定反映とプロバイダ設定について

### 1. config.tomlの変更反映について

**一部の設定は再起動不要です**。チャネル実行中、以下の設定はホットリロードされます zeroclaw:948-1024 ：

- `default_provider`
- `default_model` 
- `default_temperature`
- `api_key` / `api_url`（デフォルトプロバイダ用）
- `reliability.*` プロバイダ再試行設定

**再起動が必要な設定**：
- ゲートウェイ設定（`[gateway]`）
- チャネル設定（`[channels_config]`）
- セキュリティ設定（`[security]`、`[autonomy]`）

**再起動不要な設定方法**：
1. **環境変数使用**：`ZEROCLAW_PROVIDER`、`ZEROCLAW_API_KEY`などは即時反映されます zeroclaw:62-74 
2. **Gateway API経由**：`PUT /api/config` で設定を更新可能 zeroclaw:167-213 
3. **チャネルコマンド**：Telegram/Discordで `/models`、`/model` コマンド使用 zeroclaw:40-56 

### 2. model_providersとapi_key/default_providerの区別

**api_key / default_provider**：
- グローバルなデフォルト設定 zeroclaw:74-87 
- 環境変数で上書き可能
- シンプルな単一プロバイダ構成向け

**model_providers**：
- 名前付きプロバイダプロファイルのHashMap zeroclaw:88-90 
- 複数プロバイダの詳細設定を格納
- カスタムエンドポイントや特殊な認証に使用

**使い分け**：
```toml
# シンプルな場合（推奨）
api_key = "sk-..."
default_provider = "openrouter"

# 複雑な場合
[model_providers.custom-openai]
api_key = "sk-..."
base_url = "https://api.example.com/v1"
```

**解決順序**：
1. 明示的なconfig/CLIの認証情報
2. プロバイダ固有の環境変数
3. ジェネリック fallback: `ZEROCLAW_API_KEY` → `API_KEY` zeroclaw:13-23 

## Notes

- ホットリロードはチャネルメッセージの次のリクエストで反映されます

    /// Create a new router with a default provider and optional routes.
    ///
    /// `providers` is a list of (name, provider) pairs. The first one is the default.
    /// `routes` maps hint names to Route structs containing provider_name and model.
    pub fn new(
        providers: Vec<(String, Box<dyn Provider>)>,
        routes: Vec<(String, Route)>,
        default_model: String,
    ) -> Self {
        // Build provider name → index lookup
        let name_to_index: HashMap<&str, usize> = providers
            .iter()
            .enumerate()
            .map(|(i, (name, _))| (name.as_str(), i))
            .collect();

        // Resolve routes to provider indices
        let resolved_routes: HashMap<String, (usize, String)> = routes
            .into_iter()
            .filter_map(|(hint, route)| {
                let index = name_to_index.get(route.provider_name.as_str()).copied();
                match index {
                    Some(i) => Some((hint, (i, route.model))),
                    None => {
                        tracing::warn!(
                            hint = hint,
                            provider = route.provider_name,
                            "Route references unknown provider, skipping"
                        );
                        None
                    }
                }
            })
            .collect();

        Self {
            routes: resolved_routes,
            providers,
            default_index: 0,
            default_model,
        }
    }

    /// Resolve a model parameter to the cheapest qualifying route based on pricing.
    ///
    /// If the model starts with `"hint:cost-optimized"` or `"hint:cheapest"`, this
    /// method scores each route by `input_price + output_price` (a simple proxy for
    /// total cost), optionally filtering by capability requirements, and returns the
    /// cheapest qualifying route.
    ///
    /// Falls back to the default route when no pricing data matches.
    pub fn resolve_cost_optimized(
        &self,
        model: &str,
        prices: &HashMap<String, ModelPricing>,
        required_vision: bool,
        required_tools: bool,
    ) -> (usize, String) {
        let hint = model.strip_prefix("hint:");
        let is_cost_hint = matches!(hint, Some("cost-optimized" | "cheapest"));

        if !is_cost_hint {
            return self.resolve(model);
        }

        let mut candidates: Vec<(usize, String, f64)> = Vec::new();

        for (idx, route_model) in self.routes.values() {
            // Capability filtering
            if let Some((_, provider)) = self.providers.get(*idx) {
                if required_vision && !provider.supports_vision() {
                    continue;
                }
                if required_tools && !provider.supports_native_tools() {
                    continue;
                }
            }

            if let Some(pricing) = prices.get(route_model) {
                let total_cost = pricing.input + pricing.output;
                candidates.push((*idx, route_model.clone(), total_cost));
            }
        }

        // Sort by total cost (ascending) and pick the cheapest
        candidates.sort_by(|a, b| a.2.partial_cmp(&b.2).unwrap_or(std::cmp::Ordering::Equal));

        if let Some((idx, route_model, _)) = candidates.into_iter().next() {
            return (idx, route_model);
        }

        // Fallback to default
        tracing::warn!(
            "No cost-optimized route found with matching pricing data, \
             falling back to default"
        );
        (self.default_index, self.default_model.clone())
    }

    /// Resolve a model parameter to a (provider, actual_model) pair.
    ///
    /// If the model starts with "hint:", look up the hint in the route table.
    /// Otherwise, use the default provider with the given model name.
    /// Resolve a model parameter to a (provider_index, actual_model) pair.
    fn resolve(&self, model: &str) -> (usize, String) {
        if let Some(hint) = model.strip_prefix("hint:") {
            if let Some((idx, resolved_model)) = self.routes.get(hint) {
                return (*idx, resolved_model.clone());
            }
            tracing::warn!(
                hint = hint,
                "Unknown route hint, falling back to default provider"
            );
        }

        // Not a hint or hint not found — use default provider with the model as-is
        (self.default_index, model.to_string())
    }
}

        if !needed.iter().any(|n| n == &route.provider) {
            needed.push(route.provider.clone());
        }
    }

    // Create each provider (with its own resilience wrapper)
    let mut providers: Vec<(String, Box<dyn Provider>)> = Vec::new();
    for name in &needed {
        let routed_credential = model_routes
            .iter()
            .find(|r| &r.provider == name)
            .and_then(|r| {
                r.api_key.as_ref().and_then(|raw_key| {
                    let trimmed_key = raw_key.trim();
                    (!trimmed_key.is_empty()).then_some(trimmed_key)
                })
            });
        let key = routed_credential.or(api_key);
        // Only use api_url for the primary provider
        let url = if name == primary_name { api_url } else { None };
        match create_resilient_provider_with_options(name, key, url, reliability, options) {
            Ok(provider) => providers.push((name.clone(), provider)),
            Err(e) => {
                if name == primary_name {
                    return Err(e);
                }
                tracing::warn!(
                    provider = name.as_str(),
                    "Ignoring routed provider that failed to initialize"
                );
            }
        }
    }

    // Build route table
    let routes: Vec<(String, router::Route)> = model_routes
        .iter()
        .map(|r| {
            (
                r.hint.clone(),
                router::Route {
                    provider_name: r.provider.clone(),
                    model: r.model.clone(),
                },
            )
        })
        .collect();

    Ok(Box::new(router::RouterProvider::new(
        providers,
        routes,
        default_model.to_string(),
    )))
}

### 実装上の考慮事項

1. **HashMapキーとして使用**: hintはHashMapのキーとして使われるため、一意性が必要です zeroclaw:138-145

### 推奨される使い方

### 文章を使用する場合の注意点

- 長い文章はヒューマンエラーの原因になる可能性があります
- 分類ルールでのマッチングが困難になります
- 他の開発者が理解しにくくなる可能性があります

## Notes

- 実運用では短く分かりやすい識別子の使用が推奨されます
- 特別な意味を持つhint（cost-optimizedなど）を除き、自由に命名可能です
