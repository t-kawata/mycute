## 直面している問題
Windows 環境で `make build` を実行すると、以下のリンクエラーが発生します。

```text
error: could not find native static library `bootstrapperdll`, perhaps an -L flag is missing?
```

### 原因の推測
- `build.rs` で指定している `bootstrapperdll` というスタティックライブラリ名が、実際のファイル名（例: `bootstrapper.lib`）と異なっている。
- もしくは、`SpeechHelper.csproj` のビルド成果物が正しく `native/` フォルダに配置されていない、あるいは探索パスが通っていない。

## 引き継ぎ後の作業依頼（Windows エージェントへ）

    - Windows 環境のターミナルで、実際にビルドされた `.lib` ファイル群を確認してください。

2.  **`build.rs` の修正**:
    - 確認した実際のファイル名に合わせて、`build.rs` の `println!("cargo:rustc-link-lib=static=...");` を修正してください。
    - 他に未解決の外部シンボルが出る場合は、必要なシステムライブラリ（`user32`, `gdi32` 等）を追加してください。
3.  **ビルドと動作確認**:

 ## 技術的な補足とヒント (Windows エージェントへ)

作業効率化のため、以下の情報を頭に入れておくとスムーズです。

### 1. 探索すべきディレクトリのパス
C# の成果物（`.lib`）は、ビルド時のターゲットフレームワーク（TFM）によって非常に深い階層に生成されます。まずここを確認してください：
- `native/cs/SpeechHelper/bin/Release/net10.0-windows10.0.26100.0/win-x64/native/`
- もし `net10.0` の部分が環境によって異なる場合は、`native/cs/SpeechHelper/bin/Release/` 以下を `dir /s` して `.lib` を探してください。

### 2. `CopyNativeAotLibs` ターゲットについて
`SpeechHelper.csproj` の末尾には、`.NET SDK` の内部フォルダ（`IlcSdkPath`）から `bootstrapper.lib` などのランタイムライブラリを、上記の `native/` フォルダへ自動コピーするカスタムターゲットを記述してあります。
もし `native/` フォルダに必要な `.lib` が足りない場合は、このターゲットの挙動（パスが正しいか等）を疑ってください。

### 3. 静的リンクのエラー対応
現在出ている `bootstrapperdll` が見つからないというエラーが解決した後、今度は「未解決の外部シンボル（unresolved external symbol）」が大量に出る可能性があります。その場合は、以下を試してください：
- `build.rs` のシステムライブラリ（`advapi32`, `bcrypt` 等）のリンク順序を変えてみる。
- Windows SDK に含まれる標準ライブラリ（`msvcrt.lib` 等）のリンクが必要か検討する。

### 4. ログ出力のスタイル
本プロジェクトでは、ログの接頭辞に `<Win>` や `[Win]` を付加する慣習があります。修正後の `log::info!` 等でもこのスタイルを継承してください。
