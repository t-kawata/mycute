## 4. 現象の解釈（日本語）

EventProjection フレームワークは完全に決定論的であり、確率的要素を含まない。
ProjectionEventFilter による種別フィルタリングは 100% の精度を示し、
クロスプロジェクション汚染はゼロである。これは各 projection が独立した
内部状態 (Vec<DarviumEvent>) を持ち、FakeProjectionCatalog の project_all()
が個別に project() を呼び出す設計による。

1000 ランダムイベント中、search_filter に合致したのは 83 件、
training_filter に合致したのは 27 件、system_filter に合致したのは 84 件。
残りはフィルタ未定義の event_kind（WorkflowExecution, Knowledge, Conversational,
Lifecycle, Gc, Repair, Reciprocity, Fusion, Hitl, Extension）であり、
どの projection にも配送されなかった — これが期待される動作である。

## 5. 目的関数 J(θ) の評価

- 収束速度: 該当なし（確率的要素なし）
- 定常誤差: 該当なし
- オーバーシュート: 該当なし
- 総合評価: 全 8 テスト PASS、フィルタリング精度 100%、クロスプロジェクション汚染ゼロ

## 6. 次チケットへの示唆

本チケットで実装した EventProjection トレイトは M1.5-R10 でのドメイン統合
（SearchTrace・TrainingRunLog・ReciprocityEvent の EventProjection 化）の基盤となる。
特に ProjectionEventFilter により、各ドメイン投影は自身の関心種別のみを
受け取ることが保証される。現状の interested_kinds() は filter の kind_filter を
そのまま返す実装であるため、R10 で本格的な projection を実装する際には
interested_kinds() をオーバーライドする設計が推奨される。
