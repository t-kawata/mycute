## 3. 較正ループ

本チケットでは較正を行わない。全テスト PASS をもって完了とする。

## 4. 現象の解釈（日本語）

シミュレーションでは初期 50 ワークフローで開始し、tick 3 以降で非慈悲的ワークフローの生存率が 0 になった。これは GC hazard が慈悲スコアの低い個人を早期に排除したため。慈悲的ワークフローも tick 9 以降で急速に減少し、tick 12 で全滅した。デフォルトの ReciprocityLifecyclePolicy では生存維持が困難であることが示唆される。

観測テストの LifecycleScore 計算では、freshness/usage を経験値の単純正規化で代用している。P6 以降で LifecycleScore の全 5 成分を適切に供給できるようになれば、より精緻な GC 制御が可能になる。

## 5. 目的関数 J(θ) の評価

本チケットでは J(θ) 評価を行わない (P6 スコープ)。

## 6. 次チケットへの示唆

- P6 で LifecycleScore の各成分 (特に freshness と usage) を適切に供給する機構が必要
- P4 (6 フェーズループ) 実装時は transition_gc_state の hazard 閾値を P6 の較正結果に基づいて調整
- 信頼継承と評判継承の減衰係数 TRUST_INHERIT_DECAY=0.70 は KW4 で sweep 対象
