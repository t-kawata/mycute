## 3. 較正ループ

### 反復 1
- 仮説: シミュレーションの初期パラメータは、7つの MagnificentSevenParams のデフォルト値で OFAT sweep を実行したとき、lambda_gc_base が最も感度の高いパラメータである
- 変更定数: なし（初回実行のため constants.rs 未変更）
- 観測結果: lambda_gc_base=0.1 で J(θ)=0.152755 が最良。残りのパラメータは J(θ)=0（閾値未達）
- 解釈: 初期パラメータ近傍では lambda_gc_base のみが有意な目的関数値を生成する。他のパラメータは sweep 範囲内で J(θ) が 0 に張り付いており、感度が低いか、相互作用が単一パラメータ変更では検出できない。

## 4. 現象の解釈（日本語）

Phase 0 の純粋関数検証は全て PASS した。benevolence_score は [0, 1] の出力値域を守り、単調性も満たしている。indirect_reciprocity の出力範囲は [0.5, 0.993] であり、これは設計仕様と一致する。

Phase 1 の決定論的リプレイは全てのシードで Fail となった。これは run_replay_scenario が内部で時刻情報等の非決定論的要素を使用しているためである。bit-level の完全一致を要求する現在の検証方法は、シミュレーションのリプレイ保証が不十分であることを示している。これは既知の制限であり、将来のチケットで対応が必要。

Phase 2 の摂動テストは 2 種のシードで PASS した。自己比較（baseline と同一 seed の再実行）では churn_delta=0, jsd_delta=0 となり、摂動がない場合のメトリクス一致性が確認できた。

Phase 3 の OFAT sweep では、lambda_gc_base=0.1 が best J(θ)=0.152755 を達成した。その内訳は AUC 成分が支配的（0.2878）であり、churn 成分は負の寄与（−0.1350）を示した。help_success_rate は全区間で 0 であり、シミュレーション構成が短 tick 数（10 ticks）のため支援行動が発生していない可能性がある。

Phase 4 では上位 5 候補が選択され、human_review_ticket が生成された。canary/production の環境分離も正常に機能している。

## 5. 目的関数 J(θ) の評価

- 収束速度: N/A（単一 sweep のため較正収束の評価は未実施）
- 定常誤差: 最良 J=0.152755 だが、help_success 成分が常に 0 であるため、目的関数が真の生態系性能を反映しているとは言い切れない
- オーバーシュート: 該当せず
- 総合評価: パイプラインは正常に動作するが、シミュレーションの tick 数や初期状態のチューニングが必要。λ重みの設計も再検討の余地がある。

## 6. 次チケットへの示唆

1. **Phase 1 の非決定論問題**: run_replay_scenario の完全再現性を確保するため、シミュレーション内部の時刻依存処理を排除するチケットが必要。
2. **シミュレーション tick 数の増加**: 現在 10 ticks では支援行動（help offer/acceptance）が発生しない可能性が高い。Phase 3 の sweep 前に tick 数を増やすべき。
3. **default_replay_scenario の改善**: 現在の 6 workflow 構成では生態系の多様性が不十分。より多様な初期ワークフロー構成の導入を検討。
4. **目的関数 λ 重みの実データ較正**: 現在の λ 重みは仮の値 — 実運用データに基づく重み較正が別チケットで必要。
