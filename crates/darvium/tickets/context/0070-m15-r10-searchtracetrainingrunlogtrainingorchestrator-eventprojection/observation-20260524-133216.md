## 3. 較正ループ

本チケットに較正すべき定数は存在しない。純粋な型定義とトレイト実装。

## 4. 現象の解釈（日本語）

DomainProjection フレームワークは完全に決定論的であり、確率的要素を含まない。ProjectionEventFilter による種別フィルタリングは 100% の精度を示し、クロスプロジェクション汚染はゼロである。これは各 DomainProjection が独立した内部状態 (Vec<DarviumEvent>) を持ち、ProjectionCatalog の project_all() が個別に project() を呼び出す設計による。

SearchRunLogProjection の subset フィルタ（SearchEvent の StepCompleted/Completed/Failed/Aborted のみ）も正確に機能し、Started が除外されていることを確認した。

1000 ランダムイベント中、search_filter に合致したのは 84 件、training_filter に合致したのは 68 件、reciprocity_filter に合致したのは 65 件。SearchRunLog は Search の subset として 71 件（Search 全 84 件中、Started 13 件が除外されたため 71 件）を受信した。残りのイベントは WorkflowExecution, Knowledge, Conversational, Lifecycle, Gc, Repair, Fusion, Hitl, System, Extension であり、これらの kind に対応する projection が存在しないため配送されなかった — これが期待される動作である。

## 6. 次チケットへの示唆

本チケットで実装した DomainProjection + initialize_domain_projections() は M1.76-21 の外部イベント購読基盤（EventSubscriber + WebSocketEventChannel）におけるドメイン別イベント再配送の基盤となる。特に initialize_domain_projections() により、アプリケーション起動時に全 Projection を一括登録できる設計となっている。

Dual-path（DualStoreCoordinator からの EventBus publish）は SearchEvent::Started のみを publish する。他の SearchEvent variant（StepCompleted, Completed, Failed, Aborted）の publish は SearchWorkflow の該当箇所で個別に実装する必要がある。

RFC §12E との差分：RFC 定義の 4 標準 Projection（SearchTrace, ReciprocityProjection, FusionTrace, LifecycleLog）に対し、本チケットでは TrainingRunLog と SearchRunLog を代わりに実装した。FusionTrace と LifecycleLog は今後のチケットで追加可能。
