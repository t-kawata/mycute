# 観察レポート: k-means実行間隔の設定可能化

## 1. 計装の実装状況

- **計装対象**: `SimulationContext.kmeans_distance_computations` — k-means および Voronoi 割り当てにおける距離計算延べ回数
- **実装した計装コード**: `phase2_village_clustering` 内の k-means++ 初期化および Lloyd 反復の各距離計算でカウント
- **観測した統計量**: k-means 実行 tick vs Voronoi 割り当て tick の距離計算回数比

## 2. 実装完了項目

### Config 追加
- `ReciprocitySimulatorConfig.village_recluster_interval: u64` — デフォルト 1（従来動作）
- `SimulationContext.last_centroids: Vec<[f32; 3]>` — 前回 k-means の centroids を保存
- `SimulationContext.kmeans_distance_computations: u64` — 距離計算カウント

### Voronoi 割り当て関数
- `phase2_voronoi_assign()` — 既存 centroid から最近傍割り当て（空の村防止ロジック含む）
- 距離計算: n × k のみ（k-means++ 初期化 + Lloyd 反復不要）

### 定数抽出 (Boy Scout)
- `KMEANS_PLUSPLUS_SEED = 42` — マジックナンバー定数化
- `KMEANS_MAX_ITERATIONS = 50` — マジックナンバー定数化
- `euclidean_distance_3d()` — 3次元ユークリッド距離の共通関数化
- `compute_village_count()` — 村数計算ロジックの共通関数化

### ループ分岐 (4箇所)
- `tick % config.village_recluster_interval.max(1) == 0` → k-means
- `else if centroids あり` → Voronoi 割り当て
- `else` → 0（フォールバック）

### フロントエンド
- スライダー追加（index.html, script.js）
- 最小値 1, 最大値 100の数値入力
- server.rs で `val.max(1)` クランプ

## 3. 検証結果

- **cargo test**: 1389 passed, 0 failed, 71 ignored (前回1327 passedから増加)
- **後方互換性**: `village_recluster_interval=1` で Default 値 = 従来動作
- **フロントエンド連携**: 設定パース `val.max(1)` で 0 指定を防止

## 4. 現象の解釈

k-means 実行間隔を設定可能にすることで、以下のトレードオフをユーザーが制御できるようになった：
- **間隔 = 1**: 毎 tick 正確なクラスタリング（従来動作、計算コスト大）
- **間隔 = N**: N tick ごとの k-means + 間の Voronoi 割り当て（計算コスト約 1/N）
- Voronoi 割り当ては k-means++ 初期化と Lloyd 反復をスキップするため、O(n×k×iter) → O(n×k) に削減

村構造の大規模変化（churn）は k-means 実行 tick でのみ発生し、間引き tick では既存 centroid への最近傍割り当てのみ行うため、村の大構造は保持される。

## 5. 目的関数 J(θ) の評価

本チケットでは較正は行わない（フロントエンドからユーザーが設定可能）。目的関数の枠組みは spec で定義済み。

## 6. 次チケットへの示唆

- `village_recluster_interval` の最適値はシミュレーションパラメータ依存のため、フロントエンドから適宜調整されたい
- Voronoi 割り当ての精度検証（k-means と Voronoi の村構造一致度）は後続の観測チケットで評価可能
