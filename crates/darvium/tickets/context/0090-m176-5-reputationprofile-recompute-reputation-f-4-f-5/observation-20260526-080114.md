## 3. 較正ループ

本チケットは M0.x (pure function validation) フェーズのため、較正ループは実施しない。

### 反復 1（初期値検証）
- 仮説: spec 定義の初期定数 (θ_dir=0.35, θ_ind=0.35, θ_exp=0.20, θ_inh=0.10, κ_E=0.01) で全不変条件が成立する
- 変更定数: なし（初期値そのまま）
- 観測結果: 全 TC-1〜TC-7 通過。値域 [0,1] 拘束確認 (n=10,000)。全単調性確認 (dir/ind/inh sweep)。E_norm 漸近確認 (count=1000 → 0.999955)。
- 解釈: 初期値は健全。係数和 1.0 により spec 推奨に合致。

## 4. 現象の解釈（日本語）

**経験値飽和曲線**: κ_E=0.01 の場合、count=100 で E_norm≈0.632、count=200 で ≈0.865、count=500 で ≈0.993 と急速に飽和する。κ_E=0.05 以上では count=100 で既に 0.993 に達し、経験値の差別化がほとんど効かなくなる。これは古参固定化防止の設計意図（経験値の上限を設けて新規参入者の追従を妨げない）と合致する。

**係数感度**: 確率単体サンプリングにおいて、θ_dir と θ_ind が大きいほど最終スコアが高くなる傾向が確認された。θ_exp=0.20 の初期値では経験値の寄与は限定的であり、主に直接・間接互恵性のバランスで最終スコアが決まる。

**値域 [0,1] 拘束**: 10,000 件のランダムサンプルで全 final_score が [0, 1] に収まり、NaN/Inf は一件も発生しなかった。これは clamp 操作の健全性を確認する。

## 5. 目的関数 J(θ) の評価

本チケットは較正対象外（M0.x 純粋関数検証フェーズ）。後続チケット (M1.76-6〜M1.76-9) で GC hazard や child protection と結合した際の J(θ) 評価が有効となる。

## 6. 次チケットへの示唆

1. κ_E の初期値 0.01 は経験値の差別化に十分な分解能を持つ（count=0〜500 で有意な差）。後続チケットで最終スコア全体の分散を確認し、必要に応じて調整可能。
2. ReciprocityLifecyclePolicy のデフォルト値修正（theta_dir の誤参照を修正）により、spec 推奨の係数和 = 1 が達成された。後続チケットではこの修正を前提として実装可能。
3. ReputationInputs 構造体を導入したことで、recompute_reputation は ReputationProfile の全16フィールドに依存せず、テスト容易性が向上した。
