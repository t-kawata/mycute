# 観察レポート: M-0.5-1 メモリ内デュアルストア候補抽出及び統合・重複排除器（Stage 2c）の検証

## 1. 計装の実装状況

- 計装対象: `merge_and_deduplicate_candidates` 関数の重複排除ロジック（最大値保存則、provenance連結、順序維持）
- 実装したテストコード: `src/store/mod.rs`（`#[cfg(test)] mod tests` 内の T1〜T9 + OTS-1 + OTS-2）
- 観測した統計量:
  - OTS-1: カイ二乗統計量 χ² = 69.96（64バケット、自由度63、209,649候補集約）
  - OTS-2: 最大値保存率 100%（10,000組）

## 3. 較正ループ

該当なし（本チケットは純粋関数のロジック検証であり、較正対象の定数は存在しない）

## 4. 現象の解釈（日本語）

**OTS-1（カイ二乗検定）**: 全10,000イテレーションで生成された209,649件のマージ後候補の workflow_id を64バケットのハッシュ値に割り当て、カイ二乗検定を実施した。χ² = 69.96 は自由度63のカイ二乗分布における95%臨界値（≈82.5）を下回っており、帰無仮説「バケット割り当ては一様分布に従う」を棄却できない。すなわち、マージ関数による重複排除処理が特定の workflow_id を偏って選択するようなバイアスは確認されなかった。

**OTS-2（最大値保存則）**: 10,000組の重複候補ペア（ランダムスコア）に対して最大値保存が100%成立した。同一 workflow_id を持つ候補の blended_score がマージ後も最大値で維持されることを確認。
