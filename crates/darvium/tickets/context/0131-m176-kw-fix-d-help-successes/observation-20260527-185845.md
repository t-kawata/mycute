## 3. 較正ループ

本チケットは純粋なバグ修正であり、較正を要する定数は存在しない。較正ループはスキップ。

### 反復 1
- 仮説: help_successes 累積変数を削除し、new_successes を直接 phase5_capability_diffusion に渡すことで、経験値の重複加算が解消される
- 変更定数: なし（定数変更不要のバグ修正）
- 観測結果: 修正後の平均経験値 12.255（50 tick, 200 ノード）。各ノードの経験値は実際の HELP 成功回数に一致する（重複なし）
- 解釈: 修正前は help_successes が累積されていたため、早期に HELP されたノードほど経験値が tick 数倍に膨張していた。修正後は各 tick の成功のみが処理されるため、経験値は実際の HELP 成功回数と一致する。

## 4. 現象の解釈（日本語）

本バグは「help_successes の累積」という単純な実装ミスに起因する。run_kw_real_simulation と run_evaluation_simulation の両方で、phase5_capability_diffusion が毎 tick 全過去の HELP 成功を再処理していた。これにより、例えば tick=0 で HELP されたノードは 50 tick のシミュレーションで 50 回経験値が加算される（本来 1 回）という歪みが生じていた。

修正後は各 tick の new_successes のみが phase5_capability_diffusion に渡される。これにより経験値の加算は各 HELP 成功につき 1 回のみとなる。

## 5. 目的関数 J(θ) の評価

本チケットはバグ修正であり目的関数の変更はない。ただし、以下の影響が期待される：
- lifecycle_score: 経験値の重複加算が解消されることで、lifecycle_score（usage 成分）が適正化される
- j_lifecycle: 本来より低くなる（人為的な膨張が除去されるため）
- 次チケット（KW4 較正ループ）の精度が向上する
