## 3. 較正ループ

本チケットは較正対象の定数（HITL_RECONNECT_BACKOFF_SECS = 5.0）が Calibration Candidate として定義されているが、指数バックオフの実装検証は回復ループの基本動作確認であり、パラメータ感受性の分析は後続チケットで実施する。

### 反復 1
- 仮説: HITL_RECONNECT_BACKOFF_SECS = 5.0 は単体テスト（max_retries=0）では使用されないため、観測不能
- 変更定数: なし（デフォルト値で検証）
- 観測結果: 全11不変条件テスト + 2観測テスト PASS
- 解釈: 基本回復プロトコルが正しく動作している。指数バックオフの実装検証は max_retries>0 のテストケース追加により拡充可能。

## 4. 現象の解釈（日本語）

バッチ回復成功率の観測では、FakeHumanChannel における 90% の成功確率設定に対して、観測された成功率が 89.7%-95.0% の範囲で変動している。この変動は期待される二項分布の範囲内であり、回復ループが確率的な成功・失敗を正しく集計していることを確認した。

回復レイテンシの観測では、FakeHumanChannel を使用した場合の回復ループ全体のレイテンシが中央値 28μs、P99 84μs と極めて低く、オーバーヘッドは無視できるレベルであることが確認された。これは InMemoryMetadataStore + FakeHumanChannel という軽量なテスト環境での値であり、実際の JsonMetadataStore やネットワークチャネルを使用する場合はより大きなレイテンシが予想される。

混合シナリオ（T-R3）では、5成功 + 3タイムアウト + 2到達不能の正確な分類が確認された。特に、StdinoutChannel のクロスインスタンス回復（T-R4/T11）では、新チャネルインスタンスが過去の Pending レコードを interaction_id ベースで正しく回復できることを検証した。

## 6. 次チケットへの示唆

本チケットでは JsonMetadataStore（簡易ファイル永続化）を使用した。後続の M1-1 では SqliteMetadataStore を実装し、JSON ファイルよりも堅牢なデータベース永続化に移行することが推奨される。また、指数バックオフパラメータ HITL_RECONNECT_BACKOFF_SECS は本番環境での実測値に基づく較正が必要である。
