## 3. 較正ループ

### 反復 1
- 仮説: `EVENTBUS_REPLAY_BATCH_SIZE` は RFC §12C 既定値 100 が正しく、チケット spec の 256 は誤りであった。RFC を正本として 100 を採用する。
- 変更定数: EVENTBUS_REPLAY_BATCH_SIZE: 指定なし → 100 (RFC 値)
- 観測結果: C-5 テストで 100 を確認。既存テストに影響なし。
- 解釈: チケット spec と RFC の定数定義に乖離があったが、RFC 優先ルールにより RFC 値を採用した。6件の定数名も RFC の EVENTBUS_ プレフィックスに統一。

### 反復 2（proptest 戦略の調整）
- 仮説: proptest はデフォルト cases=256 で全不変条件を検証可能。P-8（quarantine）のみ 128 ケースを指定。
- 変更定数: 特になし。proptest 設定のみ調整。
- 観測結果: P-4〜P-9 の全不変条件が n=256 cases で PASS。
- 解釈: 全不変条件 violation 率 0%。shrinking も正しく機能し、P-8 の偽陽性（event_id 重複による誤削除）は proptest が最小事例に縮約したことで迅速に特定・修正できた。

## 4. 現象の解釈（日本語）

FakeEventBus の全6不変条件（publish→replay 完全性、TwoWay 状態遷移有限性、clock 単調増加性、replay 不変性、quarantine 除外性、projection 独立性）に対して proptest ベースのファジングを実施した結果、全 256 cases × 複数イベントで violation 0 を確認した。これは既存の FakeEventBus 実装が RFC §12C の全不変条件を満たしていることを統計的に裏付ける。

P-8（quarantine 除外性）の実装において、proptest の shrinking 機能が有用であることが確認できた。初期実装では event_id の重複により quarantine が正常イベントも削除する偽陽性が発生したが、proptest が自動的に最小事例（event_id 衝突）を特定したため、デバッグが迅速に行えた。

また、RFC §12C の定数定義とチケット spec の間に乖離があったが（EVENTBUS_REPLAY_BATCH_SIZE の値等）、RFC 優先ルールにより統一的に解決した。結果として constants.rs には RFC §12C 由来の6定数 + チケット spec 由来の5定数の計11定数が適切に分類されて定義された。

## 6. 次チケットへの示唆

1. proptest 戦略群（event_kind_strategy, darvium_event_strategy, interaction_mode_strategy）は他のモジュールのプロパティベーステストでも再利用可能。特に event_kind_strategy は全ての Event Architecture テストで共通基盤として使用できる。
2. FakeEventBus の quarantine 実装（events.retain による event_id 一致除去）は interaction_id と event_id が同一であることを前提としており、この依存関係が変更された場合にテストが偽陽性となる可能性がある。
3. RFC との定数乖離は常に RFC 優先で解決すること。今回のケースではチケット spec に「EVENT_REPLAY_BATCH_SIZE = 256」とあったが RFC では「EVENTBUS_REPLAY_BATCH_SIZE = 100」であり、RFC 値を採用した。
