## 3. 較正ループ

### 反復 1
- 仮説: 成熟度閾値は RFC §41B.3 推奨デフォルト値で初期設定。後続チケット M1.75-11 の多目的最適化で調整されるため、本チケットでは初期値のまま較正不要。
- 変更定数: MIN_SURVIVAL_EXPERIENCE=5, E_ADULT_THRESHOLD=20, T_ADULT_THRESHOLD=0.70, R_ADULT_THRESHOLD=0.70（全4定数新規追加）
- 観測結果: 21テスト全PASS。境界値±1での判定切り替わり確認。MIN_SURVIVAL_EXPERIENCE=5 のとき experience_count=4 で Child、experience_count=5 で Child（MIN_SURVIVAL_EXPERIENCE は Child 条件のみに関与）。E_ADULT_THRESHOLD=20 で Adult 判定閾値として正しく機能。
- 解釈: 初回実装のため較正ループは実質的に1回。定数は後続チケット M1.75-11 の多目的最適化で較正される。

## 4. 現象の解釈（日本語）

classify_maturity の判定ロジックが RFC §41B.3 の式 41B-3・41B-4 に従って正しく実装された。経験値不足（< MIN_SURVIVAL_EXPERIENCE）が最も優先され、信頼・レピュテーションが閾値を超えていても Child と判定される。Adult 判定には経験値・信頼・レピュテーションの全3軸が閾値以上であることが要求され、1軸でも不足すれば Child となる。

filter_adult_candidates では、ConsistencyStateTag::Committed かつ is_adult_maturity=true の adult 候補のみが保持される。Pending/NeedsRepair/Quarantined の候補はすべて除外される。これにより、整合性が保証され成熟した workflow のみが Local Village の構成要素となる。

build_local_village_topk は Child 位置からの距離昇順で最大 k 件の Adult を選抜し、距離昇順の adult_ids を返す。同距離の場合は任意の順序で最大 k 件が選抜される。build_local_village_radius は d_max 以内の全 Adult を選抜する。centroid は選抜 Adult 位置の算術平均として計算される。空村の centroid は SpacePositionEmbedding::unknown() となる。

## 5. 目的関数 J(θ) の評価

本チケットでは単独の目的関数を定義しない（M1.75-11 の J_village(θ) の構成要素となる）。

## 6. 次チケットへの示唆

- 本チケットの classify_maturity / build_local_village / filter_adult_candidates は M1.75-3（HELP プロトコル）の Adult 選抜と Child 判定の組み合わせに直接利用される
- AdultCandidate の is_adult_maturity フラグは LifecycleState 未実装の代替である。M1.76 系列で LifecycleState が実装されたら、フィルタ条件を拡張すること
- WorkflowGraphId は String 型（types.rs:19）である。LocalVillage の adult_ids は String の Vec として保持される
