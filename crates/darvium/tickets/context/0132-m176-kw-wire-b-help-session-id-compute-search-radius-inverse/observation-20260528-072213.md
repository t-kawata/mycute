## 4. 現象の解釈（日本語）

`compute_search_radius_inverse()` は従来 `strip_prefix('n')` のみでパースしていたため、production 環境の HelpSession に含まれる WorkflowGraphId（"adult-1", "child-1" 形式）に全くマッチせず、常に 0.5 を返す永久スタブであった。またシミュレーション環境の ID（"wf-child-3", "session-42" 等）にも対応していなかった。

修正により `parse_workflow_id()` 関数を抽出し、以下の 6 形式を順次試行するようにした：
1. `"n<数字>"` — レガシー形式
2. `"wf-child-<数字>"` — シミュレーション子ワークフロー
3. `"wf-adult-<数字>"` — シミュレーション大人ワークフロー
4. `"session-<数字>"` — シミュレーション HELP セッション
5. `"adult-<数字>"` — 本番環境 WorkflowGraphId
6. `"child-<数字>"` — 本番環境 WorkflowGraphId

これにより j_search_radius_inv（s_search の 25%）が実測 L2 距離ベースで計算されるようになった。

ただし、現在のシミュレーション環境では HELP セッション自体が発生しないため、compute_search_radius_inverse は sessions.is_empty() で早期 return し 0.5 のままである。この問題は WIRE-C（シミュレーション内 HELP フロー実装）で解決される。
