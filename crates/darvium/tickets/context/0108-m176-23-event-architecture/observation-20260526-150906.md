## 3. 較正ループ

本チケットは一貫性検証が主目的であり、較正対象の定数はない。ただし、以下の実装上の問題を修正した：

### 反復 1
- 仮説: generate_random_event_kind() は13ドメインのランダムイベントを生成するため、ドメイン別バケットに格納しても kind 一致が保証されない
- 変更: TC-3 と TC-7 のイベント生成を generate_random_event_kind から明示的なドメイン特化 variant の循環生成に変更
- 観測結果: kind_filter_accuracy が 0.088→1.0 に改善
- 解釈: テスト設計時の暗黙の前提（「ランダムイベントが均等に分布する」）が誤りであった。ランダム生成ではドメイン別期待件数が保証されないため、明示的な kind 指定が必要

### 反復 2
- 仮説: シャッフル後の publish 順と replay 順が一致する
- 変更: kind_filter_accuracy 計算で replayed[idx] を replayed[*pos] に修正（pos は publish 順の位置）
- 観測結果: kind_filter_accuracy が 0.067→1.0 に改善（反復1の kind 修正後の残差を解消）
- 解釈: shuffled_indices の各要素は all_events の元のインデックスであり、replay 配列のインデックスと一致しない。replay は publish 順（= shuffled_indices 順）なので、位置ベースの比較が必要

## 4. 現象の解釈

全13ドメインの DarviumEvent が EventBus（FakeEventBus）経由で一貫した canonical envelope により publish/replay/subscribe/projection されることが検証された。

特に重要な観測結果：
- ドメイン横断一貫性スコア = 1.0 達成。全5指標（replay完全取得率、kindフィルタ精度、クロック単調増加性、projection配送完全性、JSONラウンドトリップ成功率）が全て 1.0
- 14個の DomainProjection（既存5 + 新規9）が相互汚染ゼロで動作。各 projection は自身の interested_kinds に該当するイベントのみを受信
- 既存テスト test_r10_initialize_domain_projections が 5→14 projection への変更で期待値不一致を起こしたため修正。これにより initialize_domain_projections() の一括登録動作も検証された
- 1300イベントの JSON ラウンドトリップ完全性確認（100%）。全13ドメインの serde 派生が正しく動作
