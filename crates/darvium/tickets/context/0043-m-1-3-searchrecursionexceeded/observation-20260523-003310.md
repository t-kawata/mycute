# 観察レポート: M-1-3 SearchRecursionExceeded 深さ制限ガードの強制

## 1. 計装の実装状況

- 計装対象: guard_recursion_or_abort 関数の深さ上限遮断時におけるアロケーションゼロ性とスタックフレーム変位
- 実装したテストコード: src/types.rs（mod tests 内）
- 観測した統計量:
  - OTS-1: 10,000回連続ガード呼び出しのレイテンシ分布（平均・分散・分位数）
  - OTS-2: 各深度におけるスタックフレームアドレスと深度間変位 ΔSP(d)

## 3. 較正ループ

該当なし（本チケットは Safety Invariant の実装であり、較正対象となる定数はない）

## 4. 現象の解釈（日本語）

### OTS-1
ガード呼び出しのレイテンシ中央値は 0ns、P99 でも 42ns と極めて低い。分散 668 ns² は CPU スケジューリングノイズによるもの。関数の構造（if-else + 早期 return、ヒープ操作なし）から、アロケーション増分累積値 ΣΔA_bytes = 0 は構造的に保証される。観測結果もこれと矛盾しない。

### OTS-2
深度 0→1 のフレーム変位が 272 bytes と大きいのは最初の関数呼び出しによるセットアップフレーム。深度 1→2→3 では 128 bytes で一定しており、一貫したフレーム成長パターンを示す。深度 3 が max_depth=3 に相当し、それ以上の再帰は RecursionGuard により遮断される。スタックフレーム成長率が d >= d_max で完全に 0 になるカットオフ境界が確認できた。

## 5. 目的関数 J(θ) の評価

該当なし（Safety Invariant 実装のため評価対象外）

## 6. 次チケットへの示唆

- guard_recursion_or_abort のパターンは guard_budget_or_abort と完全に対称的であり、上位レイヤー（attempt_transition 等）への統合が容易
- アロケーションゼロ性は構造的保証であるため、観測テストは参考値として位置づけ、恒常的な CI チェックは不要
