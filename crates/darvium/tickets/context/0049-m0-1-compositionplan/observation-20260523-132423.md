- 観測した統計量: 捕捉率、avg_steps vs n の線形スケーリング、最大計算ステップ数

## 4. 現象の解釈（日本語）

**OTS-1（捕捉率）**: 10,000 回のランダムグラフアンサンブルに対し、3,264,531 件の注入違反が全て捕捉された。捕捉率 1.0000 は V-03/V-04 バリデータが未解決変数を決して見逃さないことを統計的に確認した。

**OTS-2（線形スケーリング）**: ノード数 n に対する平均検証ステップ数は n≈50 まで完全に線形 (avg_steps ≈ 1.96n)。これはバリデータが各エッジを 1 回ずつ走査するだけで動作しており、非線形な計算爆発が発生しないことを示す。

**OTS-3（有界性）**: 最大ノード数 512、1,000 アンサンブルにおいて最悪計算ステップ数は 2,048（< 10,000）。各エッジ走査の O(E) 性が保証され、グラフサイズの上限に対しても現実的な計算資源内で完了する。

## 6. 次チケットへの示唆

- M0-2（GenerateNew 安全ガード）は本バリデータと同様の静的検証パターンで実装可能。
- 本チケットで拡張した EdgeMeta / WorkflowNode enum は後続の M0 シリーズでも使用されるため、設計の一貫性を保つこと。
- Frontier leakage 検出は現状、同一変数名を異なる source node が出力する単純な重複チェックにとどまる。真の DAG 依存関係分析が必要な場合は M2.75-3（frontier-based parallel execution）で拡充する。
