## 3. 較正ループ

本チケットは定数化（パラメーター経路の確立）が目的であり、較正は後続の WIRE 全チケット完了後に行う。本チケット単独では較正しない。

### 反復 1
- 仮説: 3ハードコード値を constants.rs 定数 + AllParams G4 グループとしてパラメーター化
- 変更定数: SIMULATION_CHILD_TRUST_MAX=0.3, SIMULATION_ADULT_TRUST_MIN=0.3, SIMULATION_BENEVOLENT_THRESHOLD=0.5
- 観測結果: 既存テスト全1306件PASS。C1-C5新規テストPASS
- 解釈: パラメーター経路が確立された。デフォルト値は既存のハードコード値と同一のため挙動変化なし

## 4. 現象の解釈（日本語）

WIRE-C は3つのハードコード値（子供trust上限0.3、成人trust下限0.3、benevolent分類閾値0.5）を constants.rs 定数に抽出した。デフォルト値は既存のハードコード値と同一であるため、シミュレーション結果に一切の変化は生じない。変更の価値は将来の較正可能性にある。

注目すべき設計判断として、observe_tick の benevolent_threshold は関数パラメーター化された。これにより AllParams G4 経路と定数経路の2つの制御点を持つことになるが、現状では config.benevolent_threshold → observe_tick のパラメーター経路が有効であり、constants の値は Default impl の初期値としてのみ機能する。AllParams G4 値は to_sim_config_g1g2g4() を経由して config に書き込まれる。
