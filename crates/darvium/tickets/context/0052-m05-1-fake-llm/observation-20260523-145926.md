## 3. 較正ループ

本チケットはテスト基盤の整備が主目的であり、較正ループは適用しない（spec の「較正計画」に基づく）。

### 反復 0（新規定数追加）
- 仮説: デフォルト p_m = 0.0 で常に正常応答し、既存コードに影響を与えない
- 変更定数: constants.rs に SCRIPTED_FAKE_LLM_DEFAULT_MALFORMED_PROB = 0.0 を追加
- 観測結果: p_m = 0.0 で観測出現率 0.0000（期待値 ± 許容範囲に収束）
- 解釈: デフォルト状態で既存コードへの影響はゼロ。Fake-First 原則に従い、基盤整備として適切

## 4. 現象の解釈（日本語）

### OTS-S1: p_m スイープ
p_m と観測出現率の関係はほぼ線形であり、PRNG 駆動の確率的制御が正しく機能していることを確認した。各ポイントで観測値は期待値 p_m ± 約 0.02 の範囲に収まり、n=1,000 のサンプルサイズで十分な精度が得られている。高 p_m 領域（0.9 以上）では若干の正のバイアス（0.909, 1.000）が見られるが、これは乱数サンプリングの自然な分散範囲内である。

### OTS-S2: エントロピー一致性
p_m=0.3 における 3 カテゴリ（正常/不正文字列/エラー）の分布エントロピーは観測値 1.136 bits に対し期待値 1.157 bits、比率 0.9825 であり、10% 閾値内に十分収まっている。特に RawError モードがエラーカテゴリとして正しく分離され、エントロピー計算に寄与している点が重要である（943/10000 = 約 9.4% のエラー率）。

### OTS-S3: デシリアライズ相転移
p_m の増加に伴い、serde_json デシリアライズ成功率が単調減少することが確認された。しかし、p_m=1.0 でも成功率が 0.504 と約 50% 残ることが観測された。これは一部の MalformationType（WrongKeyName, ExtraField, TypeMismatch）が JSON 構文的には正常な文字列を生成するためである。これらのタイプは RFC §14.2 が想定する「意味的に不正だが構文的に正しい」入力をシミュレートしており、設計意図通りの挙動である。構文的な不正のみを注入したい場合は、これら 3 タイプを除外して使用する必要がある。

## 6. 次チケットへの示唆

- M0.5-2（確率的パッチ操作インジェクション）では、ScriptedFakeLlmClient を直接利用することで、パッチ生成における LLM 不正出力の影響テストが可能

- serde_json デシリアライズ相転移の観測結果は、LLM 出力の品質閾値設計（M2 以降）のベースラインとして使用可能
