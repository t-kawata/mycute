## 4. 現象の解釈（日本語）

- 全 6 テストが PASS し、決定論的リプレイの MUST 条件が確認された。
- 同一イベント列・同一ポリシー・同一 VirtualClock のもとで ReputationProfile と GC hazard の再計算結果が完全一致することを、n=100 の独立実行で立証。
- policy version の変更は snapshots.policy_version フィールドにのみ現れ、数値パラメータが同一なら profiles/hazards に影響しないことを確認。
- clock_schedule の変更はスナップショット数に影響するが、最終 clock の profiles/hazards は一致。
- golden_trace_hash は実行間で完全一致（798ebb35b3a1afe7）。
- trace_hash 計算では HashMap の iteration 順序非依存性を排除するため、全マップをキーソート後に決定論的多項式ハッシュを使用。DefaultHasher（実行ごとに異なる内部キー）は不使用。
- 現行パラメータでは全 MUST 条件が成立。
