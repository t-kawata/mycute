## 4. 現象の解釈（日本語）

ReputationProfile の永続化経路は GraphStore トレイトの2メソッド（store_reputation / load_reputation）として追加され、DualStoreCoordinator の store_memoized_graph / load_memoized_graph から呼び出される。以下の設計判断を行った：

1. **非 fatal エラーハンドリング**: store_reputation の失敗は store_memoized_graph の成功/失敗に影響しない。load_reputation の失敗（NotFound または I/O エラー）は cold_start() にフォールバックする。これにより、レピュテーションストアに障害が発生してもワークフローグラフ自体の操作は継続できる。

2. **NotFound と I/O エラーの区別**: NotFound（単に未保存）の場合は無音で cold_start にフォールバックし、I/O エラー（ストア障害）の場合は eprintln! で警告を出力する。これにより、デバッグ時のノイズを減らしつつ、実際の障害は可視化される。

3. **FailingGraphStore の制約**: 現状の FailingGraphStore は全操作に一律のエラー確率を適用するため、特定操作のみのエラー注入ができない。T3 の非 fatal テストは InMemoryGraphStore（常に成功）で行い、コード構造による検証に留めた。
