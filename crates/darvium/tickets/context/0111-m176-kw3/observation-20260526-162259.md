## 4. 現象の解釈（日本語）

シミュレーションデータによる 20 tick の観測テストでは、以下の現象が確認された：

1. **村数安定性**: 全 20 tick を通じて村数は 3 で一定であった。12 ワークフローの位置が変化しないため、assign_village_ids は毎回同一の 3 クラスタ（各 4 ワークフロー）を出力している。村サイズ分散も一貫して 0.0 であり、均等な村割り当てが継続している。

2. **村形成強度**: 0.994〜0.996 の極めて高い値を維持した。これは各村内のワークフローが重心に密接している（4 ワークフローが狭い範囲に集中）ことを示す。最大距離 √2 で正規化した silhouette 類似スコアが妥当に機能している。

3. **村間相互作用率**: 0.4〜1.0 の範囲で変動した。これはランダムな session 割り当て（12 ワークフロー間でのランダムな helper/requester 選択）により、村間セッションと村内セッションが確率的に出現するため。平均約 0.72 であり、3 村構成でのランダム相互作用としては妥当な範囲。

4. **知識拡散速度**: 全 tick を通じて 0.0 であった。これは村割り当てが毎 tick 同一（位置不変）であるため、前回割り当てと今回割り当てで村構成に変化がなく、各村の平均 experience の標準偏差が変化しないため。実際のシミュレーションではワークフロー位置が変化するため、正の値が観測されると予想される。

5. **フローバランス**: 全 tick を通じて 0.0（変化なし）。同上の理由により、村 ID の割り当てが毎 tick 同一のため churn が発生していない。実際のシミュレーションでは位置変化により churn が発生する。

## 5. 目的関数 J(θ) の評価

KW3 は計装層の実装であり、J_kw の J_village 成分として統合される。KW4 で実際のシミュレーター結合時に評価を行う。

- compute_village_health_score は churn の適正範囲 [0.05, 0.30] に基づく二値判定に更新済み（KW1 の線形近似からの改善）
- 4 指標すべてが [0, 1] 範囲かつ NaN/Inf フリーであることを確認

## 6. 次チケットへの示唆

1. 知識拡散速度とフローバランスは位置変化なしのテストでは常に 0.0 となる。KW4 のシミュレーター結合時には、ワークフロー位置の時間変化に伴う村再編成がこれらの指標にどのように影響するかを観測する必要がある。

2. 村形成強度が 0.99 以上と高いため、村間相互作用率が適切に変動している。村形成強度が低い（位置が分散している）シナリオでのテストを KW4 で追加するとよい。

3. compute_cross_village_interaction_rate の独立関数は、population の ID マッピングが解決できないためスタブとして 0.0 を返す設計とした。実際の計算は VillageInteractionObserver 内で HashMap を使用して行う。この設計判断は KW2 の reuse_ratio 計装と同様のパターンである。
