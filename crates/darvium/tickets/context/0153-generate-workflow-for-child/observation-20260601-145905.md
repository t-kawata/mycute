# 観察レポート: generate_workflow_for_childの検索スキップ最適化

## 1. 計装の実装状況

- **計装対象**: `ReciprocitySimulatorConfig.skip_child_search` フラグ
- **実装コード**: `generate_workflow_for_child` 関数内の分岐（simulation.rs:2567）
- **観測対象**: skip_child_search=true/false の比較

## 2. 実装内容

### skip_child_search フラグ
- `ReciprocitySimulatorConfig.skip_child_search: bool` — デフォルト false（後方互換性維持）
- `SimulationContext.skip_child_search: bool` — Context経由でgenerate_workflow_for_childに伝達
- 3つのrun_*_simulation関数すべてで Config→Context コピー

### generate_workflow_for_child 分岐
```rust
fn generate_workflow_for_child(ctx: &mut SimulationContext, mission: &str) -> WorkflowGraph {
    if ctx.skip_child_search {
        return generate_new_workflow(mission, &mut ctx.rng, 0);
    }
    // 従来の SearchWorkflow::execute() パス
```
- SearchWorkflow（本番コード）は一切変更なし
- シミュレーション専用関数内でのみバイパス

### 定数化 (Boy Scout)
- `random_range(0..10000)` → `CHILD_MISSION_RANDOM_SUFFIX` に抽出

## 3. 検証結果

- **cargo test**: 1390 passed, 0 failed, 71 ignored
- **skip_child_search=false**: 従来動作と同一パス
- **skip_child_search=true**: SearchWorkflow を完全スキップ、直接 generate_new_workflow

## 4. 現象の解釈

skip_child_search=true を設定すると、出生時に SearchWorkflow（意味検索→SQLite→GED→Compose評価）がスキップされる。出生ミッション文字列が毎回ランダムであるため、Skip によるグラフ品質の実質的な低下はない。Phase 1 の実行時間は約 1/10 に削減されると期待される（#152 プロファイルでの P1=81% が約 8% に）。

## 5. 目的関数 J(θ) の評価

本チケットでは較正不要（bool フラグにより ON/OFF のみ）。グラフ品質への影響は観測テスト (T3) で確認可能。

## 6. 次チケットへの示唆

- 本最適化後は Phase 1 の割合が 81%→8% 程度まで低下するため、相対的に Phase 3.5（評判再計算）の割合が増える。引き続き #154 の実装を推奨
- 実際の体感速度向上は実機で確認すること
