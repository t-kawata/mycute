# 観察レポート: M-2-1.6 LLMClient 抽象トレイトの定義

## 1. 計装の実装状況

- 計装対象: トレイト境界を通過する LLM 呼び出しの全二重記録による完全監査可能性。`FakeLlmClient` における出力のシャノンエントロピーと注入された乱数ノイズのエントロピーの一致性。
- 実装したテストコード: `src/llm/mod.rs` — `observation_llm_entropy_consistency()` (OTS-LLM)
- 観測した統計量: 出力カテゴリ分布（正常/空文字列/不正JSON/予期外文字列）、シャノンエントロピー $H_{obs}$、エントロピー比 $H_{obs}/H_{exp}$

## 3. 較正ループ

### 反復 1
- 仮説: `FAKE_LLM_DEFAULT_MALFORMED_PROB` はデフォルト 0.0 で乱数モード無効。設定変更時のエントロピー一致性を観測テスト OTS-LLM で確認（確率 0.3 でテスト実行 → エントロピー比 1.0000 で完全一致）。
- 変更定数: なし（テストパラメータとして直接指定）
- 観測結果: エントロピー一致性が成立（観測 1.356780 bits = 期待 1.356780 bits）
- 解釈: FakeLlmClient の決定論的ハッシュベース乱数生成が、確率設定に対して正確なカテゴリ分布を生成していることを確認。

## 4. 現象の解釈（日本語）

FakeLlmClient のエントロピー特性を観測した結果、以下の知見を得た:

- **エントロピー一致性**: 観測エントロピーと期待エントロピーが完全一致 (1.356780 bits) した。これは、FakeLlmClient の内部で使用されている線形合同法ベースの決定論的ハッシュが、確率 p=0.3 のベルヌーイ試行を正確に再現していることを示す。出力カテゴリも期待値に対して 0.1% 未満の誤差で均等に分布しており、3種類の不正フォーマット（空文字列・不正JSON・予期外文字列）が等確率で出現する設計が正しく機能している。

- **完全監査可能性**: 呼び出し回数 (`call_count: Arc<AtomicUsize>`) による追跡機構により、トレイト境界を通過する全 LLM 呼び出しがカウント可能である。これにより後段で RealLlmClient に差し替えた際も、同一の監査パターンを適用できる。

- **出力カテゴリ分布**: 7000 正常 / 999 空文字列 / 1000 不正JSON / 1001 予期外文字列。3つの不正カテゴリ間の偏りは統計的に有意でない（χ² ≈ 0.002, p ≈ 0.999）。これは `generate_malformed` 内の `count % 3` による巡回選択が、十分なサンプル数で均等分布に収束することを確認した。

## 5. 目的関数 J(θ) の評価

- エントロピー一致性: ✅ 観測 = 期待 (ratio = 1.0000)
- カテゴリ分布の一様性: ✅ 3不正カテゴリが均等分布
- 決定論性: ✅ 同一シーケンスで完全再現可能
- トレイト境界完全性: ✅ Box<dyn LLMClient>, Send + Sync 確認済み

## 6. 次チケットへの示唆

- FakeLlmClient の決定論的性質は M-0.5-1（スクリプト化 Fake LLM）で直接利用可能。RealLlmClient のテストでも本 FakeImpl を基準とした比較検証が可能。
- エントロピー観測テストは、RealLlmClient 導入後に「Fake と Real の動作差」を定量化するベースラインとして再利用できる。
- `call_count` による監査機構は、リトライ・サーキットブレーカーロジック（M-2-2 以降）のテスト基盤としても機能する。
