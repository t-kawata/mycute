## 3. 較正ループ

### 反復 1
- 仮説: TRUST_INHERIT_DECAY=0.70 が phase1 継承 fidelity に与える影響は deterministic であるため fidelity=1.0 が期待される
- 変更定数: なし（TRUST_INHERIT_DECAY=0.70 は既存）
- 観測結果: trust_inheritance_fidelity=1.000000（期待通り）
- 解釈: inherit_trust は child = parent * decay の厳密演算であるため、fidelity は常に 1.0。decay の値に依存しない。

## 4. 現象の解釈（日本語）

**mean_benevolence_aggregate=0.491471**: SimulationContext の TrustProfile は子ノードが (0.3, 0.3, 0.3)、成人が (0.6, 0.6, 0.6) で初期化される。成人比率と子比率のバランスから平均約 0.49 となり、0.5 を下回る妥当な値。benevolence プロキシとして TrustProfile 3 次元平均を使用する方式は RFC の B_i 定義（重み付き評判結合）の簡略版として機能する。

**mean_reciprocity_score=0.000000**: 現在の HELP プロトコルは成人→子の一方向提供のみであり、子が成人に HELP を返す機構が存在しない。そのため全ペアが非対称となり reciprocity は 0.0。これは設計上の制約であり、実装の誤りではない。双方向 HELP が発生する拡張があれば初めて非ゼロになる。

**trust_inheritance_fidelity=1.000000**: inherit_trust の演算が deterministic（child.operational = parent.operational * TRUST_INHERIT_DECAY の厳密乗算）であるため、各継承イベントの fidelity は常に 1.0（理想値）。decay の値（0.70）に依存しない。何らかのノイズ注入や確率的変動が導入された場合に初めて 1.0 を下回る。

## 6. 次チケットへの示唆

- mean_reciprocity を非ゼロにするには、子→成人の HELP 方向を可能にする双方向 HELP プロトコルの導入が必要
- trust_inheritance_fidelity が常に 1.0 であるのは deterministic 継承による。将来的に継承にノイズや突然変異を導入する場合、fidelity 測定が意味を持つ
- j_trust の RFC §15.9.2 定義（J_trust = 1/|S| * sum min(T_c / (T_p * gamma_decay), 1.0)）は現在の trust_inheritance_fidelity と等価。RFC 準拠の j_trust には TrustProfile 次元ごとの fidelity 計算が必要。
