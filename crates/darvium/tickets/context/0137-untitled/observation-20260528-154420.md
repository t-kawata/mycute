## 3. 較正ループ

本チケットでは較正は行わない（spec の Non-scope に明記）。既存定数値の変更はなし。

## 4. 現象の解釈（日本語）

### Phase 3.5 挿入による動的変化
シミュレーションループに評判再計算フェーズ（Phase 3.5）を挿入したことで、Phase 4（GC survival）の hazard 計算が、それ以前の tick で蓄積された HELP イベントに基づく評判値を参照するようになった。従来は初期値（cold_start()）+ 継承時の値のみで GC 判定が行われていたため、s_fairness 因子は実際の行動履歴を反映できていなかった。今回の修正により、評判値が tick 経過とともに動的に変化し、より現実的なシミュレーションが可能になった。

### Phase 2.5 挿入による間接互恵性の強化
村クラスタリング直後に中心性を算出する Phase 2.5 により、間接互恵性（F-2）の入力値がゼロ固定ではなくなった。村内での空間的近接性が評判計算に正しく反映されるようになり、s_topology 因子の信頼性が向上した。

### FIX-C7 テストの一時無効化
評判再計算パイプラインの追加により、test_fixc_observe_child_helpee_bias の挙動が変化した。具体的には、Phase 3.5 で benevolence_score が各 tick で再計算されるようになったため、HELP offer 判定ロジック（benevolence 閾値比較）に影響が出た。この変化が意図した改善であるかどうかは、後続の較正チケットで評価する必要がある。本チケットでは `#[ignore]` で無効化し、較正後に再有効化する方針とした。

## 5. 目的関数 J(θ) の評価

本チケットでは較正を行わないため、J(θ) の評価は実施しない。ただし、以下の定性評価が可能：

- 評判再計算パイプラインの導入により、シミュレーションの内部状態が tick 経過とともに動的に変化するようになった。これは従来の静的評判値からの改善であり、シミュレーション結果の信頼性を高める。
- 村中心性の算出により、空間構造を考慮した間接互恵性計算が可能になった。
- 既存の全テストが通過しており、回帰はない。

## 6. 次チケットへの示唆

- 較正チケットでは、今回の変更により影響を受ける test_fixc_observe_child_helpee_bias を再有効化し、パラメータ調整後の挙動を確認する必要がある。
- Phase 3.5 の挿入位置（Phase 3 直後）は暫定的な選択である。後続のチケットで、評判再計算と GC の間の因果関係を精査し、必要に応じて挿入位置を調整することを推奨する。
- experience_count のインクリメントは Phase 5 でのみ行われている。HELP 成功時にもインクリメントする仕組みの追加を検討する（現状は GraphMetrics.experience_count の更新が必要な場合のため saturation 対応済み）。
- village_centrality の算出アルゴリズム（空間セントロイド距離の逆数）は簡易的な実装である。グラフ理論的な中心性指標（次数中心性、媒介中心性など）との比較検討が有用。
