## 4. 現象の解釈（日本語）

### 人口制御の動作原理
`compute_adjusted_policy` 関数は、現在の生存人口と目標人口を比較し、ヒステリシス帯を考慮して GC ポリシーを動的に調整する：

1. **HIGH 圧状態**（生存人口 >= 目標 + ヒステリシス）:
   - `lambda_gc_base` を上げる（デフォルト 1.0 → 3.0）→ 全個体の死亡率上昇
   - `gamma_child_protect` を下げる（デフォルト 8.0 → 2.0）→ 子供保護緩和

2. **LOW 圧状態**（生存人口 <= 目標 - ヒステリシス）:
   - `lambda_gc_base` と `gamma_child_protect` をデフォルトに戻す

3. **ヒステリシス帯**（目標 ± ヒステリシス幅）:
   - 圧力状態を維持（変更なし）→ 発振防止

### ヒステリシスの安全性
`target_hysteresis=0` に設定しても、`compute_adjusted_policy` 内で `.max(1)` により最小ヒステリシス 1 が強制される。これにより、目標人口と同数の場合に HIGH/LOW が頻繁に切り替わる発振が防止される。

### フロントエンド連携
既存の `Arc<RwLock<SimulationParams>>` パイプラインを拡張し、`target_population` フィールドを追加。フロントエンドのスライダー変更が WebSocket → SimCommand → sim_params と伝播され、`run_evaluation_simulation_with_channel` 内で config 値より優先される。

## 5. 目的関数 J(θ) の評価

- **収束速度**: 本実装は人口制御の枠組みを提供するものであり、具体的な較正は未実施。較正は今後の観測テスト（OT1/OT2）で行う。
- **定常誤差**: 実装上の最小ヒステリシス 1 により、目標人口 ±1 の範囲で定常偏差が生じうる。これは発振防止のための意図的な設計。
- **オーバーシュート**: 人口が目標+ヒステリシスを超過した時点で HIGH 圧がかかるため、オーバーシュートはヒステリシス幅以内に制限される。
- **総合評価**: 実装完了。J(θ) 較正は今後の観測テストで行う。

## 6. 次チケットへの示唆

- 長期的な人口安定性を確認するには、`run_simulation` を使用した観測テスト（OT1/OT2）を実装し、数百 tick にわたる人口変動を観測する必要がある
- より細かい制御が必要な場合、比例制御（P制御）や目標人口に近づくほど圧力を弱める方式に拡張可能
- フロントエンドのスライダーは即時反映されるため、シミュレーション実行中に目標人口を動的に変更できる
