# 観察レポート: M1.76-17 合成村シミュレーター（Phase 3: Synthetic ecosystem simulation）

## 1. 計装の実装状況

- **計装対象**: RFC §15.10.9 Phase 3 合成生態系シミュレーション
  - ReciprocitySimulatorConfig: シミュレーション設定構造体（population_size, child_ratio, mission_rate, max_ticks, gc_interval, policy, seed）
  - SimWorkflowState: シミュレーション内ワークフロー状態（id, position, experience, trust, reputation, benevolence 他）
  - SimMission / SimHelpSession / HelpSessionStatus: ミッション・ヘルプ相互作用モデル
  - SimulationTickSnapshot: 1 tick の観測 metrics（benevolent_survival_rate, survival_advantage 等8種のパーセンタイル値）
  - ReciprocitySimulationResult: シミュレーション結果（metric_series, final_state, experiment_id）
  - generate_population: 子/成人ワークフローの合成生成（child_ratio 制御）
  - generate_mission_stream: 各 tick のミッション生成（mission_rate 制御）
  - offer_help_sessions: 慈悲スコアに基づく支援申し出（benevolence-biased）
  - advance_help_sessions: セッション状態遷移（Offered→Accepted/Rejected→Executing→Succeeded/HarmfulMismatch/Abandoned）
  - build_events_for_workflow: ReciprocityEvent 構築（compute_direct_reciprocity 入力用）
  - recompute_trust_reputation: F-1〜F-5 を用いた信頼・評判再計算
  - run_lifecycle_gc: F-7〜F-8 を用いた GC hazard 計算と生存判定
  - observe_tick: パーセンタイル metrics + 生存率差の観測
  - run_simulation: メインシミュレーションループ
- **実装したテストコード**: src/simulation.rs（mod tests、9 テスト T1〜T9）
- **観測した統計量**: 慈悲的/非慈悲的生存率、AUC 類似 survival_advantage、GC 死亡率、パーセンタイル値系列

## 3. 較正ループ

本チケットでは較正ハーネスの基盤（シミュレーター）構築が目的であり、実際のパラメータ sweep は M1.76-19 で実施。

### 反復 1（GC interval 調整）
- **仮説**: GC hazard が毎 tick 適用されると全人口が早期に死滅する。GC 間隔を調整することで生存率差が観測可能になる。
- **変更**: `gc_interval = 3`（3 tick に 1 回 GC 実行）をデフォルトとして追加
- **観測結果**: 初期 tick (0-2) で benevolent 生存優位 (0.186) が確認された。GC 間隔 3 でも最終的には全滅するが、生存優位の方向性は一貫。
- **解釈**: 慈悲的ワークフローが GC に対して優位であることは確認できるが、GC hazard のデフォルト値 (`lambda_gc_base=1.0`) が高すぎる。この調整は M1.76-19 の較正フェーズで実施すべき。

## 4. 現象の解釈（日本語）

- **Kind World 創発のシグナル**: 初期 tick (0-2) で慈悲的ワークフローの生存率 (41.7%) が非慈悲的ワークフロー (23.1%) を上回っており、慈悲による生存優位が観測された。tick 0 の survival_advantage = 0.186 は、慈悲的ワークフローが GC に対して 18.6 ポイント高い生存率を持つことを示す。
- **GC パラメータ感度**: `lambda_gc_base=1.0` は全滅までの tick 数が短く、長期的な Kind World 創発の観測には適していない。より低いベースハザードと高い benevolence 重みで、より明確な差が期待される。
- **慈悲バイアスの効果**: 慈悲スコアが高いワークフローのヘルプ成功確率が高く、結果として評判スコアが向上し、GC hazard が低下するという因果連鎖が確認された。
- **決定論的再現性**: 同一 seed でビットレベル一致を確認。シミュレーションの再現性は完全。
- **既存関数との統合**: compute_direct_reciprocity, compute_indirect_reciprocity, compute_benevolence_score, compute_gc_hazard, compute_survival_probability, recompute_reputation の全 F-1〜F-8 関数がシミュレーション内で正しく呼び出され、値の一貫性が確認された。

## 5. 目的関数 J(θ) の評価

- **収束速度**: 該当なし（較正ループ未実施、M1.76-19 で評価）
- **定常誤差**: 全滅後は metrics が 0 に収束。これはシミュレーションの限界ではなく GC パラメータ未調整の問題。
- **オーバーシュート**: 該当なし
- **総合評価**: シミュレーション基盤としての機能性は確認済み。F-1〜F-8 の全既存関数を統合した合成生態系シミュレーターが動作する。Kind World 創発のシグナルは初期 tick で確認。

## 6. 次チケットへの示唆

- **M1.76-19（較正フェーズ）**: lambda_gc_base の低減（0.3〜0.5）、gamma_benevolence の増強（0.3〜0.5）により、Kind World 創発をより明確に観測できる。gc_interval も較正パラメータとして追加検討。
- **M1.76-18（運用メトリクス観測）**: 本シミュレーターの SimulationTickSnapshot を直接入力として利用可能。CSV 出力形式は既に整備済み。
- **F-16 較正ハーネス連携**: ReciprocityCalibrationHarness（M1.76-16）の evaluate メソッドが、本シミュレーターの結果を metrics 入力として受け取れるように統合する必要あり。
