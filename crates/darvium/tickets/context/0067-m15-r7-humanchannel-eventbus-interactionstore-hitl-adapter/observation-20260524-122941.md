## 4. 現象の解釈（日本語）

EventBusHumanChannel は HumanChannel トレイトの adapter 変換を RFC §12B.3 に従って実装した。
notify は DarviumEventBus::publish(OneWay, NotificationRequested) に変換され、
communicate は open(TwoWay, InteractionRequested) + MetadataStore on Pending に変換される。
reconnect は MetadataStore::reconnect_interaction + EventBus::reconnect の二段階で行う。
非同期解決のための mpsc pending マップを内部に持ち、EventBus::resolve からの応答を
InteractionHandle::wait に中継する。

FakeHumanChannel は eventbus_delegate フィールドを Option で保持し、
with_config() で adapter モードが有効化された場合のみ委譲する。
従来の new() コンストラクタは従来モードのままであり、後方互換性が保たれている。

MetadataStore 実装（InMemoryMetadataStore / JsonMetadataStore / FailingMetadataStore）の
RefCell→Mutex 変換は Arc<dyn MetadataStore + Send + Sync> を EventBusHumanChannel で
使用するための前提条件である。これにより HumanChannel が要求する Send/Sync 境界を充足する。
