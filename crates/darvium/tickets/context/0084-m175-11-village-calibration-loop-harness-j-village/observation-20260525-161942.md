# 観察レポート: M1.75-11 Village Calibration Loop Harness (\(J_{village}\))

## 1. 計装の実装状況

- **計装対象**: Village 状態の統計量（churn, JSD, child survival rate, false new, review load）を ReplayTrace から再構成し、目的関数 \(J_{village}(\theta)\) を計算する較正ハーネス。
- **実装したテストコード**: `src/calibration.rs`（12 テスト）
  - objective_*: 目的関数の境界値・感度・劣化・決定論性・重み感度（5 tests）
  - sweep_*: OFAT / Grid / LHS の各スイープモード（3 tests）
  - harness_*: ハーネス全体の整合性・空パラメータ・レポート形式（4 tests）
- **観測した統計量**:
  - 目的関数値 \(J_{village}\) の分布（3 パラメータ × 3 値で 27 通りのグリッド評価）
  - churn_p95（0.1–0.3 程度）、jsd_p95（0.01–0.1 程度）、survival_rate（0.6–0.9 程度）
  - 各パラメータ因子の主効果（helper_boost が churn に最も影響、min_confidence が生存率に影響）

## 3. 較正ループ

### 反復 1
- **仮説**: 目的関数の重みが偏っていると、ある指標が過剰に最適化される。バランスのとれた重み（churn=0.35, jsd=0.25, survival=0.25, false_new=0.10, review_load=0.05）を初期値として設定する。
- **変更定数**: OBJECTIVE_WEIGHT_CHURN=0.35, OBJECTIVE_WEIGHT_JSD=0.25, OBJECTIVE_WEIGHT_SURVIVAL=0.25, OBJECTIVE_WEIGHT_FALSE_NEW=0.10, OBJECTIVE_WEIGHT_REVIEW_LOAD=0.05（全定数新規追加）
- **観測結果**: 全テスト通過。C-2（extreme params degradation）で helper_boost を 0.1 に下げると J 値が低下（0.668→0.584）、churn 劣化が主要因。offer_threshold の主効果は極めて小さい（OFAT 範囲 < 0.001）。

### 反復 2
- **仮説**: offer_threshold が OFAT でほぼ変動しないのは、パラメータ範囲（0.70→0.20）が不十分か、Fake 環境で offer が saturated している可能性がある。
- **変更定数**: なし（パラメータ範囲の調整はテスト内で行うべき事項であり、定数変更ではない）
- **観測結果**: C-2 の helper_boost 範囲を 0.5→0.1 に拡大したところ、J 値の劣化が明確に観測可能（delta=-0.084）。offer_threshold は Fake 環境では本質的に影響が小さいことが確認された。
- **解釈**: 現状の Fake 実行環境では offer_threshold や acceptance ポリシーの効果が限定的。これは実際の LLM 駆動エージェントでは異なる可能性がある。

## 4. 現象の解釈（日本語）

Village 較正ハーネスを実装し、12 のテスト（C-1～C-12）ですべての機能を検証した。最も顕著な観測結果は、**helper_boost パラメータが churn 率に与える影響が支配的**であることだ。helper_boost を 0.8 から 0.3 に下げると J 値は 0.668 から 0.664 と微妙な変化しか示さないが、0.1 という極端値では churn_p95 が急上昇し J 値が 0.584 まで低下した。これは helper が少ない村ほど新生児（child）の支援が不十分になり、結果として脱落（churn）が増加するというメカニズムと整合的である。

一方、offer_threshold の OFAT スイープでは J 値の変動が 0.001 未満と実質的にゼロであった。この理由は、Fake 実行環境ではすべての提案が機械的に受け入れられるため、閾値の効果が現れないことにある。本番 LLM 結合時には異なる挙動が期待される。

目的関数 J 値の典型範囲は約 0.60～0.72 であり、churn_p95 が 0.1～0.3、jsd_p95 が 0.01～0.1、survival_rate が 0.6～0.9 という分布は理論的期待値と整合している。false_new と review_load は現在の Fake 環境では常に 0 であり、これらが観測可能になるのは M2+ フェーズとなる。

## 5. 目的関数 \(J(\theta)\) の評価

- **収束速度**: N/A（較正ループは 1 回のイテレーション、本格的な最適化はスイープ結果を見て人間が判断）
- **定常誤差**: 目的関数値 J は標準的なパラメータで 0.668、最大 0.714（生存率を人為的に高めた場合）。理論的最大値 1.0 に対して乖離があるが、これは churn や JSD がゼロにならない現実的制約を反映している。
- **オーバーシュート**: なし
- **総合評価**: 良好。OFAT / Grid / LHS の 3 モードが正常動作し、目的関数はパラメータ変化に対して正当な単調性を示す。Fake 環境での限界（false_new=0, review_load=0）は認識済み。

## 6. 次チケットへの示唆

1. **LLM 結合後**（M2+）に offer_threshold や acceptance ポリシーの較正が重要になる。その時点で LHS スイープを本格活用すること。
2. **false_new と review_load** が観測可能になった時点で、目的関数の重みを再調整する必要がある（現状はこれらの重みが機能していない）。
3. OFAT スイープはパラメータ数が少ない現状では十分有効だが、パラメータ数が増えたら LHS が推奨される。ステップ数を SWEEP_LHS_DEFAULT_SAMPLES=20 から 50 程度に増やすことでより細かい探索が可能。
4. **定数名の命名規則**: 較正候補定数は `CALIB_` プレフィックスで統一すると後で一覧しやすい（現状は `OBJECTIVE_WEIGHT_*` と `SWEEP_*` の混在）。
