## 3. 較正ループ

本チケットは純粋関数の実装が主目的であり、較正対象の定数は constants.rs に定義済みだが較正ループ自体は KW4 で実施する。以下の発見があった：

### 発見 1: 空入力時の J_kw ≠ 0
- 仮説: 全 metrics = 0 で J_kw = 0
- 結果: cost_efficiency=0 → J_cost = 1.0 - 0 = 1.0（最大）。benevolent_ratio=0 → J_penalty = 1.0（最大）。J_kw = 0.325
- 解釈: 「全ゼロ入力 = 最悪の状態」ではない。cost_efficiency=0 は「極度の非効率」=「改善の余地が最大」と解釈され J_cost が最大になる。これは意図された動作であり、J_cost の定義域が [0, 1] となるよう clamp されているため NaN/Inf は発生しない。
- 対処: TC-6 の assertion を「J_kw = 0」から「panic せず J_kw が有限値」に修正

### 発見 2: J_penalty の寄与方向
- 仮説: J_penalty は「ペナルティ」なので J_kw を減少させる
- 結果: RFC 定義 J_penalty = max(0, 1-ratio) は、慈悲的劣位（ratio < 1）で高い値を返す。α₆·J_penalty は J_kw に正の寄与をする
- 解釈: J_penalty は「ペナルティの大きさ」を測る指標であり、全 J 成分と同様に「値が高い = 何かを測定している」という設計。J_kw の各成分は全て正の重みで加算されるため、J_penalty が高いと J_kw も高くなる。これは「慈悲的劣位が大きい = エコシステムが penalize されるべき状態」を定量化しており、目的関数設計として一貫している。
- 対処: TC-7 の assertion を方向修正。「J_penalty あり < なし」→「ratio 変化で J_kw が変化することの確認」

## 4. 現象の解釈

Kind World 目的関数 J_kw は 6 成分の重み付き和として設計され、RFC §15.9.2 の定義を忠実に実装した。n=10,000 のランダム入力テストでは常に J_kw ∈ [0, 1] かつ NaN/Inf フリーであることが確認された（最小 0.085、最大 0.897、平均 0.480）。

Kind World 成立率は 2.52%（n=10,000 中 252 件）と低く、これはランダム入力では 8 条件すべてを同時に満たす確率が低いことを反映している。各条件の閾値（人口成長 1%・Shannon 多様性 0.5・再利用 0.3 等）は現実的なハードルとして設計されており、ランダムなパラメータ空間では稀にしか成立しない。

6 つの重み係数は Σα = 1.0 を満たし（精度 1.1e-16）、人口成長（α₁=0.25）と能力カバー率（α₂=0.20）およびコスト効率（α₄=0.20）が主要な寄与成分となっている。
