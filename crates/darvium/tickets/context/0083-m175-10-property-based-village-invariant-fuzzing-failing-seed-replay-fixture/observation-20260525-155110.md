## 4. 現象の解釈（日本語）

1. **ヘルパー選定の頑健性**: 10,000 ケースのランダム生成を行った結果、select_helpers は top_k 制約を常に守っていた。HelperSelectionPolicy の各パラメータ変動に対して helper 選定数が安定していることを確認。
2. **ConsistencyState フィルタの完全性**: 全 variant の ConsistencyStateTag をランダムに注入しても、filter_adult_candidates は Committed のみを通す。Pending/NeedsRepair/Quarantined の混入は 100% ブロックされる。
3. **HELP 状態機械の安全性**: 終端状態（Rejected/Succeeded/Failed）からの遷移は is_legal_help_transition により常に違法と判定される。proptest による全組み合わせテストで確認。
4. **空 village の安全フォールバック**: 候補が全滅しても build_local_village_topk は panic せず空の LocalVillage を返す。unsafe execution のリスクはない。
5. **Fixture 基盤の動作確認**: FailingSeedEntry の JSON ラウンドトリップ（シリアライズ→デシリアライズ→フィールド一致）が正しく動作。fixture ディレクトリの自動作成と sample 保存も確認。
