# 観察レポート: M1.5-R2: MetadataStore 汎用 Interaction API 拡張

## 1. 計装の実装状況

- 計装対象: 6メソッド × 1000 呼び出しのスループット計測（spec OTS-1）
- 実装したテストコード: `src/store/metadata_store.rs` → `ots1_throughput_measurement`
- 観測した統計量: 各メソッドの合計実行時間、平均レイテンシ（ns/call）、スループット（calls/sec）

## 2. 観測テスト実行結果

```
=== OTS-1: Throughput Measurement ===
  n=1000
  store_interaction:    1.547708ms (avg 1547.7 ns/call)
  load_interaction:     674.958µs (avg  675.0 ns/call)
  list_interactions:    401.422709ms (avg 401422.7 ns/call)
  resolve_interaction:  1.861541ms (avg 1861.5 ns/call)
  abort_interaction:    1.397375ms (avg 1397.4 ns/call)
  reconnect_interaction:320.75µs (avg  320.8 ns/call)
  total (6 x 1000):     407.225041ms
  throughput:           14734 calls/sec
=== 結果: PASS ===
```

## 3. 較正ループ

本チケットはインターフェース追加のみであり、較正対象の定数はない。較正ループは実施していない。

## 4. 現象の解釈（日本語）

全6操作が O(1) の計算量を示し、1000回の呼び出しが合計407ms（約14,734 calls/sec）で完了した。内訳を見ると、list_interactions が他と比較して顕著に遅い（401ms / 1000回 = 401μs/call）。これは list_interactions が全レコードを反復処理する O(n) 操作であり、かつ OTS-1 のテスト設計上、呼び出し時点で既に約4000件のレコードが蓄積されているためである。他の操作（store/load/resolve/abort/reconnect）はすべて HashMap のキー検索（期待 O(1)）であり、数百ns〜数μsで完了している。

この性能は十分実用範囲であり、特にチューニングは不要。list_interactions はレコード数に比例して線形に増加するため、大規模データ（10万件以上）での使用時にはページネーションやインデックス追加を検討する余地がある。

## 5. 目的関数 J(θ) の評価

- 収束速度: 該当なし（較正対象なし）
- 定常誤差: 該当なし
- オーバーシュート: 該当なし
- 総合評価: 6操作すべてが期待通りの O(1) パフォーマンス。list_interactions の線形特性も想定内。

## 6. 次チケットへの示唆

- list_interactions のパフォーマンスはレコード数に依存する。大規模データを扱う後続チケットではページネーション対応を検討する。
- store_interaction と resolve_interaction のレイテンシが近い（~1.5μs vs ~1.9μs）ことは、両者が同じ HashMap 操作を内在していることと整合する。
