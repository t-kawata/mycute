## 3. 較正ループ

本チケットでは新たな較正パラメータは導入せず、既存定数（DETERMINISM_THRESHOLD 等）の変更なし。較正は観測後の判断とした。

## 4. 現象の解釈（日本語）

### GMR 差分推論の動作
DeterminismScore がグラフ構造（out-degree）から計算されるようになり、det_score は 0.59〜0.75 の範囲で分布している。target_size は DETERMINISM_THRESHOLD を超えるスコアにより常に 3 となっている（2 + (0.6〜0.75)*2 = 2 + 1〜2 = 3〜4）。実際の抽出ノード数は BFS の接続状況により 1〜3 ノードに分布。抽出エッジは 0〜4 本で、接続密度の高い部分グラフが選択される傾向。

### HELP 提案モデルの動作
受入確率（accept_prob）は 0.50〜0.57 の範囲で分布しており、約 30〜50% の提案が受け入れられている。helper のノード数が helpee より少ない場合でも提案が行われ（例: helper=7 helpee=13 で提案 rejected）、「助けようとする」動きが実現されている。

### 複雑化の改善
最大ノード数が 30+ に到達しており（例: helper=31 helpee=22）、以前の 15 ノード上限を大きく超えている。出生時のノード数も 8〜12 ノード程度と複雑化している（WORKFLOW_GENERATION_MAX_COMPLEXITY=4 の効果 + SearchWorkflow PATCH/COMPOSE）。

## 5. 目的関数 J(θ) の評価

- knowledge_diffusion_rate = 0.946（高い — GMR + HELP 提案が活発に伝搬）
- mean_node_density = 0.315（中程度 — さらなる複雑化の余地あり）
- 収束速度: tick_to_convergence = 10（20 tick 中 10 で収束）
- 総合評価: 改善。複雑化メカニズムが活性化した。

## 6. 次チケットへの示唆

- DeterminismScore の target_size が常に 3 になっているのは、DETERMINISM_THRESHOLD が低すぎる可能性がある。閾値を引き上げると低 determinism のグラフは 1 ノードのみ、高 determinism のみ 4 ノードまでという差別化が可能。
- HELP 提案の受入確率が 0.50〜0.57 と狭い範囲に集中している。benevolence と trust_factor の重み係数を調整することで、より広い分布を得られる可能性。
- ノード数が 30+ まで成長しているが、この規模で HELP 提案の 1〜3 ノード追加の影響が相対的に小さくなる。後続チケットでは GMR の抽出サイズ上限引き上げや、複数回拡散を検討。
