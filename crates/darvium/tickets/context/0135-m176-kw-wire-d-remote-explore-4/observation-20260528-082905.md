# 観察レポート: M1.76-KW-WIRE-D: REMOTE_EXPLORE_* 定数のシミュレーション実装 — 遠隔探索機構の導入

## 1. 計装の実装状況

- 計装対象: `offer_help_sessions()` の村内/村外別 offer 確率検証
- 実装したテストコード: simulation.rs test_d1〜test_d6
- 観測した統計量: 村内 offer 回数、村外 offer 回数、LOCAL_HELP_BOOST 感度、child_need 境界値

## 2. 観測テスト実行結果

```
D1: local offers count = 1
D2: remote offers count = 0 (expected 0)
D3: total remote offers in 1000 trials = 0 (expected 0)
D4: base boost offers=1, 2x boost offers=1
D5: offers without village_assignments = 1 (expected >0)
D6: child_need (no children) = 0, child_need (all children) = 1
```

## 3. 較正ループ

本チケットは遠隔探索機構のロジック追加が目的であり、パラメーター値の較正は WIRE-E 完了後の統合較正で実施する方針のため、較正ループはスキップ。

## 4. 現象の解釈（日本語）

### 村内/村外の offer 分離
`offer_help_sessions()` に `village_assignments` 引数を追加し、村内ノードには `(base_prob + epsilon_remote) * local_help_boost`、村外ノードには `epsilon_remote` のみの確率で offer を生成するロジックを実装した。これにより RFC §4A.5 F-13 で定式化された「局所的な助け合いが基本であり、村外への HELP は低確率で探索的に行われる」という設計意図がシミュレーションパスで反映されるようになった。

- D1: 村内同一 village で offer_help_base=1.0 → 確実に offer 生成（counter=1）
- D2: 別 village で epsilon=0 → 村外 offer は 0
- D3: n=1,000 試行で epsilon_remote_max=0 → 村外 offer は 0（統計的に確定）
- D4: LOCAL_HELP_BOOST=1.0 と 2.0 で同一 seed → 2x でも 1 件（小人口のため差が現れなかったが counter2 >= counter1 は成立）
- D5: village_assignments=None → 全ノード local 扱いで正常に offer（後方互換維持）
- D6: child_need 境界値確認（子供 0 → 0.0、全員子供 → 1.0）

### 定数 LOCAL_HELP_BOOST = 1.0
デフォルト 1.0（ブーストなし）に設定。これは後続 WIRE-E での統合較正まで変更しない。

## 5. 目的関数 J(θ) の評価

本チケットはロジック追加フェーズのため、J(θ) 直接評価は実施せず。J(θ) への影響は WIRE-E 完了後の統合較正で評価予定。

## 6. 次チケットへの示唆

- `village_assignments=None` の後方互換パスにより、WIRE-E では既存テストに影響を与えずに追加パラメーターを導入可能
- LOCAL_HELP_BOOST の較正には WIRE-E 完了後に村内/村外別の HELP 比率（VHELP）と s_topology/j_clustering の関係を分析することが有効
- `offer_help_sessions()` のロジックは phase3_help_protocol()（KW-REAL パス）とは独立しているため、両パスで整合性を検証するテストを WIRE-E で追加することが望ましい
