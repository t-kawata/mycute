# M1.76-KW2: エコシステム成長メトリクス計装

## Summary

エコシステムの成長を「人口増加」「能力カバー率拡大」「再利用促進」「コスト低減」の 4 次元で計測する 5 つの純粋関数と、それらを統合する `EcosystemGrowthObserver` を実装する。これにより Kind World の定量的評価に必要な基礎メトリクスが整う。

## Background

- **RFC:** §15.9 SocialAcceleration（トップレベル KPI）、§41B.20.7 ExtendedOperationalMetrics
- **経緯:** M1.76-KW1 で `KindWorldMetricsInput`（9 フィールド）と `compute_kind_world_objective()` が実装された。この入力のうち `population_growth_rate`、`capability_coverage`、`reuse_ratio`、`cost_efficiency`、`benevolent_vs_non_benevolent_coverage_ratio` の 5 フィールドを本チケットで計算する純粋関数を提供する。残りの 4 フィールド（village_formation_score, churn_rate, cross_village_interaction_rate, knowledge_diffusion_rate）は KW3 で実装される。
- **現在の状態:**
  - `src/kind_world.rs` に `KindWorldMetricsInput`（9 フィールド）と `compute_kind_world_objective()` が実装済み（KW1）。
  - `src/simulation.rs` に `SimWorkflowState`、`SimHelpSession`、`ReciprocityEvent` が実装済み（M1.76-17, M1.76-18）。これらが本チケットの計算関数の入力として利用される。
  - `compute_population_growth_rate` 等の 5 関数は未実装。
  - `EcosystemGrowthObserver` は未実装。
- **KW1 との関係:** KW1 が `KindWorldMetricsInput` の受入側（判定ロジック）であるのに対し、KW2 は `KindWorldMetricsInput` の供給側（メトリクス計算ロジック）を実装する。両者は直交しており、KW2 の出力を KW1 の入力に接続することで完全な Kind World 評価パイプラインが完成する。

## Scope

### 実装範囲

1. **`EcosystemGrowthMetrics` 構造体**（`src/kind_world.rs` に追加）:
   - `tick: u64` — 観測 tick
   - `population_growth_rate: f64` — 人口成長率
   - `capability_coverage_shannon: f64` — Shannon 多様性指数で測った能力カバー率 [0, 1]
   - `reuse_ratio: f64` — ワークフロー再利用比率 [0, 1]
   - `cost_efficiency: f64` — コスト効率 [0, 1]
   - `benevolent_vs_non_benevolent_coverage_ratio: f64` — 慈悲的/非慈悲的能力カバー率比

2. **5 つの純粋関数**（`src/kind_world.rs` に追加）:
   - `compute_population_growth_rate(population: &[SimWorkflowState], previous_count: usize) -> f64`
   - `compute_capability_coverage_shannon(population: &[SimWorkflowState]) -> f64`
   - `compute_reuse_ratio(events: &[ReciprocityEvent], sessions: &[SimHelpSession]) -> f64`
   - `compute_cost_efficiency(sessions: &[SimHelpSession]) -> f64`
   - `compute_benevolent_vs_non_benevolent_coverage_ratio(population: &[SimWorkflowState]) -> f64`

3. **`EcosystemGrowthObserver` 構造体**（`src/kind_world.rs` に追加）:
   - `ReciprocityMetricsObserver` と同様の observer パターン
   - `observe(tick, population, sessions, events) -> EcosystemGrowthMetrics`
   - `print_csv(series, prefix)` で CSV 標準出力

4. **定数定義**（`src/constants.rs` に追加）:
   - Shannon 多様性指数計算用のグリッド分割数（Calibration Candidate）

### 非スコープ

- シミュレーター本体への統合（KW4 で実施）
- 村間相互作用・知識拡散トラッキング（KW3）
- 較正ループ実行（KW4）
- `ExtendedOperationalMetrics` への `ecosystem_growth` フィールド追加（KW4 の統合フェーズで実施）
- CSV 出力の可視化・解析（人間の判断領域）

### 関数詳細設計

**1. `compute_population_growth_rate`:**
```
人口成長率 = (current_count - previous_count) / max(previous_count, 1)
```
- 減少時は負値、増加時は正値を返す。
- `population: &[SimWorkflowState]` から生存ワークフロー数をカウント（`w.survived`）。
- `previous_count: usize` は前 tick の生存ワークフロー数（呼び出し側で保持）。
- 空人口時は 0.0 を返す（0 除算防止）。

**2. `compute_capability_coverage_shannon`:**
```
能力空間を 10×10 グリッドに量子化 → Shannon 多様性指数 H = -Σ p_i log p_i
H_max = log(100) で除算 → [0, 1] に正規化
```
- 各ワークフローの `position: [f32; 3]` の x, y 成分（`position[0]`, `position[1]`）を [0, 1) に clamp 後、10 分割。
- 空の場合は p_i = 0 として H = 0 を返す。
- `position` は [0, 1] 範囲の一様乱数で初期化されているため、clamp のみで量子化可能。

**3. `compute_reuse_ratio`:**
```
再利用回数 / 全インタラクション数
```
- 全セッション（`sessions`）のうち、同一 workflow が複数回ヘルプ提供または依頼を受けている割合。
- `helper_id` と `requester_id` をキーに出現頻度をカウントし、2 回以上出現する workflow によるインタラクション数を「再利用回数」とする。
- 全セッション数が 0 の場合は 0.0 を返す。

**4. `compute_cost_efficiency`:**
```
コスト効率 = 1.0 - (失敗セッション数 + 放棄セッション数) / 全セッション数
```
- 失敗: `HarmfulMismatch`、放棄: `Abandoned`。
- 全セッション成功時 1.0、全セッション失敗時 0.0、空セッション時 1.0（無入力の完全効率）。
- KW1 では `cost_efficiency` は「値が小さいほど効率的」として `J_cost = 1.0 - cost_efficiency` と逆転して使われている点に注意。本関数の戻り値はそのまま KW1 の入力となる。

**5. `compute_benevolent_vs_non_benevolent_coverage_ratio`:**
```
慈悲的集団（上位 20%）の能力カバー率 / 非慈悲的集団（下位 20%）の能力カバー率
```
- `BENEVOLENT_TOP_FRACTION`（0.2）と `BENEVOLENT_BOTTOM_FRACTION`（0.2）を使用。
- 各集団内での能力カバー率は Shannon 多様性指数（正規化前の H）で計測。
- > 1.0 で慈悲的優位を示す。
- 各集団の人口がグリッド分割に足りない場合は 1.0 を返す（差がないとみなす）。
- 全人口が空の場合は 1.0 を返す。

## 計装方法・観測対象

### 計装方法

- 全 5 関数を `src/kind_world.rs` の `mod tests` 内のユニットテストとして実装する。
- `EcosystemGrowthObserver` の統合テストはシミュレーターの出力を使用した結合テストとする。
- 観測テスト（`--nocapture` 出力）として、各 tick の `EcosystemGrowthMetrics` を CSV 形式で標準出力に書き出す。
- 固定シード `StdRng::seed_from_u64(12345)` を使用し、決定論的再現を保証する。

### 観測対象

- 各 tick の 5 指標の時系列変化（CSV 出力）
- `benevolent_vs_non_benevolent_coverage_ratio`: Kind World の core signal
- 出力範囲外の値や NaN/Inf が発生した場合は即座にテスト失敗とする
- サンプルサイズはシミュレーターのデフォルト設定（`max_ticks=20`）を基本とする

## Boy Scout Rule — 翻訳可能性計画

本チケットで新規作成するコードに対して以下の方針を適用する：

- **関数名は動詞句**: `compute_population_growth_rate`, `compute_capability_coverage_shannon` 等、自然文として読める命名
- **変数名はドメイン概念**: `population`, `sessions`, `events` 等、チケット仕様と一致する命名
- **一関数一責務**: 5 関数はそれぞれ独立した責務を持ち、混在しない
- **ハードコード値は名前付き定数**: `constants.rs` にグリッド分割数や割合定数を定義
- **エラー握りつぶし禁止**: 空入力 / 境界値は早期リターンで安全に処理し panic させない
- **Observer パターンは既存コードに準拠**: `ReciprocityMetricsObserver`（`simulation.rs:804-867`）と同じ API 設計を踏襲
