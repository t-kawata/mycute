# M1.76-KW-REAL-P3: ワークフロー実行抽象化

## Summary

RFC §4A.4 に定義されたワークフロー実行機構のうち、未実装の 2 機構（compile_to_steps、ErrorMode）を abstract 実装する。既存の SideEffectSet はそのまま流用する。Darvium-Tickets-v2.3.md に定義された StepExecutionResult / StepStatus も合わせて実装する。

## Background

P4（6 フェーズシミュレーションループ）は個人の能力（WorkflowGraph）を「実行可能」と仮定してシミュレーションを進行するが、実際の WorkflowGraph → 実行可能ステップへの変換機構（compile_to_steps）は未実装である。

本チケットは KW-REAL シリーズ 6 チケットの第 5 弾であり、P4 の全フェーズで使用される実行抽象化を提供する。**「シミュレーションはツールであって目的ではない」** — compile_to_steps は単なるトポロジカルソートであり、将来の本物のコンパイラ（IL 生成等）で置き換える trait として定義する。SideEffectSet は既存の本物の型をそのまま流用し、新規型を作らない。

### チケット系列の位置づけ

KW-REAL シリーズは以下の 6 チケットで構成される：
1. ✅ P1: SimulationContext 基盤
2. ✅ P5: ライフサイクル・成熟機構
3. ✅ P4: 6 フェーズシミュレーションループ
4. ✅ P2: GMR 抽象化層
5. 🔴 **P3: ワークフロー実行抽象化（本チケット）**
6. ⬜ P6: 計装インターフェース更新

P3 は P4 と並行開発が可能であり、P4 はスタブモードで動作するため実装順序の制約はない。

## Scope

### 新規作成: src/compiler.rs

1. **compile_to_steps 関数** — `pub fn compile_to_steps(graph: &WorkflowGraph) -> Result<Vec<NodeId>, DarviumError>`
   - petgraph の `toposort` を使用して DAG を直列化
   - 循環依存検出時は `DarviumError::CycleDetected` を返す
   - 空グラフの場合は空の Vec を返す
   - SubWorkflow ノードはエラーにせずそのまま ID を返す（再帰展開は将来の責務）

2. **ErrorMode 列挙型**:
   ```rust
   pub enum ErrorMode { FailOnAny, SkipOnError, Degrade, RetryOnError(u32) }
   ```

3. **StepStatus 列挙型**:
   ```rust
   pub enum StepStatus { Success, Failure, PartialSuccess, Skipped }
   ```

4. **StepExecutionResult 構造体**:
   ```rust
   pub struct StepExecutionResult {
       pub node_id: NodeId,
       pub status: StepStatus,
       pub output: Option<String>,
       pub error: Option<String>,
       pub duration_ticks: u64,
   }
   ```

### 拡張: src/lib.rs

5. `pub mod compiler;` の追加
6. `pub use compiler::compile_to_steps;` の追加
7. 型の再エクスポート（`pub use types::{ErrorMode, StepStatus, StepExecutionResult};`）

## Non-scope

## Test Plan

### ユニットテスト（src/compiler.rs 内 mod tests）

1. **compile_to_steps: 単純 DAG のトポロジカルソート**
   - 3 つの AgentStep を直列接続（A→B→C）し、ソート結果が [A, B, C] またはその逆順になることを確認
   - 結果の要素数が 3 であること

2. **compile_to_steps: 空グラフ**
   - 空の WorkflowGraph で compile_to_steps が空の Vec を返すこと
   - エラーにならないこと

3. **compile_to_steps: 単一ノードグラフ**
   - 1 つの AgentStep のみのグラフで compile_to_steps が [node_id] を返すこと

4. **compile_to_steps: 循環依存グラフ（異常系）**
   - 循環依存を含むグラフで `Err(DarviumError::CycleDetected(_))` が返ること
   - 自己ループ（A→A）も検出されること

5. **compile_to_steps: 分岐・合流グラフ**
   - DAG で分岐（A→B, A→C）と合流（B→D, C→D）があるグラフでソート結果の全ノードが出力に含まれること
   - エッジ方向の依存関係が維持されていること（A が B/C より前、B/C が D より前）

6. **compile_to_steps: SubWorkflow ノードを含むグラフ**
   - SubWorkflow ノードを含むグラフでもソート可能であること
   - SubWorkflow は展開せずそのまま NodeId を返すこと

7. **ErrorMode: バリアントの構築**
   - 全 4 バリアントが構築可能であること（FailOnAny, SkipOnError, Degrade, RetryOnError(3)）
   - Debug/Clone/PartialEq が derive されていること

8. **StepExecutionResult: 全フィールドの構築**
   - 全フィールドを指定して構築可能であること
   - 各フィールドにアクセス可能であること
   - Debug/Clone/PartialEq が derive されていること

9. **StepStatus: バリアントの構築**
   - 全 4 バリアントが構築可能であること（Success, Failure, PartialSuccess, Skipped）
   - Debug/Clone/PartialEq が derive されていること

10. **compile_to_steps: 大規模グラフ（パフォーマンス観測）**
    - 100 ノードの直列 DAG で compile_to_steps が即座に完了すること
    - 結果の要素数が 100 であること

### 回帰テスト

11. 既存の全テスト（1244 tests）が本チケット追加後も PASS すること
