# M1.76-16: 多目的較正目的関数 F-16 + 較正ハーネス

## Summary

Reciprocity モジュールの較正候補パラメータ（`ReciprocityLifecyclePolicy` の全 calibration candidate）を系統的に最適化するための多目的較正目的関数 `J(θ)` を実装する。AUC-based の benevolent survival ranking を含む 6 成分の合成指標を定義し、`ReciprocityCalibrationHarness` として replay/perturbation/simulation 駆動の評価ループを提供する。

## Background

RFC §15.10.8 式 F-16 で定義される較正目的関数は、benevolence（善良性）と survival（生存）の関係を中心に据えた多目的最適化を実現する：

- `J(θ) = λ₁ · AUC_benevolent>nonbenevolent + λ₂ · HelpSuccessRate - λ₃ · VillageChurnP95 - λ₄ · FalseNewRate - λ₅ · ReviewLoad - λ₆ · InstabilityPenalty`

既存の `calibration.rs`（M1.75-11）は village パラメータ（beta, epsilon, top_k 等）の較正を提供するが、reciprocity 特有のパラメータ（`theta_dir`, `gamma_benevolence`, `lambda_gc_base` 等）は較正対象外である。本チケットは ReciprocityLifecyclePolicy の全 calibration candidate を対象とし、benevolent survival advantage を主要指標として組み込む。

M1.76-12（単調性テスト）・M1.76-14（摂動テスト）で観測された ranking 変動や survival drift を、本較正ハーネスでは目的関数の成分として定量化し、最適方向を探索する。

## Scope

### 実装するもの

1. **`SurvivalPair` 構造体**: `{ workflow_id, benevolence_score, survived: bool }` — AUC 計算の基本単位
2. **`ReciprocityOperationalMetrics` 構造体**: 6 成分全てのメトリクスを保持（`auc_benevolent_survival`, `help_success_rate`, `village_churn_p95`, `false_new_rate`, `review_load`, `instability_penalty`）
3. **`compute_auc_benevolent_survival(profiles: &[SurvivalPair]) -> f64`**: 善良群と非善良群の survival ranking AUC を Mann-Whitney U 統計量から計算
4. **`compute_calibration_objective(metrics: &ReciprocityOperationalMetrics, weights: &[f64; 6]) -> f64`**: 式 F-16 の合成値。`[0.0, 1.0]` にクランプ
5. **`ReciprocityCalibrationObjective` 構造体**: 6 成分の重み `λ₁..λ₆` と各成分の計算器メソッドを保持
6. **`ReciprocityCalibrationHarness`**: パラメータ θ（`ReciprocityLifecyclePolicy` の全 calibration candidate）を受け取り、replay/perturbation を実行し各 metrics を計算して `J(θ)` を評価
7. **`CalibrationReport`（拡張）**: θ 設定値・`J(θ)` 値・6 成分値・実験ID を保持。既存の calibration.rs の `CalibrationReport` との整合性を取る（別途 `ReciprocityCalibrationReport` として新規定義も可）
8. **実験系列管理**: `exp-{yyyymmdd}-{seq}` 形式の実験ID + 親実験ID の追跡
9. **定数群**: `constants.rs` に 6 つの λ 重みデフォルト値と較正ハーネス設定定数を追加

### 実装しないもの

- 合成村シミュレーター（M1.76-17 で別チケット）
- 運用メトリクス観測パイプライン（M1.76-18 で別チケット）
- 実際のパラメータ sweep 実行と最適値同定（M1.76-19 較正フェーズで実施）
- 既存 `calibration.rs` の `VillageCalibrationHarness` の改変（独立モジュールとして実装）

## Test Plan

### T1: `compute_auc_benevolent_survival` — ランダム ranking（AUC ≈ 0.5）

- 善良群と非善良群が完全にランダムに生存/非生存する場合、AUC ≈ 0.5（± 0.02 以内）となること
- サンプル数: 各群 1000 件、固定シード

### T2: `compute_auc_benevolent_survival` — 完全分離 ranking（AUC ≈ 1.0）

- 善良群の全員が生存し、非善良群の全員が非生存の場合、AUC ≈ 1.0 となること
- 境界値: 全て生存 / 全て非生存でも panic しないこと

### T3: `compute_calibration_objective` — 全 λ = 0 で J = 0

- `λ₁ = λ₂ = λ₃ = λ₄ = λ₅ = λ₆ = 0.0` のとき `J(θ) = 0.0` となること

### T4: `compute_calibration_objective` — 決定論的再現性

- 同一 metrics + 同一 weights で複数回呼び出し、`J(θ)` がビットレベルで一致すること

### T5: `compute_calibration_objective` — 極値パラメータで NaN/Inf 回避

- 全 metrics が 0.0 / 全 metrics が 1.0 / 負の metrics でも NaN や Inf を返さず `[0.0, 1.0]` 範囲に収まること

### T6: `ReciprocityCalibrationHarness` — 空パラメータセットで graceful

- 較正対象パラメータが空の設定で `run_sweep` が 0 結果を返すこと（既存 C-12 相当）

### T7: `ReciprocityCalibrationHarness` — 同一 θ で決定論的 J(θ)

- 同一 `ReciprocityLifecyclePolicy` で 2 回評価し、`J(θ)` が一致すること

### T8: `ReciprocityCalibrationObjective` — 各成分の分離検証

- 単一成分のみ重み 1.0、他を 0.0 にしたとき、`J(θ)` が該当成分値と一致することを確認
- 各成分を個別に検証

### T9: 実験ID 生成 — 形式検証

- `exp-{yyyymmdd}-{seq}` 形式に従っていること
- 親実験ID が指定された場合、出力に反映されること

### T10: 既存テストとの後方互換性

- `cargo test` で既存 1033+ テストが全て PASS すること

## 計装方法・観測対象

### 計装方法

- `src/calibration.rs` 内に `ReciprocityCalibrationObjective`, `SurvivalPair`, `ReciprocityOperationalMetrics`, `ReciprocityCalibrationHarness` を追加
- `compute_auc_benevolent_survival`: Mann-Whitney U 統計量から AUC を計算。全 survival pair を benevolence 降順にソートし、善良群の rank sum から U 統計量を求め、`U / (n1 * n2)` で AUC を算出
- 固定シード PRNG は不要（純粋関数型の決定論的計算）
- `println!` + `--nocapture` で各テストの結果（AUC 値、J(θ) 値、各成分値）を構造化出力

### 観測対象

- T1〜T2: AUC 値の期待範囲からの乖離
- T3〜T5: J(θ) の境界値挙動
- T6〜T8: ハーネス全体の整合性
- 各テストの観測値は CSV 形式で出力し、後続の較正フェーズ（M1.76-19）での参照可能とする

### 較正計画

- 本チケットでは較正パラメータの実際の sweep / 最適化は実施しない（較正ハーネスの基盤構築が目的）
- 定数群として 6 つの λ 重みデフォルト値を `constants.rs` に追加（Safety Invariant としてマーク）
- 較正ループの停止条件は M1.76-19 で定義

## Boy Scout Rule — 翻訳可能性計画

本チケットで新規作成するコードに対して以下を徹底する：

- **関数名は動詞句**: `compute_auc_benevolent_survival`, `compute_calibration_objective`
- **変数名はドメイン概念**: `benevolence_scores`, `survival_flags`, `lambda_weights` — 抽象名を避ける
- **一関数一責務**: AUC 計算、目的関数合成、ハーネス実行はそれぞれ別関数
- **ハードコード値禁止**: 6 つの λ デフォルト値と AUC 期待閾値は名前付き定数を使用
- **エラー握りつぶし禁止**: `unwrap()` 不使用、`Result` 伝播または `expect("reason")` に限定
- **既存コード**: 新規追加箇所は既存 `calibration.rs` の末尾に追加し、既存行の改変は最小限に
