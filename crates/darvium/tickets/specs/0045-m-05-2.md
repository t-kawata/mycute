# M-0.5-2: ランクドリフト頑健性シミュレーションテスト

## Summary

ランキングに対するガウスノイズ注入環境下において、上位選択アルゴリズムが致命的なクラッシュを起こさず、期待値通り最高値の候補を選択できることを観測ベースで検証する。固定シード由来のガウスノイズを各候補の類似度スコアに定常注入し、Rank drift（順位の逆転）が頻発する環境での頑健性をシミュレーションする。

## Background

- **RFC §12.2 類似度統合式**: セマンティックスコアと構造スコアを $\alpha=0.35$ でブレンドし、`evaluate_candidates()` が最良候補の `blended_score` を `EVALUATION_THRESHOLD (0.50)` と比較することで `ReuseExisting` / `PatchExisting` を決定する (`src/types.rs:4191-4205`)。
- **RFC §21.1 OQ-04/08**: GED 近似アルゴリズム選定および境界スムージング幅の妥当性評価が規範として要求されており、ランキングのノイズ耐性を観測する基盤が必要。
- **ノイズの現実的根拠**: 埋め込みモデルの近似誤差、GED 近似の計算誤差、実測値の揺らぎがランキングにノイズとして現れる。このノイズが上位選択の安定性に与える影響を定量化することで、`EVALUATION_THRESHOLD` の安全マージン設計に資する。
- **既存実装との関係**: `merge_and_deduplicate_candidates` (`src/store/mod.rs:24`) は候補統合までを行い、最終的な上位選択は `evaluate_candidates()` に委ねられている。M-0.5-1 で統合ロジックは検証済みだが、ノイズ下でのランキング安定性は未検証。
- **参照観察レポート**:
  - `tickets/context/0044-m-05-1-stage-2c/observation-20260523-100055.md` — M-0.5-1 最大値保存則・カイ二乗一様性の観測結果

## Scope

- テスト用 Fake ノイズ注入ランカーの実装 (`src/search/simulated_ranker.rs`)
- ガウスノイズ $\mathcal{N}(0, \sigma^2)$ を各候補の `semantic_score`, `structural_score` に加算する機能
- `evaluate_candidates()` 経由の上位選択が全ノイズ水準でパニック／クラッシュしないことのアサーション
- 観測テスト: 上位候補の順位変動軌道の平均二乗変位（MSD）解析
- PRNG: `StdRng::seed_from_u64(TEST_PRNG_SEED)` による完全再現可能な実験
- `rand_distr` クレートの依存追加

## Non-scope

- 実検索エンジン（HNSW 等）へのノイズ注入
- 実 DB（SQLite / LadybugDB）のランキング動作
- 複数スレッド環境下でのランクドリフト
- M-0.5-3 以降のバージョン不整合ハードゲート
- ノイズ以外の外乱要因（意図的なスコア操作等）

## Investigation

### 既存コード調査結果

1. **`evaluate_candidates`** (`src/types.rs:4191-4205`):
   - `best_score: f64` を `[0.0, 1.0]` の範囲で受け取り、`EVALUATION_THRESHOLD (0.50)` と比較する純粋関数。
   - 範囲外の値に対して `DarviumError::InvalidScore` を返す安全ガードが実装済み。
   - 返値は `SearchOutcome::ReuseExisting` または `SearchOutcome::PatchExisting` の二値。

2. **`RankedCandidate`** (`src/types.rs:138-146`):
   - `semantic_score`, `structural_score`, `blended_score` の3系統スコアを持つ。
   - ノイズ注入の操作対象は `semantic_score` と `structural_score`。`blended_score` はノイズ注入後の両スコアから RFC §12.2 の統合式で再計算する。
   - `trust_score`, `provenance`, `metadata` は本チケットの操作対象外。

3. **`constants.rs`**:
   - `EVALUATION_THRESHOLD = 0.50` — 上位選択の境界値。
   - `TEST_PRNG_SEED = 12345` — 全確率的テストの固定シード。
   - 本チケットで追加が必要な定数あり（後述「較正計画」）。

4. **テストディレクトリ**: `tests/` ディレクトリは未作成。本チケットのシミュレーションテストは `src/search/simulated_ranker.rs` 内の `#[cfg(test)] mod tests` で実施する。

5. **`src/search/` ディレクトリ**: 現状存在しない。新規作成する。

6. **`rand_distr` クレート**: 現状 `Cargo.toml` に未追加。`cargo add rand_distr` で追加する必要がある。

### 設計判断

- **ノイズ注入方式**: 各候補の `semantic_score` と `structural_score` に独立なガウスノイズ $\xi_{sem} \sim \mathcal{N}(0, \sigma^2)$, $\xi_{struct} \sim \mathcal{N}(0, \sigma^2)$ を加算。`blended_score` はノイズ注入後の値から $S_{blended} = (1-\alpha) \times clamp(S_{sem}+\xi_{sem}) + \alpha \times clamp(S_{struct}+\xi_{struct})$ で再計算（$\alpha=0.35$）。クランプ範囲は `[0.0, 1.0]`。
- **シミュレーション回数**: クラッシュ検証に 1,000 イテレーション（Darvium-Tickets 仕様準拠）、統計解析（MSD）に 10,000 イテレーション。
- **ノイズ強度水準**: $\sigma \in \{0.01, 0.02, 0.05, 0.10, 0.20\}$ の5水準。
- **評価指標**: (1) クラッシュ率 0%、(2) トップ1一致率 $P_{match}$、(3) ハースト指数 $H$。

## Test Plan

### T1: ノイズ注入関数の正常動作

ガウスノイズ $\xi \sim \mathcal{N}(0, \sigma^2)$ をスコア `0.5` に加算し、結果が `[0.0, 1.0]` の範囲にクランプされることを検証。10,000 回の試行で全結果が範囲内であることを確認。

### T2: 最小ノイズ時の上位選択安定性

ノイズ強度 $\sigma = 0.01$ で 1,000 回のシミュレーションを実行。全イテレーションで `evaluate_candidates()` がパニックせず、最高スコア候補の選択率が 95% 以上であることを検証。

### T3: 中ノイズ時の耐障害性

ノイズ強度 $\sigma = 0.05$ で 1,000 回のシミュレーションを実行。クラッシュが発生しないことのみを検証（順位逆転は許容）。

### T4: 高ノイズ時の耐障害性

ノイズ強度 $\sigma = 0.20$ で 1,000 回のシミュレーションを実行。クラッシュが発生しないことのみを検証（高ノイズ下でも安全であることの確認）。

### T5: 範囲外スコアの安全ガード

ノイズ注入後にスコアが `[0.0, 1.0]` の範囲を逸脱した場合でも、`evaluate_candidates()` が `DarviumError::InvalidScore` を返すのみでパニックしないことを検証（クランプなしのスコアを直接渡す）。

### T6: 空候補リスト

候補リストが空の場合、シミュレーションがパニックせず空の結果を返すことを検証。

### T7: スコア同値のタイブレーク

複数候補の `blended_score` が完全同値の場合でも決定論的に順位付けされることを検証。同一シードで2回実行し結果が一致することを確認。

### OTS-1: 順位変動軌道の MSD 解析

ノイズ強度 $\sigma \in \{0.01, 0.02, 0.05, 0.10, 0.20\}$ の各水準で 10,000 イテレーション実行。真の最高スコア候補の順位変動の平均二乗変位 $\langle |x(t) - x(0)|^2 \rangle$ を計算し、ハースト指数 $H$ を推定。$\sigma \le 0.05$ において $H \le 0.5$（通常拡散またはサブディフュージョン）が維持されることを観測。

### OTS-2: トップ1一致率のノイズ強度依存性

各ノイズ強度 $\sigma \in \{0.01, 0.02, 0.05, 0.10, 0.20\}$ における「真の最高スコア候補がノイズ注入後の最良選択と一致する確率」$P_{match}(\sigma)$ を測定。$\sigma \to 0$ で $P_{match} \to 1.0$ の単調減少が観測されることを確認。

## 計装方法・観測対象

### 計装方法

- テストコード: `src/search/simulated_ranker.rs` 内の `#[cfg(test)] mod tests`
- 計測プローブ: `println!` による構造化出力（`--nocapture` 経由で観測）
- PRNG: `StdRng::seed_from_u64(crate::constants::TEST_PRNG_SEED)` を使用
- ノイズ生成: `rand_distr::Normal` 分布（新規依存 `rand_distr`）
- スコア計算: RFC §12.2 の統合式 $S_{total} = (1 - \alpha) \times S_{sem} + \alpha \times S_{struct}$、$\alpha = 0.35$

### 観測対象

- **OTS-1（MSD 解析）**:
  - 観測量: 平均二乗変位 $\langle |x(t) - x(0)|^2 \rangle$、ハースト指数 $H$
  - サンプルサイズ: n = 10,000 イテレーション × 5 ノイズ水準
  - 期待: $\sigma \le 0.05$ で $H \le 0.5$（異常拡散が発生しないこと）

- **OTS-2（トップ1一致率）**:
  - 観測量: トップ1一致確率 $P_{match}(\sigma)$
  - サンプルサイズ: 1,000 イテレーション × 5 ノイズ水準
  - 期待: $\sigma = 0.01$ で $P_{match} \ge 0.95$、$\sigma$ 増加に伴い単調減少

### 較正計画

本チケットでは以下の定数を `constants.rs` に追加する：

```rust
/// ノイズ注入シミュレーションのガウスノイズ標準偏差 (Calibration Candidate)
/// Default: 0.05, 感度分析推奨範囲: 0.01-0.20
pub const NOISE_SIMULATION_SIGMA: f64 = 0.05;
```

観測結果に基づき、`EVALUATION_THRESHOLD` にノイズマージンを追加する必要性を評価する。$\sigma = 0.05$ で $P_{match} < 0.95$ の場合、閾値周辺の候補がノイズで誤判定されるリスクがあるため、閾値調整を検討する。

## Boy Scout Rule — 翻訳可能性計画

### 関数命名

```rust
pub fn simulate_rank_drift(
    candidates: Vec<RankedCandidate>,
    noise_sigma: f64,
    iterations: usize,
) -> RankDriftReport

pub fn inject_gaussian_noise(
    score: f64,
    sigma: f64,
    rng: &mut StdRng,
) -> f64

pub fn compute_mean_squared_displacement(
    rank_trajectory: &[usize],
) -> Vec<f64>
```

関数名だけで「ランクドリフトのシミュレーション」「ガウスノイズの注入」「平均二乗変位の計算」が読み取れる。

### 内部実装方針

- `simulate_rank_drift`: シミュレーション全体の制御（イテレーションループ、計測）
- `inject_gaussian_noise`: 単一スコアへのノイズ注入と `[0.0, 1.0]` クランプ（純粋関数）
- `compute_mean_squared_displacement`: 順位軌道から MSD 系列を計算（純粋関数）
- 各責務は独立したヘルパー関数に分割し、単体テスト可能にする

### 既存改善

- `src/search/` ディレクトリが存在しない場合、新規作成する（Boy Scout Rule: 関連機能の集約）
- `evaluate_candidates()` の呼び出し元で範囲外スコアのハンドリングは `InvalidScore` エラーが適切に伝播する設計であり問題なし。
