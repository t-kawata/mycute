# M1.76-KW3: 村間相互作用・知識拡散トラッキング

## Summary

DBSCAN 類似の空間クラスタリングにより村（village）の一時的割り当てを行い、村間相互作用率・村形成強度・知識拡散速度・村フローバランスの 4 指標を計装する。これらの指標を `compute_village_health_score` で合成し、J_kw の J_village 成分として供給する。村の状態を動的に追跡する `VillageInteractionObserver` を実装する。

## Background

- **RFC §15.9.4**: 村間相互作用指標 (Village Interaction Metrics) — 村は「空間的近接性に基づく自律的クラスタ」として形成され、村間の適切な相互作用と知識拡散がエコシステム全体の健全性の指標となる。cross_village_interaction_rate, village_formation_strength, knowledge_diffusion_rate, village_flow_balance の 4 指標を定義。村形成強度が強すぎる（churn < 0.05、凝集過多）も弱すぎる（churn > 0.30、流動過多）も不健全とみなす。
- **RFC §41B.3**: 村は静的なクラスではなく、アダルトの導出近傍（derived neighborhood）。`assign_village_ids` が tick ごとに返す一時的な割り当てラベルとして扱う。村の動的性質を正確に反映するため、位置変化に伴う村再編成を自然に表現する。
- **RFC §15.10.9**: Phase 3 合成生態系 — village 指標は J_kw の J_village 成分として統合される。
- **既存実装の制約**: KW1（チケット 109）で簡易版の `compute_village_health_score` が実装されているが、これは `1.0 - churn_rate` の線形近似であり、churn の適正範囲 [0.05, 0.30] に基づく二値判定ではない。KW3 で正式な実装に置き換える。

## Scope

1. **`assign_village_ids`**: `SimWorkflowState` の `position` に基づく DBSCAN 類似の空間クラスタリング関数。`VILLAGE_DISTANCE_THRESHOLD` と `VILLAGE_MIN_SIZE` を定数として使用。`SimWorkflowState` には永続フィールドを追加しない（村 ID は一時的な割り当てラベル）。
2. **`VillageInteractionMetrics` 構造体**: `tick`, `village_count`, `cross_village_interaction_rate`, `village_formation_strength`, `knowledge_diffusion_rate`, `village_flow_balance`, `mean_village_size`, `village_size_variance` の 8 フィールド。
3. **`compute_cross_village_interaction_rate`**: 村間セッション数 / 全セッション数。village_assignments から helper/requester の村ラベルが異なる場合を「村間」としてカウント。
4. **`compute_village_formation_strength`**: silhouette 類似スコア。各村の重心との距離の逆数平均。[0, 1] 正規化。
5. **`compute_knowledge_diffusion_rate`**: 村間の experience 分散の時間変化率。
6. **`compute_village_flow_balance`**: 村 churn 率。[0.05, 0.30] を適正範囲。
7. **`compute_village_health_score` 更新**: 既存実装を適正範囲チェック版に更新（`flow_balance_health` を churn 適正範囲に基づく二値判定に）。
8. **`VillageInteractionObserver`**: 各 tick で `assign_village_ids` → compute 各関数 → `compute_village_health_score` の順で実行。村割り当て履歴（前 tick assignments）を内部状態として保持。

## Test Plan

### テスト方針

全関数は純粋関数として実装される。不変条件は `assert!` / `assert_eq!` で検証する。統計的性質は観測テスト（CSV 出力）で観察する。全テストで固定シード `StdRng::seed_from_u64(12345)` を使用し、NaN/Inf フリーを常時検証する。

### TC 一覧（14 テスト）

1. **`assign_village_ids`**: 空間的に密集したワークフロー群が同一村 ID を割り当てられること
2. **`assign_village_ids`**: 孤立したワークフローが村未所属（`None`）になること
3. **`assign_village_ids`**: 全ワークフローが同一位置の場合、単一村に全員所属すること
4. **`assign_village_ids`**: 空 population で空ベクタを返すこと
5. **`compute_cross_village_interaction_rate`**: 全セッション同一村内 = 0.0 / 全セッション村間 = 1.0 / 空セッション = 0.0 / 空 assignments = 0.0
6. **`compute_village_formation_strength`**: 全ワークフローが各村の重心に密接 → 1.0 に近い / 各村内の分散大 → 0.0 に近い / 全員 None = 0.0
7. **`compute_knowledge_diffusion_rate`**: 各村の平均 experience が等しい = 0.0（拡散完了）/ 乖離大 = 正値
8. **`compute_village_flow_balance`**: churn 0 = 0.0 / 全員移動 = 1.0 / 空 assignments = 0.0
9. **空入力ガード**: 空 population / 空 assignments の全関数が panic せず 0.0 を返すこと
10. **村数 0（全員 None）graceful ハンドリング**: `cross_village_interaction_rate = 0.0`, `village_formation_strength = 0.0`, `compute_knowledge_diffusion_rate = 0.0`
11. **後方互換性**: 既存 `SimWorkflowState` 生成テストが変更不要で通過すること（フィールド追加なし）
12. **churn 過小ペナルティ**: 村形成が強すぎる（churn < 0.05）場合の `flow_balance_health = 0.0` 確認
13. **churn 過大ペナルティ**: 村形成が弱すぎる（churn > 0.30）場合の `flow_balance_health = 0.0` 確認
14. **churn 適正範囲**: churn ∈ [0.05, 0.30] で `flow_balance_health = 1.0` 確認

### 境界値テスト

| テスト観点 | 入力 | 期待値 |
|-----------|------|--------|
| churn 下限ジャスト | churn = 0.05 | flow_balance_health = 1.0 |
| churn 下限未満 | churn = 0.0499 | flow_balance_health = 0.0 |
| churn 上限ジャスト | churn = 0.30 | flow_balance_health = 1.0 |
| churn 上限超過 | churn = 0.3001 | flow_balance_health = 0.0 |

## Boy Scout Rule — 翻訳可能性計画

### 対象: `compute_village_health_score`（kind_world.rs L135-L144）

現在の実装は `flow_balance_health = 1.0 - churn_rate` の線形近似であり、RFC の適正範囲 [KW_VILLAGE_CHURN_LOWER, KW_VILLAGE_CHURN_UPPER] に基づく二値判定ではない。KW3 で以下のように修正する:

```rust
pub fn compute_village_health_score(
    formation_score: f64,
    churn_rate: f64,
    cross_rate: f64,
    diffusion_rate: f64,
) -> f64 {
    // flow_balance_health: churn が適正範囲内なら健全、範囲外なら不健全
    let flow_balance_health = if churn_rate >= VILLAGE_CHURN_LOWER
        && churn_rate <= VILLAGE_CHURN_UPPER
    {
        1.0
    } else {
        0.0
    };
    let raw = (formation_score + flow_balance_health + cross_rate + diffusion_rate) / 4.0;
    raw.clamp(0.0, 1.0)
}
```

## Notes

- **VillageInteractionObserver の設計**: KW2 の `EcosystemGrowthObserver`（kind_world.rs L537-L587）と同様の API 設計（`observe()` + `print_csv()`）を踏襲する。
- **assign_village_ids の返り値**: `Vec<Option<usize>>`。`None` = 村未所属。返り値は tick ごとに新規計算され、永続化しない。
- **村形成強度の幾何計算**: 各村の重心は所属ワークフローの position 平均。silhouette 類似スコア = 各村の (1.0 - 重心からの平均距離 / 最大可能距離) の平均。[0, 1] 正規化には `clamp(0.0, 1.0)` を使用。
- **知識拡散率**: current_assignments と previous_assignments の 2 時点を比較。各村の平均 experience の標本標準偏差の変化率。
