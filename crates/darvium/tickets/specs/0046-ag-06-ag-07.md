# 埋め込みモデル・テンプレートバージョン不整合（AG-06 / AG-07）ハードゲートの全弾ブロックテスト

## Summary

埋め込みベクトル（`task_embedding` / `workflow_design_embedding`）の生成に使用されたモデルバージョン・テンプレートバージョンがクエリと候補の間で不一致の場合、Stage 1 のハードゲート（AG-06 / AG-07）で即時排除されることを検証する。クエリ側が宣言する期待バージョンと候補側の `EmbeddingChannelVersion` を突合し、不一致なら ApplicabilityRejected エラーを返す ApplicabilityGate を実装し、全弾ブロック（偽陽性率 0.00）を $10^5$ 回走査で統計的に証明する。

## Background

Darvium RFC §11.1 では、検索の Stage 1 として AG-01〜AG-07 のハードゲートを AND 検査することが必須とされている。AG-06 は semantic channel（`task_embedding`）のモデルバージョン互換性、AG-07 は structural proxy channel（`workflow_design_embedding`）のモデル/テンプレートバージョン互換性を検査する：

- **AG-06**: `task_embedding` の model version が query / candidate 間で互換であること、または semantic score を無効化可能であること → 不整合なら REJECT
- **AG-07**: `workflow_design_embedding` の model / template version が query / candidate 間で互換であること、または structural score を無効化可能であること → 不整合なら REJECT

これらのハードゲートは **絶対停止条件** であり、ピクセル単位の完全一致ベースで判定されなければならない（化学ポテンシャル相当の臨界距離 $E_c = +1$ ビット、逆温度 $\beta \to \infty$ の階段関数マッピング）。1 ビットでも異なるバージョン文字列を持つ候補は後段ロジック（Stage 2 以降）に一切進入してはならない。

### 前提となる先行チケット

- **チケット #4 (M-2-1.7 EmbeddingProvider 抽象トレイト)** — `embed_dimension()` による次元数取得は本チケットのバージョン不整合検出の前提ではないが、トレイト階層としては本 ApplicabilityGate が EmbeddingProvider の提供する `EmbeddingChannelVersion` 情報を利用する。
- **チケット #44 (M-0.5-1 Stage 2c デュアルストア候補統合・重複排除器)** — ApplicabilityGate がフィルタリングした候補のみが後段の統合・重複排除に到達する。
- **チケット #45 (M-0.5-2 ランクドリフト頑健性シミュレーションテスト)** — 本実装でランキングに到達する候補の品質が担保される。

### 参照観察レポート

- `tickets/context/0045-m-05-2/observation-20260523-101846.md` — M-0.5-2 ランクドリフト頑健性評価。全ノイズ水準で H ≤ 0.5（異常拡散なし）。simulated_ranker のテスト基盤は本チケットでも再利用可能。

## Scope

1. **`EmbeddingChannelVersion` 構造体の実装**（RFC §11 準拠）:
   - `model_version: String` — 埋め込みモデルのバージョン識別子
   - `template_version: Option<String>` — テンプレートバージョン（structural channel のみ使用）
   - `EmbeddingVersions` ラッパー構造体（`task: EmbeddingChannelVersion`, `design: EmbeddingChannelVersion`）

2. **AG-06 / AG-07 ハードゲート判定関数の実装**:
   - `check_ag06(query_version: &EmbeddingChannelVersion, candidate_version: &EmbeddingChannelVersion) -> Result<(), DarviumError>` — semantic channel 不整合検出
   - `check_ag07(query_version: &EmbeddingChannelVersion, candidate_version: &EmbeddingChannelVersion) -> Result<(), DarviumError>` — structural channel 不整合検出
   - バージョン不一致時は `DarviumError::ApplicabilityRejected { gate: "AG-06".to_string(), reason: ... }` を返す
   - バージョン一致時は `Ok(())` を返す

3. **`QueryRepresentation` へのバージョン情報拡張**:
   - 既存の `design_template_version: String` に加え、`task_embedding_version: EmbeddingChannelVersion` と `design_embedding_version: EmbeddingChannelVersion` フィールドを追加
   - 後方互換性を維持（既存コンストラクタは追加フィールドにデフォルト値を設定）
   - RFC の `EmbeddingVersions` ラッパーは内部実装の便宜として併用

4. **テストコード**（全弾ブロック検証）:
   - `tests/m_minus0_5/ag_06_07_test.rs` テストファイル
   - 確率的バージョン書き換えループ（"v2.0-final" → "v1.8-legacy" 等）
   - $10^4$ 回走査での偽陽性率 0.00 確認（$10^5$ は実用的に $10^4$ で十分な統計的有意性）
   - 計装プローブによる $P_{pass}(E)$ の階段関数マッピング実測

## Non-scope

## Investigation

### 調査日時: 2026-05-23

#### 物理的証拠

1. **RFC §11.1 ハードゲート一覧** (`Darvium-RFC-0001-Unified-v2.3-final.md:1226-1238`):
   - AG-06 / AG-07 の条件と拒否理由が明文化されている。
   - 両ゲートとも AND 検査の一部であり、1 つでも失敗したら即時拒否。

2. **`EmbeddingChannelVersion` の RFC 定義**（同:606-609）:
   - `model_version: String`, `template_version: Option<String>` — ソースコード上に未実装。

3. **`EmbeddingVersions` の RFC 定義**（同:623-626）:
   - `task: EmbeddingChannelVersion`, `design: EmbeddingChannelVersion` — 未実装。

4. **`QueryRepresentation` の現状** (`src/types.rs:72-83`):
   - `design_template_version: String` は既存。しかし `EmbeddingChannelVersion` 構造体は未使用。
   - `task_embedding: Vec<f32>` と `query_design_embedding: Vec<f32>` は既存だが、対応するバージョン管理構造体がない。

5. **エラー型の既存実装** (`src/error.rs`):
   - `DarviumError::ApplicabilityRejected { gate: String, reason: String }` (62-63行) — **実装済み**。本チケットで直接使用。
   - `DarviumError::EmbeddingVersionMismatch(String)` (108行) — **実装済み**。直接使用はしないが将来の拡張に備えて存在を確認。
   - `DarviumError::EmbeddingDimensionMismatch { expected, actual }` (35-36行) — **実装済み**。本チケットでは不使用。

6. **`Provenance` 構造体** (`src/types.rs:4220`):
   - `pub struct Provenance;` — 空構造体として存在。RFC の `DesignTextProvenance` とは異なる。本チケットでは直接使用しない。

7. **`KnowledgeApplicability` 構造体** (`src/types.rs:4257`):
   - `pub struct KnowledgeApplicability;` — 空構造体。v1.8 の Knowledge Applicability Extension 用。本チケットでは不使用。

8. **`DesignTextGeneratorKind`** — RFC に定義あり（618-621行）がソースコードに未実装。本チケットでは不要。

#### 結論

Applicability Gate のコアデータ型（`EmbeddingChannelVersion`, `EmbeddingVersions`）および AG-06 / AG-07 の判定ロジックは一切実装されていない。`DarviumError::ApplicabilityRejected` のエラー型のみ利用可能である。

本チケットでは以下を新規実装する：
- `src/search/applicability.rs` モジュール（新規）
  - `EmbeddingChannelVersion` 構造体
  - `EmbeddingVersions` 構造体
  - `check_ag06()`, `check_ag07()` 自由関数
- `src/types.rs` の `QueryRepresentation` にバージョンフィールドを追加
- `src/search/mod.rs` に `applicability` モジュールを公開
- `src/constants.rs` にデフォルトバージョン定数を追加
- `tests/m_minus0_5/ag_06_07_test.rs` テストファイル（新規 mkdir）

## 計装方法・観測対象

### 計装方法

- **OTS-1 〜 OTS-3**: テストコード内で `println!` による構造化テキスト出力を `--nocapture` 経由で標準出力に書き出す。
- **固定シード PRNG**: `StdRng::seed_from_u64(12345)` を使用し、全走査の完全再現性を保証。
- **出力形式**:
  ```
  === OTS-1: False Positive Rate (AG-06) ===
  iterations=10000, mismatch_version="v1.8-legacy"
    passed=0, rejected=10000, pass_rate=0.0000

  === OTS-1: False Positive Rate (AG-07) ===
  iterations=10000, mismatch_version="v1.8-legacy"
    passed=0, rejected=10000, pass_rate=0.0000
  ```

### 観測対象

- ハミング距離 $E$ に対するゲート通過確率 $P_{pass}(E)$ の分布特性
- $E = 0$（完全一致） → $P_{pass} = 1.00$（assert で検証）
- $E \ge 1$（1ビット以上の不一致） → $P_{pass} = 0.00$（assert で検証。統計的には $10^4$ 回走査で 0 件の偽陽性）
- バージョン文字列のピクセル単位完全一致比較の厳格性（大文字小文字・空白・部分一致のいずれも不一致と判定されること）

### 較正計画

本チケットでは較正すべき定数は存在しない（バージョン比較は定性的な完全一致判定であり、連続値パラメータを伴わない）。ただし、以下の定数を新規追加する：

| 定数 | 値 | 分類 | 説明 |
|------|-----|------|------|
| `AG_HARD_GATE_DEFAULT_MODEL_VERSION` | `"v2.0-final"` | Environment Policy Knob | デフォルトの埋め込みモデルバージョン。環境（テスト/ステージング/本番）に応じて変更可能。 |
| `AG_HARD_GATE_DEFAULT_TEMPLATE_VERSION` | `"v2.0-final"` | Environment Policy Knob | デフォルトのテンプレートバージョン。同上。 |

目的関数 J(θ) は本チケットでは定義しない（較正対象パラメータを欠くため）。

## Boy Scout Rule — 翻訳可能性計画

本チケットで新規作成する `src/search/applicability.rs` および拡張する `src/types.rs` / `src/error.rs` / `src/constants.rs` において、以下の翻訳可能性を確保する：

1. **関数名は動詞句**:
   - `check_ag06()` — 「AG-06 を検査する」と翻訳可能
   - `check_ag07()` — 「AG-07 を検査する」と翻訳可能

2. **構造体名はドメイン概念**:
   - `EmbeddingChannelVersion` — 「埋め込みチャネルバージョン」
   - `EmbeddingVersions` — 「埋め込みバージョン群」

3. **一関数一責務**: `check_ag06` は semantic channel のバージョン不整合検出のみ、`check_ag07` は structural channel のバージョン不整合検出のみを責務とする。

4. **エラー握りつぶし禁止**: バージョン不整合を握りつぶさず、必ず `ApplicabilityRejected` エラーを上位に伝播する。

5. **既存コード改善**: `src/types.rs` の `QueryRepresentation` にバージョンフィールドを追加する際、(a) 新フィールドに適切な rustdoc コメントを付与する、(b) 既存の `design_template_version` は後方互換性のために維持するが、同じく rustdoc を改善する。
