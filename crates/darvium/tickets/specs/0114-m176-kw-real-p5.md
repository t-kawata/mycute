## Scope

1. **classify_maturity 正式化**: `village.rs` に既存の 3 軸判定をそのまま流用。`enum Maturity { Child, Adult }` として再エクスポート（既存の `WorkflowMaturity` と同一。型エイリアスまたは統一を検討）。
2. **`MIN_SURVIVAL_EXPERIENCE` 定数確認**: 既存の `constants.rs:328` (`= 5`) をそのまま使用。RFC §41B.3 デフォルトは 5 であり、Tickets spec の「default: 3」は誤記であった。**5 が正しい。**
3. **`LifecycleScore` 構造体**: `kind_world.rs` または新規ファイル `src/lifecycle.rs` に正式定義。RFC §15.3 に従い freshness, success, trust, usage, reputation の幾何平均として計算。
   ```rust
   pub struct LifecycleScore {
       pub freshness: f64,
       pub success: f64,
       pub trust: f64,
       pub usage: f64,
       pub reputation: f64,
   }
   ```
   幾何平均: `L(G) = (freshness * success * trust * usage * reputation) ^ (1/5)`
4. **GC 5 状態機械完全実装**: `event.rs` の `GcEvent` (現在 3 variant) に `Protected`, `Active` を追加。状態遷移関数 `fn transition_gc_state(current: GcEvent, hazard: f64) -> GcEvent`。
   - 遷移順序: Protected → Active (経験値達成) → SoftDeleted (hazard 超過) → HardDeleteCandidate (猶予経過) → Tombstoned (完全削除)
   - Protected 状態の個人は hazard が高くても Tombstoned に遷移しない
5. **信頼継承**: `trust.rs` に `fn inherit_trust(parent: &TrustProfile, child: &mut TrustProfile, decay: f64)`。各成分 (operational/semantic/temporal) に減衰係数 `decay` (default: `TRUST_INHERIT_DECAY = 0.70`) を乗算して子に継承。
6. **評判継承**: `trust.rs` に `fn inherit_reputation(parent: &ReputationProfile, child: &mut ReputationProfile, decay: f64)`。同様に減衰継承。
7. **`ExperienceNormalization` (F-5)**: `reciprocity.rs` に `fn compute_experience_normalization(experience_count: u64) -> f64`。非線形正規化（初期の急成長、成熟後の飽和）。LifecycleScore の trust 成分計算に使用。
   - 式: `1.0 - exp(-experience_count / SCALING_FACTOR)` または同様のシグモイド的関数
8. **二軸時間管理 + `BlendedFreshness`**: `clock/mod.rs` に `fn compute_blended_freshness(last_access: Option<Instant>, virtual_ticks: u64, human_weight: f64) -> f64`。
   - `F_time = w_H * F_H + (1 - w_H) * F_V`
   - `F_H`: 人間時間による減衰 (UTC 経過時間)
   - `F_V`: 仮想時刻による減衰 (virtual tick)
   - シミュレーション内では ManualClock の tick 数を virtual tick として使用
9. **既存コードの流用**: `compute_gc_hazard` (reciprocity.rs:286)、`compute_child_protection` (reciprocity.rs:362)、`compute_survival_probability` (reciprocity.rs:329) は既存のものをそのまま使用。

## Investigation

### 物理的証拠一覧

#### classify_maturity — 既に実装済み
- **場所**: `src/village.rs:80-95`
- **シグネチャ**: `pub fn classify_maturity(experience_count: u64, trust_composite: f64, reputation_finalscore: f64) -> WorkflowMaturity`
- **判定ロジック**: (1) `experience_count < MIN_SURVIVAL_EXPERIENCE` → Child, (2) 全軸閾値以上なら Adult, (3) それ以外 Child
- **閾値**: `MIN_SURVIVAL_EXPERIENCE=5` (constants.rs:328), `E_ADULT_THRESHOLD=20` (constants.rs:333), `T_ADULT_THRESHOLD=0.3` (constants.rs:337), `R_ADULT_THRESHOLD=0.3` (constants.rs:341)
- **テスト**: T-1〜T-7 既存 (village.rs:512-639)
- **注意**: Tickets spec の「`experience_count` に基づく」は不正確。実際は 3 軸判定（経験値・信頼・評判）。plan 策定時に spec を修正すること。

#### LifecycleScore — inline 実装のみ
- **場所**: `src/simulation.rs:729-731`
- **内容**: `let lifecycle_score = (wf.experience as f64 / (E_ADULT_THRESHOLD * 3) as f64).min(1.0) as f32;`
- **問題**: RFC §15.3 の定義 (freshness/success/trust/usage/reputation の幾何平均) と完全に異なる。単なる経験値正規化。
- **RFC 参照**: §4A.7 機構 39, §15.9.3 mean_lifecycle_score

#### GcEvent — 3/5 状態のみ
- **場所**: `src/event.rs:279-288`
- **現在**: `enum GcEvent { SoftDeleted, HardDeleteCandidate, Tombstoned }` の 3 状態
- **Protected の使われ方**: `EventVisibility::Protected` (event.rs:2700, 2765, 3716) として別の enum で使用 — GcEvent とは無関係
- **Active の使われ方**: `SubscriberStatus::Active` (event_channel.rs:243) として別の enum で使用 — GcEvent とは無関係
- **必要**: GcEvent に `Protected`, `Active` を追加し、5 状態遷移関数を実装

#### inherit_trust — 未実装
- **TrustProfile**: `src/trust.rs:29-32` に operational/semantic/temporal + composite の定義あり（test stub 内）
- **継承関数**: 存在しない。新規実装が必要。
- **TRUST_INHERIT_DECAY**: `constants.rs:11` — `= 0.70`

#### inherit_reputation — 未実装
- **ReputationProfile**: M1.76-2 で実装済み（reciprocity.rs 内）
- **継承関数**: 存在しない。新規実装が必要。

#### compute_experience_normalization — 未実装
- **F-5 機構**: RFC §4A.5 機構 35 に記載
- **全く存在しない**: どこにも実装なし。

#### BlendedFreshness — 未実装

## 計装方法・観測対象

### 計装方法
- **テストコード**: `src/simulation.rs` の `mod tests` に `test_p5_lifecycle_instrumentation` を追加
- **出力形式**:
  - CSV: `tick, node_id, lifecycle_score, gc_state, maturity, is_protected, experience_count`
  - JSON: 10 tick ごとに全人口の経験値分布ヒストグラム（bin width=5、範囲 0〜100）
- **固定シード**: `StdRng::seed_from_u64(12345)` を使用。再現性保証。
- **測定プローブ**: println! + `--nocapture` 経由

### 観測対象
- **統計量**:
  - LifecycleScore の平均・分散・最小・最大（毎 tick）
  - GC 状態分布（各 tick における Protected/Active/SoftDeleted/HardDeleteCandidate/Tombstoned の割合）
  - 経験値分布の形状（非線形正規化の効果確認）
  - 信頼継承減衰の実効値（spawn イベントごとの J_trust 寄与）
- **サンプルサイズ**: n=50 population × 20 ticks = 1,000 観測点（drift 検出に十分）
- **期待現象**:
  - LifecycleScore は平均的に時間とともに増加（経験値蓄積による）
  - Protected 状態の個人は hazard が高くても Tombstoned に遷移しない
  - BlendedFreshness はアクセス頻度が低い個人ほど急速に低下

### 較正計画
- **調整定数**: `TRUST_INHERIT_DECAY` (0.70) — 信頼継承の減衰率。後続 KW4 で sweep 対象。
- **目的関数 J(θ)**: 本チケットでは後続チケット (P6/KW4) の目的関数を意識した純粋な機構実装に留める。較正ループは本チケットの範囲外。
- **停止条件**: 本チケットの較正は行わない。全テスト PASS をもって完了とする。
