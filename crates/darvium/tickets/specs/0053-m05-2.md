# M0.5-2: 確率的パッチ操作インジェクションによるバリデータ耐久テスト

## Summary

GraphPatch の `PatchOperation` 型と `PatchError` 型を実装し、`apply_patch_atomic` のフェーズ2（操作適用）・フェーズ3（事後バリデーション）を構築する。固定シード PRNG 駆動でランダムなエッジ挿入（`AddEdge`）を健全な DAG に対して大量注入し、`petgraph::algo::toposort` による巡回ループ検出が 100% の完全性を持つことを統計的に証明する。サンプル数 n=10,000、見落とし確率の上側 99% 信頼限界が p_miss < 4.6×10⁻⁴ 以下であることの数学的確認をゴールとする。

## Background

RFC §14.2 は `validate_patch_result` において DAG 検証・変数スコープ検証・SubWorkflow 参照検証の3段階を義務付けている。特に DAG 健全性は P-01（WorkflowGraph は DAG でなければならない）および v2.3 の「create/update 時 + compile/execute 前の二重防御」要請を満たすために、patch-time validation として局所的に実施される。

現状、`GraphPatch` は空のスタブ構造体であり、`PatchOperation` 列挙型・`PatchError` 列挙型・`validate_patch_result` 関数・`apply_patch_atomic` 関数は未実装である。M0.5-2 では、これらの型と関数を Fake レベルの実装として整備し、プロパティベーステストによってバリデータの健全性を検証する。

### 既存コードの状態

- `WorkflowGraph` = `DiGraph<WorkflowNode, EdgeMeta>`（petgraph, src/types.rs:89）
- `NodeId = usize`（src/types.rs:11）
- `GraphPatch` = 空のスタブ（src/types.rs:4370）
- `PatchOperation` 未定義（RFC §12.1 仕様あり）
- `PatchError` 未定義（RFC §12.6 仕様あり）
- `validate_patch_result` 未実装（RFC §14.2 仕様あり）
- `apply_patch_atomic` 未実装（RFC §14.2 仕様あり）
- `PatchConfidence` / `PatchConfidence::compute` 未実装（RFC §12.3 仕様あり）
- パッチ関連定数（PATCH_CONFIDENCE_THRESHOLD 等）未定義
- petgraph は Cargo.toml に依存あり（WorkflowGraph で使用）

### M0.5-1 との連続性

M0.5-1（ScriptedFakeLlmClient）の観察レポート（0052-m05-1-fake-llm）より：
- ScriptedFakeLlmClient を直接利用することで、パッチ生成における LLM 不正出力の影響テストが可能
- WrongKeyName, ExtraField, TypeMismatch は JSON パースを通るため、スキーマバリデーションレイヤーで活用可能（M0.5-2 の AddNode/ReplaceNode 操作におけるノードデータ不正注入として流用可能）
- RawError モードがエラー伝播経路を正しくテストできることが確認された

## Scope

1. `PatchOperation` 列挙型の定義（RFC §12.1 準拠: AddNode, RemoveNode, ReplaceNode, AddEdge, RemoveEdge, UpdatePrompt, UpdateInputMapping）
2. `PatchError` 列挙型の定義（RFC §12.6 準拠: LowConfidence, CycleCreated, VarScopeViolation, SubworkflowRefMissing, SourceGraphNotFound, NodeNotFound）
3. `GraphPatch` 構造体の具象化（operations, patch_confidence フィールドの追加）
4. `PatchConfidence` 構造体と `compute` メソッドの実装（RFC §12.3 準拠）
5. `apply_operation` 関数の実装（各 PatchOperation variant に対する具体的なグラフ操作）
6. `apply_patch_atomic` 関数の実装（clone → apply → validate → swap の4フェーズ、RFC §12.4 準拠）
7. `validate_patch_result` 関数の実装（DAG 検証 + 変数スコープ検証 + SubWorkflow 参照検証、RFC §14.2 準拠）
8. `validate_var_scope` 関数の実装（DataFlow.from_var が送信ノードの output_var と一致することの検査、V-03）
9. `validate_subworkflow_refs` 関数の実装（SubWorkflow ノードの参照先が存在することの検査）
10. プロパティベーステスト: 固定シード PRNG でランダム `AddEdge` を健全 DAG に注入し、巡回ループ検出の完全性を検証（n=10,000）
11. パッチ関連定数の追加（constants.rs: PATCH_CONFIDENCE_THRESHOLD, PATCH_CONFIDENCE_PRIOR, PATCH_SELF_CONF_SWITCH_THRESHOLD 等）

- ConfidenceVector 集約との統合（M0-3 で別途実装済み）

## Investigation

### ソースコード調査結果

**src/types.rs:**
- `NodeId = usize` (L11), `WorkflowGraphId = String` (L17)
- `WorkflowGraph = DiGraph<WorkflowNode, EdgeMeta>` (L89) — petgraph の有向グラフ
- `EdgeMeta` 列挙型 (L72-86): DependsOn, DataFlow{from_var, to_var}, Conditional, FanOut, Collect
- `WorkflowNode` 列挙型 (L51-67): AgentStep{agent, prompt_template, inputs, output_var}, SubWorkflow{workflow_id, input_mapping, output_var}, Placeholder
- `GraphPatch` は空のスタブ (L4369-4370)
- `WorkflowPatch` も空のスタブ (L4364-4365)
- `ConfidenceVector` (L4382-4428) は実装済み（aggregate, perturb メソッド完備）
- `CompositionPlan` は実装済み（L4432-）
- `WorkflowPatchId` は未定義

**src/constants.rs:**
- `MAX_PATCH_OPS: usize = 1_000` (Safety Invariant, L48) — パッチ操作数上限は定義済み
- `MAX_GRAPH_NODES: usize = 10_000` (Safety Invariant, L42)
- `SELF_CONF_DISCOUNT: f64 = 0.85` (L27)
- しかし PATCH_CONFIDENCE_THRESHOLD, PATCH_CONFIDENCE_PRIOR 等のパッチ信頼度定数は未定義
- 重み定数（PATCH_CONFIDENCE_WS, PATCH_CONFIDENCE_WV, PATCH_CONFIDENCE_WS_LOW, PATCH_CONFIDENCE_WV_HIGH）未定義

**Darvium-RFC-0001-Unified-v2.3-final.md の仕様:**
- §12.1: PatchOperation 列挙型（7 variant） + GraphPatch 構造体
- §12.2: GraphPatchGenerator + PatchGenerationContext（本チケットではスコープ外）
- §12.3: PatchConfidence 構造体 + compute メソッド（cₛ_adjusted^wₛ × cᵥ^wᵥ × cₕ^wₕ 幾何平均）
- §12.4: apply_patch_atomic の4フェーズ + validate_patch_result（toposort + var_scope + subworkflow_refs）
- §12.6: PatchError 列挙型（6 variant）

**petgraph 依存:**
- WorkflowGraph ですでに `petgraph::graph::DiGraph` を使用
- `petgraph::algo::toposort` が利用可能
- `NodeIndex` は petgraph 内部型。現コードでは `NodeId = usize` でラップしているため、usize ↔ NodeIndex の変換が必要

### M0.5-1 観察レポートの知見

- 参照: tickets/context/0052-m05-1-fake-llm/observation-20260523-145926.md
- ScriptedFakeLlmClient の WrongKeyName / ExtraField / TypeMismatch は JSON パースを通るため、パッチ注入テストにおける「意味的に不正なノードデータ」の生成源として利用可能
- RawError モードはエラー伝播経路のテストに使用可能

### 設計上の判断点

1. `validate_patch_result` の変数スコープ検証（V-03）は、DataFlow.from_var が送信ノードの output_var と一致するかを検査する前方走査。現在の WorkflowNode には output_var が AgentStep/SubWorkflow に存在するため、これらを対象とする。
2. petgraph の `NodeIndex`（u32）と `NodeId`（usize）の変換には `NodeIndex::new(index as u32)` を使用。
3. `GraphPatch` は clone 可能である必要がある（apply_patch_atomic のフェーズ1で gold を clone）。

## Test Plan

### 静的検証（不変条件テスト）

1. **PatchOperation デバッグ特性テスト**: 全 variant が Debug, Clone, PartialEq を実装していることを確認
2. **PatchError デバッグ特性テスト**: 全 variant が Debug, thiserror::Error, Display を実装していることを確認
3. **GraphPatch 構築テスト**: 最小構成（空の operations Vec）で GraphPatch が構築可能であることを確認
4. **PatchConfidence 構築テスト**: `PatchConfidence::compute` で value が cₛ_adjusted^wₛ × cᵥ^wᵥ × cₕ^wₕ として正しく計算されることを確認
5. **PatchConfidence 低自信切り替えテスト**: cₛ < 0.50 時に ws/wv が動的に切り替わることを確認

### 操作適用テスト（apply_operation）

6. **AddNode 正常系**: 空グラフに `AgentStep` ノードを追加できることを確認
7. **AddEdge 正常系**: 既存ノード間に `DataFlow` エッジを追加できることを確認
8. **AddEdge ノード不在エラー**: 存在しないノード ID を指定した場合に `NodeNotFound` が返ることを確認
9. **RemoveNode 正常系**: 既存ノードを削除できることを確認
10. **RemoveNode ノード不在エラー**: 存在しないノード ID を指定した場合に `NodeNotFound` が返ることを確認
11. **ReplaceNode 正常系**: 既存ノードを置換できることを確認
12. **ReplaceNode ノード不在エラー**: 存在しないノード ID を指定した場合に `NodeNotFound` が返ることを確認
13. **RemoveEdge 正常系**: 既存エッジを削除できることを確認
14. **RemoveEdge エッジ不在エラー**: 存在しないエッジを削除しようとした場合の挙動を確認
15. **RemoveEdge ノード不在エラー**: 存在しないノード ID を指定した場合に `NodeNotFound` が返ることを確認
16. **UpdatePrompt 正常系**: AgentStep ノードの prompt_template を更新できることを確認
17. **UpdatePrompt 非対応ノード**: Placeholder ノードに対して UpdatePrompt を実行した場合の挙動を確認（エラーまたは無視）
18. **UpdateInputMapping 正常系**: SubWorkflow ノードの input_mapping を更新できることを確認

### apply_patch_atomic テスト

19. **apply_patch_atomic 正常系**: 有効なパッチ操作列（AddNode + AddEdge）でグラフを更新できることを確認
20. **apply_patch_atomic アトミック性テスト**: 途中で失敗した操作（存在しないノードへの AddEdge）が gold グラフを変更しないことを確認（フェーズ2のアトミック性）
21. **apply_patch_atomic バリデーション失敗テスト**: サイクルを作成するパッチが `CycleCreated` で拒否されることを確認（フェーズ3のバリデーション）

### validate_patch_result テスト

22. **validate_patch_result DAG正常系**: 正常な DAG が検証をパスすることを確認
23. **validate_patch_result サイクル検出**: `petgraph::algo::toposort` がサイクルを検出し `CycleCreated` が返ることを確認
24. **validate_patch_result 変数スコープ正常系**: 全 DataFlow の from_var が送信元ノードの output_var と一致する場合に検証をパスすることを確認
25. **validate_patch_result 変数スコープ違反**: from_var が送信元ノードの output_var と一致しない場合に `VarScopeViolation` が返ることを確認
26. **validate_patch_result SubWorkflow 参照正常系**: 全 SubWorkflow ノードの参照先が存在する場合に検証をパスすることを確認（本チケットでは参照先の実在チェックはスキップまたは常に OK）

### プロパティベース耐久テスト（観測テスト）

27. **OTS-C1: ランダム AddEdge インジェクション（n=10,000）**:
    - 健全な DAG（ノード数 8〜512、エッジ密度 0.1〜0.3）を構築
    - 固定シード PRNG（StdRng::seed_from_u64(12345)）を使用
    - 各イテレーションでランダムなバックエッジ（逆方向エッジ、ノードペア (from, to) where from > to）を 1〜5 本挿入
    - `apply_patch_atomic` で全操作を適用
    - 観測: `CycleCreated` エラーの検出率 = 100%（assertion）
    - 観測: バリデータ通過後のグラフが真に DAG であることを toposort で再確認
    - 統計的評価: 見落とし確率の上側 99% 信頼限界が p_miss < 4.6e-4 以下

28. **OTS-C2: ランダム全操作インジェクション（n=1,000）**:
    - 健全な DAG に対し、AddNode, RemoveNode, ReplaceNode, AddEdge, RemoveEdge をランダムに組み合わせた操作列（長さ 1〜10）を注入
    - 観測: すべての操作がパニックを起こさず、エラー時は `PatchError` として安全に捕捉されることを確認
    - 観測: バリデータ通過時のグラフが常に DAG であることを toposort で確認
    - 観測: 途中失敗時の gold グラフが不変であることを確認

### 観測のための定量的試験

全ての観測テストは `tests/m_minus0_5/` に配置し、`cargo test --test m_minus0_5 -- --nocapture` で実行可能とする。
適宜 `tests/m0_5/` にも配置し、`cargo test --test m0_5 -- --nocapture` でも実行可能とする（M0.5 の観測テスト群として統合するため）。

**ots_cycle_detection_completeness**:
- n=10,000 のランダムバックエッジ注入
- `petgraph::algo::toposort` がサイクルを検出した回数を計数
- 検出率 = 検出回数 / 注入回数
- 検出率が 1.0 であることを assertion で確認
- 出力形式: CSV（試行番号, ノード数, 注入エッジ数, 検出結果, グラフスペクトル半径ρ）

**ots_noise_injection_safety**:
- n=1,000 のランダム全操作注入
- パニック発生回数 = 0 であることを確認
- バリデータ通過グラフの DAG 再確認パス率 = 100% であることを確認

## 計装方法・観測対象

### 計装方法

- テストコード: `tests/m_minus0_5/m05_2.rs`（M0.5-2 専用のプロパティベース観測テスト）
- 計測プローブ: `println!` + `cargo test -- --nocapture` で CSV 形式の生データを標準出力
- PRNG: `StdRng::seed_from_u64(12345)`（固定シード、完全再現保証）
- グラフ構築: テスト内で `WorkflowGraph`（`DiGraph<WorkflowNode, EdgeMeta>`）を生成
  - ノードは `WorkflowNode::Placeholder` で埋める（操作対象としてのノード識別のみ必要）
  - エッジは `EdgeMeta::DependsOn`（構造検証の最小単位として十分）

### 観測対象

**OTS-C1 観測量**:
- 全試行における検出率（= サイクル検出回数 / バックエッジ注入試行数）
- 見落とし確率の上側 99% 信頼限界（二項分布に基づく Clopper-Pearson 区間）
- バリデータ通過グラフの DAG 再確認パス率
- スペクトル半径 ρ > 0 時のグラフ隣接行列の最大固有値（参考計測）
- n=10,000（ドリフト検出の要件 n>=1,000 を満たし、さらに分布同定の要件 n>=10,000 を満たす）

**OTS-C2 観測量**:
- パニック発生率（期待値: 0.0）
- PatchError 捕捉率（期待値: 1.0 — エラーは全て PatchError として捕捉）
- バリデータ通過グラフの DAG 再確認パス率（期待値: 1.0）
- n=1,000（操作列の組み合わせ爆発を考慮した現実的な試行数）

### 較正計画

本チケットはバリデータの完全性検証が主目的であり、較正ループの対象定数は少ない。ただし、テスト設計上必要な定数を追加する：

- `PATCH_CONFIDENCE_THRESHOLD: f64 = 0.75` (Safety Invariant, RFC §14.2 指定値)
- `PATCH_CONFIDENCE_PRIOR: f64 = 0.50` (Safety Invariant, RFC §14.2 指定値)
- `PATCH_SELF_CONF_SWITCH_THRESHOLD: f64 = 0.50` (Safety Invariant, RFC §12.3 指定値)
- `PATCH_CONFIDENCE_WS: f32 = 0.30` (Safety Invariant, RFC §12.3)
- `PATCH_CONFIDENCE_WV: f32 = 0.40` (Safety Invariant, RFC §12.3)
- `PATCH_CONFIDENCE_WS_LOW: f32 = 0.20` (Calibration Candidate, RFC §12.3 動的切り替え)
- `PATCH_CONFIDENCE_WV_HIGH: f32 = 0.50` (Calibration Candidate, RFC §12.3 動的切り替え)
- `VALIDATOR_VAR_SCOPE_PENALTY: f64 = 0.15` (Safety Invariant, RFC §14.2 減算規則)

目的関数 J(θ): 本チケットでは適用しない（較正対象の定数は全て RFC 指定済み Safety Invariant）。

## Boy Scout Rule — 翻訳可能性計画

### 対象ファイル

### 翻訳可能性の改善

- `apply_patch_atomic` 関数: コメントなしで「clone → 全操作適用 → 検証 → 結果返却」の流れが散文として読めるよう、明示的な4フェーズ構造を維持
