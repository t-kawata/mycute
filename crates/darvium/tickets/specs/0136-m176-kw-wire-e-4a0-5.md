# M1.76-KW-WIRE-E: 残余ハードコード値の全数パラメーター化 — 4A.0 カタログ残差ゼロ化（実装順序: 5 番目）

## Summary

WIRE-A/C/D で未対処の残余ハードコード値を simulation.rs および kind_world.rs から網羅的に抽出し、constants.rs の名前付き定数化および AllParams G6 グループへの統合を行う。これにより 4A.0 カタログのハードコード（H）エントリをゼロにする。

## Background

4A.0 カタログ再検査（2026-05-27）で、シミュレーションの主要データパスに多数のハードコード値が残存していることが確認された。WIRE-A/C/D で主要経路（offer_help_probability、advance_help_sessions、generate_population、observe_tick、遠隔探索）は対処されたが、以下の経路に残余が残っている：

- **Phase3 KW-REAL パス**（simulation.rs: phase3_help_protocol）：run_simulation パスとは独立した独自のハードコード値を持つ。should_offer_help 判定に load_level=0.3/risk_level=0.2、decide_help_offer 判定に uncertainty=0.3/autonomy_cost=0.2、成功確率計算に 0.5/0.3 係数がハードコードされている。
- **Phase4 GC 生存判定**（simulation.rs: phase4_gc_survival）：LifecycleScore の success 成分が 0.5 固定スタブ。child_prot 値が children に対して 0.5 ハードコード。compute_blended_freshness の human_weight=0.5 ハードコード。
- **Phase5 能力拡散**（simulation.rs: phase5_capability_diffusion）：inherit_reputation の decay=0.7 ハードコード（WIRE-A で run_simulation パスに ADVANCE_HELP_* 定数は追加されたが、Phase5 パスは未対処）。
- **Phase6 J_kw 測定**（simulation.rs: phase6_measure_jkw）：KindWorldMetricsInput の 10 以上のフィールドが 0.5/0.0 スタブ値でハードコード。
- **AllParams G1 未配線パラメーター**（kind_world.rs: AllParams::default_g1）：G1_SEARCH_TICK_FRACTION、G1_EVALUATE_FRACTION、G1_REMOTE_EXPLORE_HUMAN_WEIGHT が活性化（active=true）されているが、対応するシミュレーション機能が未実装のため経路が存在しない。

これらのハードコード値は 4A.0 カタログに（H）分類として記録されているが、実際にパラメーター化されていないため較正ループの対象外である。本チケットで全て定数化し、4A.0 カタログの（H）エントリをゼロにする。

## Scope

1. **simulation.rs Phase3 KW-REAL パスのハードコード値抽出と定数化**：
   - `should_offer_help(quality, 0.3, 0.2, ...)` → constants.rs に定数追加
   - `decide_help_offer(quality, 0.3, 0.2, ...)` → constants.rs に定数追加
   - `success_prob = helper_bv * 0.5 + 0.3` → constants.rs に定数追加
   - `unwrap_or(0.5)` フォールバック値 → 該当するものは定数化（シンプルな None フォールバックはそのまま維持も可）

2. **simulation.rs Phase4 GC 生存判定のハードコード値定数化**：
   - `lifecycle_success = 0.5`（P6 未完成スタブ）→ constants.rs に定数化
   - `compute_blended_freshness(0, tick, 0.5)` → human_weight を定数化
   - `child_prot = 0.5`（子供の child_protection 値）→ constants.rs に定数化

3. **simulation.rs Phase5 能力拡散のハードコード値定数化**：
   - `inherit_reputation(hr, &mut cr, 0.7)` → constants.rs に伝播減衰定数追加

4. **simulation.rs Phase6 J_kw 測定のスタブ値定数化**：
   - `KindWorldMetricsInput` に設定される複数の 0.5 スタブ値（capability_coverage, reuse_ratio, cost_efficiency, knowledge_diffusion_rate, benevolent_vs_non_benevolent_coverage_ratio, mean_nest_depth, mean_node_density, cluster_coefficient, local_density, search_radius_inverse, reasoning_steps_inverse）を定数化

5. **constants.rs への制御パラメーター定数追加**：
   - Phase3/4/5/6 用の制御パラメーターを `PHASE3_*` / `PHASE4_*` / `PHASE5_*` / `PHASE6_*` 命名規則で追加
   - 「変更によりシミュレーション挙動が変わる制御パラメーター」のみ AllParams G6 に追加
   - 「統計的閾値・内部定数」は Rust 定数のみ（AllParams には追加せず）

6. **AllParams G6 グループの追加**：
   - kind_world.rs に G6_COUNT 定数・G6_* インデックス定数追加
   - AllParams 構造体に `default_g6()` または `default_g1g2g4()` 統合更新
   - `to_sim_config_*` に G6 値の Config 伝播追加

7. **G1_SEARCH_TICK_FRACTION / G1_EVALUATE_FRACTION の決定**：
   - 対応機能未実装の RFC 理論値。
   - **決定**: `active=false` に設定し、将来のチケットで機能実装と同時に再有効化する。

8. **G1_REMOTE_EXPLORE_HUMAN_WEIGHT の決定**：
   - RFC 理論値であり現行コードに該当機能なし。
   - **決定**: `active=false` に設定する。

9. **4A.0 カタログの（H）エントリ更新**：
   - 全てのハードコード値が定数化された時点で RFC カタログの（H）分類エントリを（U）または（S）に変更

## Non-scope

- WIRE-A で対処済みの offer_help_probability / advance_help_sessions の値は変更しない
- WIRE-C で対処済みの generate_population / observe_tick の値は変更しない
- WIRE-D で対処済みの遠隔探索関連定数は変更しない
- `compute_search_radius_inverse()` 関数の動作変更（既に正しく実装済み。0.5 は空データ時のフォールバックであり永久スタブではない）
- `compute_mean_freshness()` 関数の human_weight=0.0 は metrics パスとして正しい設計であり変更しない
- ReciprocityLifecyclePolicy の Default impl フィールド値（32 フィールド）は別チケットで扱う
- SimulationContext::new() の TrustProfile 初期値（0.5）は初期化定数であり制御パラメーターではない
- generate_population() の direct_reciprocity/indirect_reciprocity/hazard 初期値（0.5/0.5/0.0）も初期化定数であり制御パラメーターではない

## Investigation

### 事前調査結果（2026-05-28）

Darvium-Tickets-v2.3.md の記載（WIRE-A/C/D 対処済み分を除外した残余）に基づき、ソースコードの grep 調査を実施した。

#### 調査方法

`grep -n '\b0\.[0-9]' src/simulation.rs | grep -v '//' | grep -v '0\.0' | grep -v '1\.0'` および同様のパターンで kind_world.rs を走査。各ヒットを以下の基準でフィルタリング：
- **対象**: WIRE-A/C/D 未対処で、シミュレーション挙動に影響するハードコード値
- **除外**: 初期化定数（generate_population の trust/dr/ir/hazard 初期値、SimulationContext::new の TrustProfile 初期値など）、識別子（percentile パラメーターの 0.5/0.95 など）、テストコード内の期待値アサーション

#### 発見 1: simulation.rs Phase3 KW-REAL パス（phase3_help_protocol）

独立したハードコード値群。run_simulation パス（WIRE-A 対処済み）とは無関係。

| H2 | 2028 | `unwrap_or(0.5)` | 0.5 | フォールバック | 存在しない helper の便宜スコア |
| H3 | 2030 | `should_offer_help(quality, 0.3, 0.2, ...)` | 0.3/0.2 | 制御パラメーター | load_level, risk_level → 提供判断 |

#### 発見 5: AllParams G1 未配線パラメーター

kind_world.rs:452-489 の `AllParams::default_g1()` 定義：

| G1 インデックス | 定数名 | 値 | active | 状態 |
|----------------|--------|-----|--------|------|
| 4 | G1_SEARCH_TICK_FRACTION | 0.5 | true | 対応機能なし（RFC §13.4 理論値） |
| 5 | G1_EVALUATE_FRACTION | 0.3 | true | 対応機能なし（RFC §13.5 理論値） |
| 12 | G1_SEARCH_RADIUS_INVERSE | 0.5 | **false** | compute_search_radius_inverse 実測値経路（正しく実装済み） |
| 13 | G1_REMOTE_EXPLORE_HUMAN_WEIGHT | 0.0 | true | 対応機能なし（RFC 理論値） |

**現状分析**:
- `G1_SEARCH_RADIUS_INVERSE` は既に `active=false` で正しい状態。`compute_search_radius_inverse()` 関数は実際に L2 距離を計算する実装済み関数であり、「永久スタブ」ではなかった。RSS カタログ #92 の記述は不正確であった。
- `G1_SEARCH_TICK_FRACTION` (4), `G1_EVALUATE_FRACTION` (5), `G1_REMOTE_EXPLORE_HUMAN_WEIGHT` (13) の 3 パラメーターは `active=true` だがシミュレーションに対応機能がない。

**決定方針**: 上記 3 パラメーターは `active=false` に設定し、対応機能の実装を将来チケットに委ねる。これらの機能実装には RFC §13.4/§13.5 の理論体系の理解と simulation.rs への新規フェーズ導入が必要であり、本チケットのスコープ（残余ハードコード値の定数化）を超える。

#### 発見 6: compute_search_radius_inverse の実態

kind_world.rs:2377-2421 の実装：
```rust
fn compute_search_radius_inverse(sessions, positions) -> f64 {
    if sessions.is_empty() { return 0.5; }
    // L2 距離を計算し、1/(1+mean_distance) を返す
}
```
この関数は完全に実装されており、0.5 は空セッション時のフォールバック値。カタログ #92 の「永久スタブ」は誤った分類であった。本チケットの対象外。
