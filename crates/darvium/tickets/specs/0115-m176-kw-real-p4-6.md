# M1.76-KW-REAL-P4: 6 フェーズシミュレーションループ

## Summary

現行の `run_simulation`（simulation.rs:1079-1138, flat `SimWorkflowState` + `SimHelpSession` 使用, 4 相ループ）に代えて、**P1 の `SimulationContext` と P5 のライフサイクル機構を活用した 6 フェーズ tick ループ**を実装する。新ループは P2（GMR 抽象化）・P3（実行抽象化）の不足部分をスタブで代用しつつ、実際の Darvium 部品（help.rs、reciprocity.rs、spaceposition.rs、village.rs）を直接呼び出して Kind World 成立条件 J_kw を観測するための実験装置を提供する。

## Background

### なぜこのチケットが必要か

現行の `run_simulation` は以下の制約を持つ：

1. **平坦な構造体**: `SimWorkflowState`（13 フィールド、String ID）と `SimHelpSession`（自前の状態機械）を使用しており、実際の Darvium 内部表現（MemoizedGraph、HelpSession、GcEvent）を一切利用していない。
2. **擬似的な HELP**: `offer_help_probability`（simulation.rs:477）と `advance_help_sessions`（simulation.rs:518）という自前の簡易実装であり、`help.rs` の `should_offer_help` / `decide_help_offer` / `HelpSession` を呼び出していない。
3. **P5 機構の未統合**: `transition_gc_state`（5 状態 GC 機械）、`LifecycleScore`（5 成分幾何平均）、`classify_maturity`（成人/子供判定）が存在するが、`run_simulation` 内では簡易 inline 計算で代用している。
4. **J_kw 未計測**: 最終 tick で `compute_kind_world_objective` を呼び出しておらず、Kind World 成立判定が行われていない。

### 本チケットの位置づけ

P4 は KW-REAL シリーズ 6 チケットの中核であり、P1（SimulationContext 基盤）と P5（ライフサイクル・成熟機構）の成果物を統合して初めて意味を持つ。P2（GMR 抽象化）と P3（実行抽象化）は本チケットの対象外とし、不足機能はスタブで代用する。

### 「シミュレーションはツールであって目的ではない」

本ループは Kind World 成立条件の探索のための実験装置であり、それ自体が製品ではない。実装は実際の Darvium 部品を「本物のまま」呼び出すことに集中し、不足機構は可能な限り単純なスタブで済ませる。

### 過去観察レポートからの知見

- tickets/context/0113-m176-kw-real-p1-simulationcontext/observation-20260526-191047.md — petgraph の指数コンパクションによりノード削除時の NodeId 管理に注意が必要。逆順削除で対応。
- tickets/context/0114-m176-kw-real-p5/observation-20260526-195519.md — デフォルト設定では全ワークフローが tick 12 で全滅。GC hazard の調整が必要。信頼継承・評判継承の減衰係数 TRUST_INHERIT_DECAY=0.70 は KW4 で sweep 対象。

### 既存コードとの共存

現行の `run_simulation` とその補助関数群（`generate_population`、`generate_mission_stream`、`offer_help_sessions`、`advance_help_sessions`、`recompute_trust_reputation`、`run_lifecycle_gc`、`observe_tick`、`compute_benevolent_survival_advantage`、`compute_harmful_gc_rate` 等）は既存のテスト（T1-T19、約 400 行）で広範に使用されている。本チケットではこれらを削除せず、**新規公開関数 `run_kw_real_simulation` を追加**する。既存コードの変更は最小限（型・関数の pub 昇格等）に留める。

## Scope

### 1. 新規関数 `run_kw_real_simulation` の追加

`simulation.rs` に以下の新規関数を追加する：

```rust
/// KW-REAL 6 フェーズシミュレーションループを実行する。
///
/// P1 の SimulationContext と P5 のライフサイクル機構を使用し、
/// 実際の Darvium 部品（help.rs、reciprocity.rs 等）を直接呼び出す。
/// P2/P3 の不足機能はスタブで代用する。
pub fn run_kw_real_simulation(config: &ReciprocitySimulatorConfig) -> ReciprocitySimulationResult
```

内部で `SimulationContext`（P1 成果物）を生成し、以下の 6 フェーズを逐次実行する。戻り値は既存の `ReciprocitySimulationResult` と同一型とし、既存のテストフレームワークとの互換性を維持する。

### 2. 6 フェーズ詳細設計

#### フェーズ 1: 人口成長

**目的**: 子供の出生による人口増加をシミュレートする。

- 各 tick において、生存している各ワークフローに対して `child_ratio` の確率で子ノードを生成
- 生成された子ノードは `SimulationContext::add_person()` を使用
- 子ノードの初期設定:
  - 信頼プロファイル: `inherit_trust(parent_profile, child_profile, TRUST_INHERIT_DECAY)` で親から継承（P5 成果物）
  - 評判: `inherit_reputation(parent_reputation, child_reputation, TRUST_INHERIT_DECAY)` で親から継承（P5 成果物）
  - 位置: 親の位置に微小摂動を加えた値（`rng.random::<f32>() * 0.1` を各成分に加算）
- **スタブ（P2 未完成時）**: 上記の継承処理をそのまま使用。差分は後述の「能力拡散」フェーズでのみ現れる。

#### フェーズ 2: 位置更新 + 村クラスタリング

**目的**: 空間位置の更新と村（Village）の形成をシミュレートする。

- 全生存ワークフローの位置を `update_space_position`（spaceposition.rs:108, 既存 real）で更新
  - `VillageObservation` は村内平均位置との差分から構築
  - `alpha` は config から取得（デフォルト: 0.3）
- P5 の `classify_maturity`（village.rs:80）で成人/子供を判定し、成人のみを村アンカー候補とする
- `build_local_village_radius`（village.rs:170）で村を構成
- 村割り当てを `SimulationContext::village_assignments` に記録（`Option<usize>`）
- 村形成数を println! で記録（観測用）

#### フェーズ 3: HELP プロトコル

**目的**: 実際の `help.rs` の HELP プロトコルを駆動する。`help.rs` の既存実装を一切変更せず外部から呼び出す。

**新規 Proposal 生成**:
- 各 tick において `mission_rate` の確率で生存成人から新規 `HelpSession::new`（help.rs:260）を生成
  - `help_id`: `"kw-help-{tick}-{seq}"`
  - `from_workflow`: ランダムに選んだ生存成人の ID（String）
  - `to_workflow`: ランダムに選んだ生存子供の ID（String）
- 生成したセッションは `SimulationContext::help_sessions` に追加

**既存セッション進行**:
- アクティブな全 `HelpSession` に対して以下を実行：

1. **Proposal 状態**: `should_offer_help`（help.rs:445）で Adult の支援意思確認
   - `quality_score`: helper の benevolence スコアで代用（P2 未完成時）
   - `load_level`: 0.3 固定（P3 未完成時）
   - `risk_level`: 0.2 固定（P3 未完成時）
   - `policy`: `AdultHelpOfferPolicy::default()`
   - `OfferDecision::Offer` → `HelpState::Offer` に遷移
   - `OfferDecision::Abstain` → セッションをアクティブリストから削除

2. **Offer 状態**: `decide_help_offer`（help.rs:493）で Child の受入判定
   - `quality_score`: helper の benevolence スコアで代用
   - `uncertainty`: 0.3 固定
   - `autonomy_cost`: 0.2 固定
   - `policy`: `ChildHelpAcceptancePolicy::default()`
   - `ChildDecision::Accept` → `HelpState::Execution` に遷移
   - `ChildDecision::Reject` / `Abstain` → セッションをアクティブリストから削除

3. **Execution 状態**: 成功判定
   - 成功確率 `helper_benevolence * 0.5 + 0.3`
   - 成功 → `HelpState::Success` + 「能力拡散（フェーズ 5）」用の情報を記録
   - 失敗 → `HelpState::RetryExhausted`、セッションをアクティブリストから削除

4. **Success / RetryExhausted / Proposal（却下後）**: セッションをアクティブリストから削除

**本物の呼び出し確認**: `should_offer_help` を実際に呼び出していることを println! 出力で確認可能にする。

#### フェーズ 4: 互恵性計算 → GC hazard → 生存

**目的**: 実際の `reciprocity.rs` と P5 の GC 機構で生存判定を行う。

**GC フェーズは `gc_interval` の周期でのみ実行**: `tick % gc_interval == 0` のときのみ実行、それ以外ではスキップ。

GC 実行 tick での処理：

全生存ワークフローに対して：
1. `build_events_for_workflow`（既存）で互恵性イベント構築
2. `compute_direct_reciprocity`（reciprocity.rs 既存）で直接互恵性計算
3. `compute_indirect_reciprocity`（reciprocity.rs 既存）で間接互恵性計算
4. `compute_benevolence_score`（reciprocity.rs 既存）で慈悲スコア計算
5. `recompute_reputation`（reciprocity.rs 既存）で評判再計算（F-4, F-5）
6. **`compute_lifecycle_score`（lifecycle.rs: P5 成果物）の呼び出し**:
   - freshness: `compute_blended_freshness`（clock/mod.rs: P5 成果物）で計算
   - success: build_events から成功イベント割合
   - trust: TrustProfile の平均値
   - usage: ExperienceNormalization（`compute_experience_normalization`）で正規化
   - reputation: ReputationProfile.final_score
   - P6 未完成のため freshness/usage は近似値で代用可
7. `compute_gc_hazard`（reciprocity.rs:286）で GC hazard 計算
8. **`transition_gc_state`（event.rs: P5 成果物）で GC 状態遷移**
9. `compute_survival_probability`（reciprocity.rs:329）で生存確率計算
10. 死亡判定 → `SimulationContext::remove_node()`（P1 成果物）

#### フェーズ 5: 能力拡散

**目的**: HELP 成功時の知識伝播をシミュレートする。

- **スタブ（P2 未完成時）**: フェーズ 3 で HELP 成功が発生した場合のみ実行
  - helper の TrustProfile を helpee に部分的にコピー: `inherit_trust(helper, helpee, 0.7)`
  - helper の ReputationProfile を helpee に部分的にコピー: `inherit_reputation(helper, helpee, 0.7)`
  - helpee の experience を +1 増加
- 本実装時（P2 完了後）: `DifferentialInference` による Workflow パターン拡散に置き換える（将来対応）

#### フェーズ 6: J_kw 測定

**目的**: 最終 tick でのみ Kind World 目的関数を計算する。

- 最終 tick（`tick == max_ticks - 1`）でのみ実行
- `KindWorldMetricsInput` を以下の値で構築：
  - `population_growth_rate`: 最終生存人口 / 初期人口 - 1.0（生存していないと負になる）
  - `capability_coverage`: 0.5 固定（P6 未完成時スタブ値）
  - `reuse_ratio`: 0.5 固定（P6 未完成時スタブ値）
  - `cost_efficiency`: 0.5 固定（P6 未完成時スタブ値）
  - `village_formation_score`: 村形成数を生存人口で割った値（最大 1.0）
  - `village_churn_rate`: 村解散率（`compute_village_churn`、village.rs 既存）
  - `cross_village_interaction_rate`: HELP 成功セッションのうち異村間の割合
- `compute_kind_world_objective(&metrics)`（kind_world.rs:163）を呼び出し
- 結果の `KindWorldAssessment` を println! で構造化 JSON 出力
- J_kw 値（`assessment.j_kw`）を `ReciprocitySimulationResult` には保存しない（P6 スコープ）

### 3. フェーズ間の暗黙依存関係

6 フェーズは以下の依存関係のため逐次実行必須（並列不可）:

```text
Phase 1 (人口成長) → Phase 2 (位置更新): 新規ノードの初期位置設定が必要
Phase 2 (村クラスタリング) → Phase 3 (HELP): HELP マッチングに村情報が必要
Phase 3 (HELP) → Phase 4 (GC): GC hazard に互恵性スコアが必要
Phase 3 (HELP 成功) → Phase 5 (能力拡散): 成功情報が必要
全 Phase → Phase 6 (J_kw): 全 tick 完了後の集計
```

- `SimulationContext`（P1）は `&'a mut MemoizedGraph` を含むため、`run_kw_real_simulation` 内で生成し関数内でのみ生存させる
- 既存の `run_simulation` を削除せず、新規関数との並存を許容する

- BlendedFreshness は P6 未完成のため、経験値の時間減衰で代用可
