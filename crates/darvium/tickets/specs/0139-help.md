# HELPイベント発行のプロダクション配線

## Summary

シミュレーションの `phase3_help_protocol` で HELP セッションの状態遷移を行っているが、その遷移が `transition_to()` 経由ではなく直接フィールド代入で行われており、結果として `emit_help_event()` が一切呼ばれない。このチケットでは、シミュレーションの HELP プロトコルが `transition_to()` を経由して `ReciprocityEvent` を発行し、そのイベントが `ReciprocityEventStore` に蓄積されて評判再計算パイプラインの入力となるように配線する。

## Background

チケット#137 で評判再計算パイプラインは実装されたが、その入力となる HELP イベントがシミュレーション/プロダクションのいずれでも発行されていない。調査の結果、問題は3層ある：

**層1: シミュレーションの HELP プロトコルが状態遷移をバイパスしている**
`phase3_help_protocol()`（simulation.rs:2565）は `HelpSession.current_state` を直接フィールド代入で書き換えている（行 2665, 2684, 2698, 2703）。遷移内容は spec 作成時から乖離しており、`Offered→Executing` は `is_legal_help_transition` で許可されていない。`HelpSession::transition_to()`（help.rs:278）は呼ばれていないため、`emit_help_event()`（help.rs:564）も呼ばれない。`SimulationContext` には `event_bus` フィールド自体が存在しない。

**層2: プロダクションの DarviumEventBus 実装がない**
`DarviumEventBus` トレイト（event.rs:945）の唯一の実装は `FakeEventBus`（event.rs:1060）であり、`#[cfg(test)]` 内でのみ使用される。

**層3: HELP プロトコルのプロダクション実行経路がない**
`HelpSession::transition_to()` は `#[cfg(test)]` 外では一度も呼ばれていない。

本チケットでは層1（シミュレーションの HELP プロトコルがイベントを発行するように修正）を主対象とする。層2・層3はスコープ外とする。

## Scope

### A. SimulationContext に event_bus を追加
- `SimulationContext`（simulation.rs:324）に `event_bus: Option<Arc<dyn DarviumEventBus + Send + Sync>>` フィールドを追加
- コンストラクタおよび各種設定構造体（`SimulationConfig`, `ReciprocitySimulatorConfig`）にも同フィールドを追加し、注入可能にする

### B. phase3_help_protocol が transition_to を経由するよう修正
- `phase3_help_protocol()`（simulation.rs:2565）内の外部観測可能な状態遷移を `session.transition_to(next, event_bus.as_deref())` に置き換え。実際のコードは Proposal→Offered, Offered→Executing（※非合法）, Executing→Succeeded, Executing→Failed の4遷移を持つ。Offered→Executing は2段階の合法遷移（Offered→Accepted→Executing）に分割する。非 Accept 枝（Offered→Rejected）も追加。
- 内部状態（内部カウンタやフラグ）の直接代入はそのまま維持
- `event_bus` がない場合（`None`）は従来通りの直接代入動作にフォールバックする（`transition_to` の第二引数が `None` の場合は状態遷移のみ行われイベント発行なし）

### C. FakeEventBus のシミュレーション注入と ReciprocityEventStore 連携
- シミュレーションテストで `FakeEventBus` を注入可能にする
- `FakeEventBus::publish()` で `DarviumEventKind::Reciprocity` のイベントをフィルタリングし、`ReciprocityEventStore` に転送する簡易経路を追加

### D. 互換性維持
- 既存の `event_bus: None` のシミュレーションテストは全て従来通りの動作を維持
- `is_legal_help_transition` による遷移検証は `transition_to` が常に行うため、従来の直接代入より安全性が向上するが、既存テストが遷移検証に依存していないことを確認

## Non-scope

- `ConcreteEventBus` の実装（プロダクションの本物イベントバス）（別チケット）
- MYCUTE からの `DarviumEventBus` 注入設計
- プロダクションでの HELP プロトコル実行ルートの新規作成
- `DarviumEventBus` の永続化・トランスポート層
- `guard_new_proposal_or_review` 等の検索パイプラインへのイベント配線

## Investigation

### [E1] phase3_help_protocol の状態遷移は全て直接代入

simulation.rs:2565-2736、以下の4箇所で直接代入（updated at plan time: 2026-05-28）：
```
行 2665: session.current_state = HelpState::Offered;   // Proposal→Offered (合法)
行 2684: session.current_state = HelpState::Executing; // Offered→Executing (非合法!)
行 2698: session.current_state = HelpState::Succeeded; // Executing→Succeeded (合法)
行 2703: session.current_state = HelpState::Failed;    // Executing→Failed (合法)
```
`transition_to()` は一切呼ばれていない。`is_legal_help_transition` による遷移検証もバイパスされている。
**クリティカル**: `Offered→Executing`（2684行目）は `is_legal_help_transition()` で許可されていない遷移である。
本実装では `Offered→Accepted→Executing` の2段階合法遷移に修正する。
spec 作成時からコードが変更されており、当初の記述（Accepted/Rejected 遷移）と実際のコード（Offered/Executing 遷移）に乖離があった。

### [E2] SimulationContext に event_bus フィールドなし

simulation.rs:324-339:
```rust
pub struct SimulationContext {
    pub population: Vec<MemoizedGraph>,
    pub tick: u64,
    pub rng: StdRng,
    pub help_sessions: Vec<HelpSession>,
    pub use_gmr: bool,
    // ...
}
```
`event_bus` フィールドは存在しない。

### [E3] transition_to のシグネチャ

`transition_to()`（help.rs:278）:
```rust
pub fn transition_to(
    &mut self,
    next: HelpState,
    event_bus: Option<&dyn DarviumEventBus>,
) -> Result<HelpState, DarviumError>
```
`event_bus` が `None` の場合、状態遷移のみ行われイベント発行なし。この場合、従来の直接代入と等価である。

### [E4] transition_to の全呼び出し元はテストコード内

`transition_to` の全呼び出し: `#[cfg(test)]` 内のみ。`emit_help_event` に `Some(...)` を渡すコードも全て `#[cfg(test)]` 内。

### [E5] FakeEventBus はイベントの種類による振り分けをしない

`FakeEventBus::publish()`（event.rs:1084-1125）は全イベントを `published: Vec<DarviumEvent>` に蓄積するのみ。`ReciprocityEventStore` への転送は行われない。

### [E6] ReciprocityEventStore はテスト内でのみ生成

`ReciprocityEventStore::new()` の全呼び出し: `#[cfg(test)]` 内。
