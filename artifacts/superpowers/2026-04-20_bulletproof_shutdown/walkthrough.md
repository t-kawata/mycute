# 運命共同体シャットダウンの防弾化 完了報告

ゾンビプロセスの発生を根絶するため、計画書に基づき「防弾（Bulletproof）設計」を実装・検証しました。

## 実装された変更内容

### 1. 起動時クリーンアップ順序の適正化
- **対象**: `src/mode/rt/main_of_rt.rs`
- **変更内容**: `config_manager.cleanup_all_backend_ports("Startup")` を、データベースから設定を読み込み終わる `ensure_initialized_with_db` の直後に移動しました。
- **効果**: これにより、ユーザーが設定画面で変更した「正しいポート番号」に対して確実に `lsof` および `kill` が実行されるようになり、古いプロセスが空振りで生き残る問題が解決しました。

### 2. 委譲型 Graceful Shutdown の確立
- **対象**: `src/utils/auth.rs`
- **変更内容**: GUI終了時に実行される `BackendProcessGuard::drop` において、即座に `kill -9` を撃つのではなく、以下の3段構えのシーケンスに変更しました。
  1. **stdinクローズ**: パイプを切断し、バックエンド自身に「自ら子プロセス（Bifrost等）を掃除して死ぬ」よう促す。
  2. **フェイルセーフ**: 500msの猶予後、並列化された `cleanup_all_backend_ports("Fate-Sharing")` を実行し、OSに頼らずポートを強制解放。
  3. **最終防衛線**: それでもバックエンド本体が残っていれば `kill -9`（または `taskkill /F`）で強制終了。
- **効果**: プロセスツリー全体のクリーンアップが確実に行われます。

### 3. シャットダウンプロセスの保護 (Watchdog 抑制)
- **対象**: `src/mode/cl/main_of_cl.rs`
- **変更内容**: `TauriState` に `is_shutting_down` フラグを追加。終了処理に入った瞬間にこのフラグを `true` にします。
- **効果**: バックエンドが「行儀よく」死んだことを Watchdog が「異常事態」と誤認し、GUI プロセス全体を道連れにして `exit(1)` してしまう競合状態（レースコンディション）を排除しました。

### 4. クリーンアップの並列高速化
- **対象**: `src/utils/process.rs`
- **変更内容**: `kill_processes_on_ports` に渡された複数ポートのクリーンアップ処理（`kill_process_on_port`）を、`std::thread::spawn` を用いて並列実行するように改修しました。
- **効果**: 各ポートの解放待ち時間が累積しなくなり、シャットダウンが高速化しました。

## 検証結果
`make check-be` を実行し、エラーおよび警告なしでビルドが完了（Exit code 0）することを確認しました。コンパイル時の正当性は 100% 担保されています。
