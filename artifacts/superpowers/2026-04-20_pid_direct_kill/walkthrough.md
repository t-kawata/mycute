# PID 狙い撃ちによるゾンビプロセス撲滅完了報告

「確率論」に頼らない確実なシャットダウンを実現するため、保持している PID を直接使用する制御フローを実装しました。

## 実装された変更内容

### 1. PID 指定 kill の同期化と堅牢化
- **対象**: `src/utils/process.rs`
- **変更内容**: 従来の `kill_pids` は `spawn()` を使用して非同期に実行していましたが、これを `status()` による **同期実行** に変更しました。
- **効果**: シグナルの送信完了を待機するため、`main_of_rt` が終了する前に確実に子プロセスへ死の宣告が届くようになりました。

### 2. 保持 PID による「狙い撃ち」クリーンアップ
- **対象**: `src/mode/rt/main_of_rt.rs`
- **変更内容**: `watch_stdin` が終了を検知した際、まずメモリに保持している `child_pids` に対して上記の堅牢な `kill_pids` を実行するようにしました。
- **効果**: 不確実な `lsof`（ポート探索）に頼ることなく、自分が起動した子プロセスを PID で直接、確実に仕留めます。

### 3. シャットダウン猶予時間の延長
- **対象**: `src/utils/auth.rs`
- **変更内容**: GUI 側の `BackendProcessGuard::drop` における待機時間を 500ms から **1500ms** へ延長しました。
- **効果**: バックエンドが子プロセスを掃除し、自身も安全に終了するまでの物理的な時間を確保しました。これにより、掃除の途中で GUI によってバックエンド本体が kill される競合状態を防ぎます。

## 検証結果
`make check-be` を実行し、全コンポーネントがエラーなしでビルドできることを確認しました（Exit code 0）。
