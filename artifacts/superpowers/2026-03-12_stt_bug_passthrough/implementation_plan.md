# 実装計画書: Windows版パススルーモードにおける句読点重複バグの修正

## 1. 目的（Goal Description）
Windows環境のSTTにおいて、OSパススルーモードで発生する「句読点が不自然に重複・確定し、文脈が分断されるバグ（事象3）」を解決します。

前回の修正で「タイムアウトによるイベントをすべて `FinalResult` に昇格させる」改修を行いましたが、これが原因で「文の途中の息継ぎ（未確定）」であっても強制確定されてしまい、後続の音声入力によるバックスペース修正が効かなくなる副作用を生んでいました。

本計画では、この「未確定（話の途中）」と「確定済み（文末）」を正確に判定し、タイムアウト時のイベント種別を動的に切り替えることで、本来の意図である「文末の句読点の保護」と「文中の句読点の繋がり」を両立させます。

### なぜパススルーモードでのみ起きるのか？
ご指摘の通り、この問題は「パススルーモード」でのみ発生し、LLMアシストが有効な状態（非パススルー）では発生しません。その理由は**「文字の『確定（FinalResult）』の主導権を誰が握っているか」**の違いにあります。

1. **LLM有効時（非パススルー）**
   LLMが有効な場合、OSから送られてくる細かい音声認識結果や、今回問題となった500msの無音タイムアウトイベントは、一旦すべて中間の `PostCorrectionProcessor` に吸い込まれ（ストックされ）ます。この状態では、画面にはすべて仮置き（`PartialResult`）として流れるのみで、本当の確定（`FinalResult`）は、**LLMが文脈全体を推敲し終えて最終的なテキストをアプリに返約した瞬間にのみ**送信されます。つまり、小さなタイムアウトで細かく `FinalResult` が生成されること自体がブロックされているため、このバグは物理的に発生しません。

2. **LLM無効時（パススルーモード）**
   一方、パススルーモードではLLMという「せき止め役」が存在しません。そのため、システムが自動で発火させる「500msタイムアウトイベント」が、そのままダイレクトに `main_of_cl.rs`（UI側）へ直撃します。前回の修正でこの直撃イベントを `FinalResult`（取り消し不可の確定）に変更してしまったため、OSによる本来の確定イベントと、タイムアウトによる独自の確定イベントが衝突し合い、不要な句読点が大量に確定・保護されてしまうという、このモード特有のバグとして顕在化しました。

この構造的な違いにより、本問題はLLMの有無（パススルーか否か）に完全に依存する現象となっています。

## 2. 変更内容（Proposed Changes）

### [MODIFY] src/stt/win.rs
- `ticker_task` ループ内（558行目付近）、タイムアウト発火時のイベント送信ロジックを修正します。
- 送信前に、現在保持している文字列の長さと、確定済みの文字数（`watermark_len`）を比較し、**未確定の文字が残っているか**を判定するロジックを1行追加します。
- この判定に基づき、送信イベントを以下のように分岐させます。

  1. **未確定文字が残っている場合 (話の途中)**
     - 仮置きの句読点として `SttEvent::PartialResult` を送信します。
     - これにより、ユーザーの次の発話で直ちに句読点が削除され、一連の文章として綺麗に繋がります（重複・分断の防止）。

  2. **未確定文字が残っていない場合 (文末)**
     - OS側で前の文章が確定された直後の無音（実質的な文末）と判断し、真の句読点として `SttEvent::FinalResult` を送信します。
     - これにより、次回の文の冒頭で前文の文末句読点が消去されてしまう事象（事象1）を確実に防ぎます。

## 3. 検証プラン（Verification Plan）

今回はWindows固有のイベントハンドリングに直接関わるため、ビルド後に実機でマニュアルテストを実施します。

### 手動検証の手順（Manual Verification）
1. **パススルーモードの有効化**: 
   言語モデルの接続設定（APIキー等）をダミーにするなどして、WindowsのSTTがパススルーモードで動作する状態にします。
2. **文中の息継ぎの確認**:
   「これから（一呼吸置く）テストをして行きます」と発話します。
   - 途中の無音時に一時的に「これから。」と表示されることがあります。
   - その後「テストを〜」が入力された瞬間に「。」が自動で消え、「これからテストをして行きます」と文が正しく繋がることを確認します。
3. **文末の保護の確認**:
   「テストが終了しました」と話し切り、無音を作ります。
   - 確定処理とタイムアウトにより、文末に自然に「。」が付与されます。
   - 続いて「次のステップは」と発話した際、付与された「。」が消えることなく、「テストが終了しました。次のステップは」と残ることを確認します。
4. **疑問符の重複確認**:
   「うまくいっているでしょうか」と話し切ります。
   - 文末に付与される「？」が「？？」のように不自然に連打されないかを確認します。
