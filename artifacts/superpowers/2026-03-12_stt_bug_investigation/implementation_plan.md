# 実装計画書: Windows版STTバグの抜本的修正とクリップボードペースト入力の導入

## 1. 目的（Goal Description）
Windows環境において発生している以下の2つの重大なバグを解消します。
1. **文末句読点の消失**: 無音タイムアウトによって自動付与される句読点が、直後の音声入力により削除されてしまう問題。
2. **文字抜けの発生**: `SendInput` APIによる1文字ずつのキーボードエミュレーションが対象アプリの処理速度を追い越してしまうことで発生する文字欠落問題。

現状の「1文字ずつ入力する」体験が将来的に優れている可能性を残すため、文字抜け解消のための「クリップボード方式（ペースト入力）」は、定数フラグ1つで即座に従来の方式に切り戻せるように安全に設計します。

## 2. 変更内容（Proposed Changes）

### [MODIFY] Cargo.toml
- `arboard` クレートを依存関係に追加します（`cargo add arboard` によって追加）。
- **理由**: 現在のクリップボード操作は Mac 固有の `pbcopy/pbpaste` コマンドに依存しており Windows で動作しません。Mac / Windows 両方でメモリ安全かつ高速にクリップボードを操作できる標準的なクレートを使用するためです。

---

### [MODIFY] src/stt/win.rs
- `ticker_task` ループ内の `is_timeout` 判定ブロックにて、タイムアウト時の再処理イベントを `SttEvent::PartialResult` から **`SttEvent::FinalResult`** に変更します。
- **理由**: `FinalResult` を送信することで、フロントエンド側（`main_of_cl.rs`）の確定文字列バッファに「。」が正式に書き込まれ、その後の入力差分（`input_diff`）におけるバックスペース（削除）対象から物理的に除外されるためです。

---

### [MODIFY] src/input/clipboard.rs
- 既存の `pbcopy` / `pbpaste` サブプロセス呼び出しを全削除し、追加した `arboard::Clipboard` を利用する形に完全に書き換えます。
- **理由**: これにより、Windows 環境の Rust ネイティブから安全に `get_clipboard` や `set_clipboard` メソッドを呼び出せるようになり、フロントエンドおよびタイピング注入機能から利用可能にします。

---

### [MODIFY] src/input/keyboard_win.rs
- ファイル冒頭または `KeyboardInjector` の設定箇所に、以下のトグル用定数を追加します。
  ```rust
  /// クリップボード（Ctrl+V）方式を利用してテキストを注入するかどうかのフラグ。
  /// false に設定すると従来の1文字ずつ送信する方式に切り替わります。
  pub const USE_CLIPBOARD_INJECTION: bool = true;
  ```
- `type_text_inner(text: &str)` の実装を修正し、`USE_CLIPBOARD_INJECTION` が `true` の場合に以下の「ペーストインジェクション」を実行させます。
  1. `clipboard::get_clipboard()` で現在のユーザーのクリップボード内容を文字列として退避。
  2. `clipboard::set_clipboard(text)` で入力したい文字列をセット。
  3. `Self::send_cmd_v()` を呼び出し、対象アプリに `Ctrl+V` を送信。
  4. 対象アプリへの貼り付け処理が終わるまでわずかに待機（余裕を持たせて50msほど）。
  5. 退避しておいた元の文字列を `clipboard::set_clipboard(saved)` で復元。
- 上記処理の際、元のクリップボードが画像等の非テキストデータだった場合の退避・復元は難しいため、エラー時はクリップボードを空のままにする等、フォールバックを考慮します。`false` の場合は、既存の1文字ずつ打つロジックを実行します。

## 3. 検証プラン（Verification Plan）

今回はWindows固有の低レイヤーイベント（音声合成API、SendInputAPI）が関わるため、ビルドを通した後の実機（ユーザーの手元）でのマニュアルテストが主体となります。

### 手動検証の手順（Manual Verification）
1. **クリップボードインジェクションの確認**:
   - `USE_CLIPBOARD_INJECTION = true` の状態で起動します。
   - `現在テストをしています` と発話した際、「きちと」のように文字が抜けず、クリップボード経由で瞬時に「現在テストをしています」と貼り付けられることを確認します。
   - 入力前と入力後で、ユーザー自身がコピー（Ctrl+C）していた別のテキストデータが破壊されておらず、復元されていることを確認します。
2. **句読点の保護確認**:
   - 音声入力後、500msの無音により「。」が画面に入力されるのを待ちます。
   - `。` が入力された直後に、間髪を入れず「テストの内容は」と次の文章を発話します。
   - 従来のように「。」がバックスペースで消去されることなく、「現在テストをしています。テストの内容は」と綺麗に繋がることを確認します。
3. **退行テスト（フォールバックの確認）**:
   - もしペースト方式の挙動（UIのちらつき等）が気に入らない場合、コード上で `USE_CLIPBOARD_INJECTION = false;` に書き換えてビルドし、文字抜けのリスクは伴うものの元の「1文字ずつタイピングする」体験に即座に切り戻せることを確認します。
