# 質問への回答：クリップボード方式の適用範囲について

ご質問ありがとうございます。

「クリップボード方式を使用するのは**入力による追加部分のみ**であり、差分を計算して**バックスペースで削除する処理は従来の実装を完全に維持する**」というご認識で**100%合っています**。

### なぜ削除処理（バックスペース）はそのままにするのか？

1. **技術的理由**:
   クリップボード（ペースト）は「文字列を挿入・上書きする」ことは得意ですが、「特定の文字数だけテキストを削る（削除する）」という操作はOSの標準機能として提供されていません。削除を行うためには、これまで通り「必要な回数だけ `Backspace` キーをエミュレートして叩く」ことが**唯一にして最も確実な方法**です。
2. **アーキテクチャ上の理由**:
   `KeyboardInjector::input_diff` の処理フローは以下の2段構えになっています。
   - 第1段階: `send_backspaces_inner` （削除） ← **今回は一切変更しません**
   - 第2段階: `type_text_inner` （新規テキストの打鍵） ← **ここだけを切り替え可能にします**

### 変更のスコープ（適用範囲）

実装計画書に記載した `USE_CLIPBOARD_INJECTION` フラグが影響を与えるのは、新しく打つべき文字列（差分計算後の `new_text`）を対象アプリに流し込む「最後の数ミリ秒の工程」だけです。

フロントエンドの `main_of_cl.rs` でのバッファ管理や、`keyboard_win.rs` 内の「旧テキストと新テキストを比較して何文字戻るべきか」を計算するコアロジックは、実績のある現在のコードがそのまま再利用されます。

したがって、今回の変更によって「削除関連のバグ（例：消しすぎる、消えない）」が新しく引き起こされるリスクはありません。ご安心ください。

もしこの点でご懸念が払拭されましたら、引き続き待機しておりますので、実装実行（`/superpowers-execute-plan` 等）のご指示をお願いいたします。
