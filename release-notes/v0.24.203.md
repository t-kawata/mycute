# Release v0.24.203

## Summary

Add operational metrics instrumentation pipeline to the Event Architecture (EventBus), enabling observability of throughput, TwoWay resolution rates, and quarantine ratios. Follows the same pattern as the M1.76-18 ReciprocityMetricsObserver.

## What's Changed

- **feat(darvium/event): Add EventBusMetrics struct with 9 operational counters** — tracks total_published, total_clock_advances, two_way_opened/resolved/aborted/timeout, quarantine_count, replay_count, and subscribe_count
- **feat(darvium/event): Add EventBusMetricsObserver** — observe() snapshot and print_csv() time-series output compatible with the existing observational testing pipeline
- **feat(darvium/event): Instrument FakeEventBus with metrics hooks** — all 7 DarviumEventBus methods now increment corresponding counters with minimal lock contention
- **feat(darvium/constants): Add EVENTBUS_METRICS_WINDOW_SIZE** — calibration candidate for throughput moving window computation (default: 100)
- **test(darvium/event): Add 8 tests (T1-T5 unit + O1-O3 observational)** — includes n=1000 random operation series, full resolution rate verification, transparency validation, and CSV time-series output
