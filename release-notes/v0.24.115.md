# Release v0.24.115

## Summary
Defined the Dual-Store abstraction layer (GraphStore / MetadataStore traits) with in-memory implementations for the Darvium crate, establishing the trait-based programming foundation for all 13 development phases.

## What's Changed
- **feat**: Added `GraphStore` trait (LadybugDB responsibilities) with `InMemoryGraphStore` implementation — workflow graph CRUD, embedding vector storage and semantic search, knowledge object/relation management, origin trace recording
- **feat**: Added `MetadataStore` trait (SQLite responsibilities) with `InMemoryMetadataStore` implementation — search trace, trust audit log, patch history, training/fusion metadata persistence
- **feat**: Extended `DarviumError` with `Storage`, `NotFound`, and `EmbeddingDimensionMismatch` variants
- **feat**: Added 6 core data types: `GraphId`, `KnowledgeObject`, `RelationRecord`, `OriginTrace`, `TrainingMetadata`, `FusionMetadata`
- **refactor**: Updated `DarviumConfig` to use `#[derive(Default)]`, added `pub mod store` to lib.rs
- **docs**: Added "データベース非依存の原則" (DB Independence Principle) documentation to Darvium-Tickets.md
- **test**: 32 unit tests covering all trait methods, error cases (NotFound, dimension mismatch, empty vectors), object safety, CRUD operations, and semantic search ranking
