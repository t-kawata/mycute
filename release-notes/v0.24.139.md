# Release v0.24.139

## Summary
Implement HITL HumanChannel communication abstraction (M-0.5-4) and crash recovery loop (M1-4) for robust human-in-the-loop interaction persistence and resumption across process restarts.

## What's Changed
- **feat(HITL)**: Add HumanChannel trait with notify/communicate/reconnect, InteractionHandle blocking wait, FakeHumanChannel test double, and StdinoutChannel reference implementation (M-0.5-4)
- **feat(HITL)**: Add MetadataStore HITL persistence with 4 methods (store/load/list_pending/resolve) and JsonMetadataStore file-backed implementation with atomic writes (M-0.5-4 / M1-4)
- **feat(HITL)**: Add crash recovery loop `recover_pending_interactions()` that iterates all pending interactions, calls reconnect/wait/resolve with exponential backoff (M1-4)
- **feat(HITL)**: Define 6 HITL data types (HumanRequest, HumanResponse, HumanOutcome, HumanDecision, StoredInteraction, InteractionStatus), HumanChannel error variants, and state machine (Idle/Pending/Resolved/TimedOut/Unreachable/ChannelClosed)
- **docs**: Update Darvium-RFC, Darvium-Tickets, and TableSpec to v2.3-d with §12B HumanChannel Abstraction and crash recovery protocol
- **test**: 13 invariant + 2 observational tests covering single/batch/mixed/cross-instance/timed-out/race-condition/channel-swap recovery scenarios
- **chore**: Add `uuid` dependency for interaction_id generation
