# Release v0.24.153

## Summary
M1.5-3: Implemented startup repair scan (Repair Worker) for deterministic crash recovery of dual-store consistency states, completing the M1.5 dual-store consistency phase.

## What's Changed
- **feat**: Implemented `DualStoreCoordinator::startup_repair_scan()` — scans all `Pending`/`NeedsRepair` assets on startup and transitions them to `Committed` (via retry) or `Quarantined` (on failure)
- **feat**: Added `RepairScanSummary` struct with `total_scanned`, `found_inconsistent`, `repaired`, `quarantined`, `already_clean`, `duration_ms` fields
- **feat**: Added `REPAIR_SCAN_MAX_RETRY=3` (Safety Invariant) and `REPAIR_SCAN_BATCH_SIZE=100` (Calibration Candidate) constants
- **test**: T51-T60 invariant tests (normal, mixed, empty, failing store, idempotent, large-scale)
- **test**: T61-T65 exclusion gate tests (eligibility during/after scan, filter integration, non-decreasing)
- **test**: OTS-1 (10,000 ensemble 100% success rate), OTS-2 (decay curve convergence), OTS-3 (absorption distribution, zero residual inconsistency)
- **chore**: Exported `RepairScanSummary` from crate public API; added `Default` derive to `RankedCandidate`
