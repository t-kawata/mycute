# Release v0.24.51

## Summary
Fixed a critical bug where `rt_crypto_key` was regenerated on every headless boot due to `last_rotated_at` not being set during key initialization. Added comprehensive test coverage (19 tests) for key lifecycle and rotation logic.

## What's Changed
- **fix**: `ensure_unique_secret_keys` now sets `last_rotated_at` when regenerating `rt_crypto_key`, preventing `check_and_rotate_keys` from re-rotating the key on the next boot
- **refactor**: Extracted `should_rotate_keys()` as a pure testable function from `check_and_rotate_keys()`
- **test**: Added 12 tests in `mycute_settings` (unit tests for `ensure_unique_secret_keys`, DB round-trip, serde default injection, two-boot sequence, full rotation chain verification)
- **test**: Added 7 tests in `rotation_bl` (date parsing, boundary conditions for RFC3339 and Naive formats)
- **diag**: Added `[DIAG]` logging at all key decision points (key initialization, DB load/seed, rotation check enter/exit)
- **docs**: Updated README to clarify "Sovereignty Reconfiguration" as ultimate goal and "Trust Democratized" as core value proposition
