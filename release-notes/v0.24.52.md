# Release v0.24.52

## Summary
Fixed a bug where `reset_application` deleted the server settings row from the database, causing `rt_crypto_key` to be regenerated on the next boot and making encrypted identity data undecryptable.

## What's Changed
- **fix**: Added `SETTING_KEY_SERVER` to `protected_settings_keys()` so the server settings row (containing `rt_crypto_key` and `last_rotated_at`) is preserved during application reset
- **test**: Added `test_protected_settings_keys_includes_server` to prevent regression
