# Release v0.24.149

## Summary
Implemented M1-1 HumanReviewQueue — a thread-safe in-memory isolation queue that prevents missions awaiting human review from leaking into the automatic execution pipeline (P_leak = 0 guarantee).

## What's Changed
- **feat**: Add HumanReviewQueue with full thread-safe queue operations, isolation barrier (contains_mission always returns false), and HumanChannel integration via push/resolve lifecycle
- **feat**: Add HumanReviewQueuePolicy struct (RFC Section 16A.1) with 5 configuration fields and default values from Annex A constants
- **feat**: Add 3 calibration constants (HUMAN_REVIEW_TIMEOUT_SECS, ESCALATION_SECS, MAX_BATCH_SIZE)
- **feat**: Add 10 invariant tests (T1-T10) covering basic cycle, concurrency, isolation, duplicate rejection, and timeout detection
- **feat**: Add 4 observational tests (OTS-1-4) measuring linear growth dynamics (R^2=1.000), contention wait times (P99=6.9ms), leak rate (P_leak=0), and decision response patterns
- **refactor**: Add public constructor InteractionHandle::new() for test channel implementations
- **docs**: Mark M1-1 as completed in Darvium-Tickets-v2.3.md and tickets/queue.md
