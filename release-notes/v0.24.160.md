# Release v0.24.160

## Summary
Redefined VirtualClock as a read-only commit sequence counter, separating it from time measurement (renamed to ManualClock), and integrated it as a DarviumEventBus supertrait per RFC §12C.6.

## What's Changed
- **feat**: Added `VirtualClock` read-only trait (`fn now(&self) -> u64`), the commit sequence counter for DarviumEventBus
- **feat**: `DarviumEventBus` now requires `VirtualClock` as supertrait — all EventBus implementations guarantee read-only clock access
- **feat**: `FakeEventBus` implements `VirtualClock` trait
- **refactor**: Renamed old `VirtualClock` struct (time measurement) to `ManualClock` in `src/clock/mod.rs` to resolve name collision
- **refactor**: Added advance() doc comment with RFC §12C.6 MUST #4 restriction
- **test**: Added 12 test cases (TC-1 through TC-8) covering VirtualClock trait, FakeEventBus impl, supertrait bounds, per-operation clock advancement (publish/open/resolve/reconnect), replay non-advancement (MUST NOT #3), and n=1000 observation test
- **docs**: Completed ticket M1.5-R6 spec, implementation, observation report, and review
