# Release v0.24.72

## Summary
Fixed a race condition in clipboard-based voice input flush where concurrent access from hotkey handler and STT event loop threads could paste stale clipboard content, especially on Windows.

## What's Changed
- fix: Added Mutex-based thread safety to clipboard flush operations (`save_paste_and_restore`, `get_selected_text`, `replace_selected_text`) to prevent interleaving of save/set/paste/restore sequences from multiple threads
- fix: `replace_selected_text` now properly saves and restores clipboard content instead of leaving it overwritten
- chore: Extracted magic number `50` to named constant `PASTE_DELAY_MS`
