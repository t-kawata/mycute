# Release v0.24.95

## Summary
Prevent silent server startup failures by adding file-based diagnostics (launcher log, exit status, startup marker) and auto-retry mechanism across all three binaries (launcher, server, GUI).

## What's Changed
- **fix**: Change launcher log output from stdout to `mycute-launcher.log` file — ensures logs survive hidden/elevated execution via UAC `-WindowStyle Hidden`
- **feat**: Write `launcher-exit.status` file on launcher exit ("0" = success, "1:error_msg" = failure) so GUI can read exit code even from elevated processes
- **feat**: Add `server-startup.marker` written before `acquire_lock()` in core server — enables tracking how far startup progressed when server dies before logger initialization
- **feat**: Add `collect_startup_diagnostics()` function in GUI that reads launcher status, launcher log, server marker, and server log on startup timeout
- **feat**: Wrap spawn + health check in retry loop (up to 2 attempts) with automatic process cleanup before retry
- **fix**: Downgrade DLL write failures in launcher from fatal to warning with continuation — error code 32 (ERROR_SHARING_VIOLATION) no longer blocks startup
- **fix**: Move `cleanup_orphan_processes()` before `acquire_lock()` in core server to clear stale lock holders
- **fix**: Write `server_lock_error.log` when `acquire_lock()` fails — previously silent before logger init
- **chore**: Downgrade Unix permission set failures in launcher from fatal to warning
- **refactor**: Adopt path (existing server) no longer runs redundant health check polling
